# AnimeBox: slug, сезоны и длинные списки серий

## Что действительно ломалось в этом архиве

1. `AnimeFranchise` — серверный компонент. Кнопки сезонов были `Link`, а не `setState`. `getAnimeFranchise()` загружал только прямых соседей, после чего `getPrimarySeasonItems()` нумеровал получившееся подмножество с 1. Поэтому одинаковая подпись «Сезон 1» могла вести на разные произведения. Это подтверждается кодом, а не гипотезой об асинхронности React.
2. `/api/anilibria` брал первые три результата поиска и возвращал первый с нужным номером серии, не проверяя точное название. Клиент также пытался искать по укороченному названию — это смешивало сезоны, фильмы и другие релизы.
3. Страница эпизода использовала только `anime.episodes`. У продолжающегося сериала итоговое число может быть неизвестно. `episodesAired` не передавалось в список; локализация подробной карточки не сохраняла `episodes_aired` из Shikimori.
4. Обрезание до 100 серий именно API в присланном коде не подтверждено. `.slice(0, 3)` ограничивал кандидатов-релизов, а не серии. `EpisodeList` уже умел отображать диапазоны по 50; проблема была в числе серий на входе.

## Что изменено

### Постоянные URL

- `lib/anime-url.ts`: slugify (латиница, транслитерация кириллицы, дефисы) и общий `animeHref()`.
- `lib/anime-registry.ts`: SQLite, уникальный индекс `slug`, транзакция `BEGIN IMMEDIATE`, разбор коллизий через `-2`, `-3` и т.д. Повторная регистрация того же внутреннего ID сохраняет старый slug даже после изменения названия. Суффикс коллизии НЕ означает номер сезона.
- Slug назначается сервером при получении каталога, расписания, франшизы или отдельного произведения. Для прямого открытия ещё не зарегистрированного названия сначала импортируйте/откройте тайтл через каталог либо старый числовой URL. По строке slug не выполняется неточный внешний поиск.
- Роуты переименованы в `app/anime/[slug]` и `app/api/anime/[slug]`. **Не оставляйте рядом старые `[id]`!**
- Числовые URL страниц и эпизодов перенаправляются на канонический slug с HTTP 308. Старые записи трекера в localStorage продолжают работать. Внутренние ID оставлены для прогресса и однозначного обращения к каталогам; в пользовательском URL их нет.
- `generateMetadata()` выводит название тайтла. Страница использует уже загруженный объект, без второго запроса подробностей.
- Ссылки каталога, расписания, карточек, избранного и трекера используют общий помощник. Старые записи без slug идут через совместимый числовой redirect.

### Переключение частей

- Загружается цепочка PREQUEL/SEQUEL среди TV/TV_SHORT/ONA, а не только ближайшие соседи. Побочные ветви не обходятся рекурсивно.
- На холодную загрузку не более 12 запросов. Внешние ответы кэшируются существующим слоем AniList; итоговая цепочка кэшируется на час в процессе, неполная — на 30 секунд. Ошибка/бюджет дают явный признак неполной цепочки, а не выдуманные номера.
- Кнопки подписаны точными названиями. Автоматическая нумерация соседнего подмножества удалена. Даже полный порядок релизов не гарантирует официальную нумерацию сезонов: бывают split-cour и ONA.
- Серверная страница эпизода разрешает slug и передаёт данные в `components/AnimeEpisodePage.tsx`. При смене тайтла компонент получает новый key, при смене серии меняется identity `slug:episode`. Cleanup прерывает запрос, а active-флаг блокирует старый ответ. Такой подход соответствует https://react.dev/reference/react/useEffect#fetching-data-with-effects .
- Номер запрошенной серии больше не подменяется последней известной серией из каталога. Страница 1300 не должна молча включать 100-ю.

### Название и номер сезона для плеера

Клиент отправляет:

```text
/api/anilibria?slug=gintama-enchousen&title=Gintama%3A%20Enchousen&season=1&episode=3
```

Точный запрос зависит от сохранённой записи. Сервер получает авторитетные полные названия и `provider_season` из БД по slug. Произвольному `title` из URL он не доверяет, а устаревший `season` отклоняет с 409. Никакого `mal_id` в запросе плеера нет.

**Номер сезона франшизы и сезон внутри видеорелиза — разные данные.** У AniLiberty продолжение обычно выбирается отдельным alias релиза, а внутри него серия нумеруется с 1. Поэтому default `provider_season=1` — локальный сезон отдельного релиза, не утверждение «это первый сезон всей франшизы». У используемых в архиве методов AniLiberty нет задействованного параметра выбора сезона: выбирается конкретный alias. Подставлять выдуманный `season=3` во внешний API нельзя.

Существующий в архиве маршрут Kodik не подключён к обновлённому экрану эпизода и не изменялся; для его использования требуется отдельно связать интерфейс с его документированным API и вашими параметрами доступа. Передача одного названия не делает подбор автоматически точнее ID.

Поиск AniLiberty теперь проверяет полное название (в том числе значимую пунктуацию Gintama / Gintama' / Gintama.). При неоднозначности он сообщает ошибку вместо выбора первого кандидата. Строгий поиск может не найти синоним, которого нет в каталоге: для этого есть явное сопоставление.

Чтобы закрепить проверенный alias без изменения исходного кода:

```bash
node scripts/set-release.cjs <существующий-slug> <проверенный-alias-провайдера> 1
```

Аргументы в угловых скобках замените своими значениями. Не угадывайте alias. Скрипт меняет только существующую запись SQLite. Обновление alias не меняет публичный slug.

### Все серии

- Сохраняется `episodes_aired` из Shikimori; AniList запрашивает `nextAiringEpisode { episode }` и использует `episode - 1` как дополнительную оценку уже вышедших серий.
- Страница учитывает максимум из общего числа, числа вышедших серий и номеров, возвращённых провайдером. Диапазоны по 50 сохраняются, доступны все диапазоны.
- Адаптер обрабатывает все элементы `episodes` релиза. `lib/provider-episodes.ts` также умеет обходить обёрнутые страницы `data/items` по `links.next` или `next_page_url`, удалять дубли и сортировать по номеру. Нет лимита 100 и нет ложного `limit=99999`.
- Циклический курсор, чужой домен, ошибка следующей страницы или явные метаданные неполноты без ссылки продолжения дают ошибку, а не успешный обрезанный список. Общий timeout ограничивает запрос; незавершённый обход не считается успехом.
- Этот механизм условный: он применяется, **если провайдер действительно возвращает страницы** в такой структуре. Не выдуман отдельный endpoint пагинации AniLiberty. Если plain array скрытно обрезан без метаданных, автоматически определить это невозможно: нужен фактический ответ API и его контракт.
- Отдельный release-level iframe больше не считается подтверждением, что включена нужная серия.
- Реальные отсутствующие у провайдера серии пагинация создать не может. Количество в каталоге не гарантирует наличие озвучки. Дробные номера спецэпизодов не включаются в целочисленный маршрут серий.

## Запуск

1. Используйте **Node.js 22.13+**, лучше Node 24 LTS. Здесь используется встроенный `node:sqlite`.
2. Распакуйте архив в отдельную папку. Не накладывайте его поверх старых `[id]` маршрутов.
3. Выполните:

```bash
npm ci
npm run dev
```

4. Откройте каталог, затем нужное аниме. Сервер создаст `.data/animebox.sqlite` и назначит постоянные slugs.
5. Сохраните эту БД вместе с данными проекта. **Удаление `.data` может поменять распределение коллизий slug.** `node_modules`, `.next`, локальная БД и кэши в архив не включены.

Локальный запуск и один обычный Node-сервер с постоянным диском поддерживаются. Для другого пути БД задайте `ANIMEBOX_DB_PATH`. На Vercel без `ANIMEBOX_DB_PATH` приложение автоматически использует stateless-slug вида `название-ANILIST_ID`, поэтому каталог и страницы аниме не зависят от SQLite и не падают. Если позже нужна постоянная ручная привязка `provider_alias`, подключите постоянную БД и задайте `ANIMEBOX_DB_PATH`. Файл SQLite нельзя включать в клиентскую сборку или раздавать через public.

## Проверки

```bash
node tests/routing-sources.cjs
npx next typegen
npx tsc --noEmit
npm run build
```

Регрессионный тест использует фиктивные ответы провайдера: коллизии и постоянство slug, отличие Gintama от Gintama', 1300 серий в 13 страницах, доступ к последнему диапазону, дубли, циклический курсор, чужой домен, неполные метаданные, реальный route handler с серией 1300, конфликт сезона 409, ошибка провайдера 503, одинаковая цепочка частей при открытии первой/второй/третьей.

Живое воспроизведение One Piece и взаимодействие в браузере не проверены. Ссылки на API могут зависеть от сети, региона и доступности самого провайдера. Документация использованной версии Next.js прочитана из node_modules/next/dist/docs; публичная справка: https://nextjs.org/docs/app/api-reference/file-conventions/dynamic-routes .

Итог проверки в рабочей среде: регрессионные тесты, TypeScript и `next build` прошли успешно. При сборке установлены Linux-варианты нативных зависимостей вместо приложенных Windows-бинарников; это касается только локальной среды проверки. `npm ci` установит зависимости для вашей ОС.
