# AnimeBox: статистика, серии, достижения и обсуждения

Изменения встроены в исходный Next.js-проект. Отдельный Express/Python-сервис не нужен: API работает через Route Handlers, данные — в Supabase PostgreSQL, авторизация — через существующие Supabase cookies. Полный код находится в файлах проекта.

## Запуск на твоём компьютере

1. Сохрани копию текущего проекта. Распакуй этот архив в отдельную папку.
2. Перенеси свою `.env.local` из текущего проекта. Архив намеренно не содержит секреты, `.git`, `node_modules` и сборку.
3. В Supabase SQL Editor выполни **один раз целиком** файл `supabase/migrations/202609150001_community.sql`. Он выполняется в транзакции. Повторный запуск после успешного применения не нужен. При ошибке не выполняй отдельные куски: сначала исправь причину, затем повтори всю неуспешную транзакцию.
4. В `.env.local` добавь `SUPABASE_SERVICE_ROLE_KEY` из настроек своего Supabase-проекта. Он нужен исключительно серверу, чтобы сохранять проверенные метаданные аниме. Не добавляй префикс `NEXT_PUBLIC_` и не отправляй ключ в GitHub. Остальные переменные оставь прежними. Имена показаны в `.env.example`.
5. В CMD внутри папки проекта:

```bat
npm ci
npm run dev
```

6. Войди в аккаунт. На странице аниме выбери статус в блоке «В моей библиотеке». На странице серии нажми «Я посмотрел эту серию». Проверь `/profile` и `/list`.
7. Для Vercel добавь ту же серверную переменную в Environment Variables и выполни новый деплой обычным способом. База должна быть мигрирована до публикации нового интерфейса. В этом сеансе рабочая БД и Vercel не изменялись.

## Проверка главного сценария

В новом аккаунте отметь только 18-ю и 29-ю серии одного достаточно длинного аниме. В профиле должно быть **2 серии, 48 минут**. Серии 19–28 остаются без отметок. Повторная отметка 29-й ничего не прибавляет. «Снять отметку» уменьшает счётчик на одну серию. Открытие страницы, переход к следующей серии и смена статуса не создают завершений.

## Таблицы и связи

| Таблица | Назначение и ключи |
|---|---|
| `auth.users` | Существующая таблица users в Supabase Auth. UUID — идентификатор пользователя; пароли обслуживает Supabase. Вторую таблицу паролей создавать нельзя. |
| `profiles` | Существующий профиль: ник, биография, аватар и баннер. Миграция его не изменяет. |
| `anime_catalog` | Проверенный сервером AniList ID, название, итоговое число серий, признак завершённого выпуска, жанры и дата обновления. MAL ID не подменяет AniList ID. |
| `anime_library` | Один статус для пары `(user_id, anime_id)`: watching, planned, completed, dropped. |
| `episodes_history` | PK `(user_id, anime_id, episode_number)`, completed, completion_source, completed_at. Одна строка — одна конкретная серия. После снятия отметки строка остаётся с completed=false. |
| `achievements` | Каталог условий: код, метрика, порог, название, описание и изображение. |
| `user_achievements` | Уникальная пара пользователь/достижение и дата выдачи. |
| `comments` | UUID, аниме, автор, parent_id, depth, текст, is_spoiler, дата и request_id для идемпотентной отправки. |

Составной FK `(parent_id, anime_id)` не позволяет отвечать на комментарий другого аниме. Изменять parent_id через пользовательский API нельзя, поэтому циклы не образуются. Корень имеет глубину 0, разрешено 8 уровней ответов. Ограничение защищает интерфейс и сервер от патологической вложенности. Удаление аккаунта оставляет комментарии с анонимизированным автором, а личную историю и награды удаляет каскадно.

`anime_library` введена отдельно от старой `user_anime`, SQL-схемы которой в исходном архиве нет. Это предотвращает несовместимые изменения существующей таблицы. Старые `user_anime` и localStorage сохранены, но новая библиотека аккаунта не импортирует их автоматически. Статусы нужно выбрать заново. Старый номер текущей серии не содержит достоверной истории: из него нельзя восстановить уникальные просмотры. Автоматического преобразования N в серии 1…N нет.

## Что именно считается

- **Уникальные серии:** COUNT строк episodes_history с completed=true. Переозвучка и повторный просмотр не создают дополнительную серию. Сезоны должны иметь разные каталожные ID, как в существующей модели AniList.
- **Примерное время:** число завершённых серий × 24 минуты. Часы — целая часть деления на 60, минуты — остаток. Это оценка по условию задачи, не измеренный хронометраж; короткометражки и фильмы тоже оцениваются по 24 минуты за эпизод.
- **Завершённые тайтлы:** выпуск завершён, известно итоговое число серий и отмечены все номера 1…N. Для неизвестного количества серий тайтл пока не считается завершённым. Проверка счёта с уникальным PK и верхней границей номера гарантирует отсутствие пропусков.
- **Статусы библиотеки:** самостоятельная пользовательская классификация. «Просмотрено» в списке не доказывает завершение тайтла и не изменяет историю. Автоматическая выдача достижения по статусу не выполняется.

Последний открытый эпизод в localStorage остаётся только позицией продолжения. Сетки серий получают отдельный массив завершённых номеров из БД, а не рисуют сплошной диапазон до текущего номера. Продолжение открывает последнюю выбранную серию, не перескакивает на следующую только из-за посещения страницы.

## Автоматический и ручной учёт

`useEpisodeTracking.ts` слушает timeupdate/seeking/pause у собственного HTML video. Он объединяет фактически проигранные интервалы, исключает скачки позиции и повторно проигранные участки. После покрытия 90% длительности отправляется отметка одной серии. Ошибка сохранения показывается под плеером, повтор не чаще раза в минуту. Объединение интервалов хранится в памяти текущего источника: после перезагрузки или смены источника покрытие собирается заново. Для таких случаев есть ручное подтверждение.

У внешнего iframe нет универсального доверенного события завершения. Для него используется кнопка «Я посмотрел эту серию». Она доступна и для встроенного плеера, чтобы пользователь мог отметить просмотр на другом устройстве или снять ошибочную отметку.

**Граница защиты:** это защита от ошибочного счёта, скачков и дублей, а не доказательство, что человек смотрел видео. Владелец аккаунта может поставить ручную отметку или подделать события/запросы браузера. Поле source хранит происхождение отметки, но не является криптографическим доказательством. Если награды будут давать деньги или ценные бонусы, понадобится отдельная модель доверенных сессий и верификация событий на стороне провайдера. Текущие достижения — обычные профильные награды.

## API

Все ответы новых маршрутов имеют Cache-Control: private, no-store. Личные запросы требуют аккаунт, чтение комментариев доступно гостям. user_id не принимается из JSON: он получается через auth.getUser(), а внутри SQL — через auth.uid().

| Метод и путь | Параметры | Результат |
|---|---|---|
| GET `/api/community/profile` | Нет | stats, achievements, library текущего пользователя |
| GET `/api/community/episodes?animeId=1` | AniList ID | Массив конкретных завершённых номеров |
| POST `/api/community/episodes` | animeId, episode, completed, source: manual/player | Идемпотентная установка/снятие отметки |
| POST `/api/community/library` | animeId, status | Сохранение одного из четырёх статусов |
| GET `/api/community/comments?animeId=1` | Необязательно parent, cursor | Страница из 20 комментариев одной ветки и nextCursor |
| POST `/api/community/comments` | animeId, body, isSpoiler, parentId: UUID/null, requestId: UUID | ID созданного комментария |

Пример сохранения серии:

```javascript
const response = await fetch('/api/community/episodes', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ animeId: 1, episode: 29, completed: true, source: 'manual' }),
});
const result = await response.json();
if (!response.ok) throw new Error(result.error);
```

Ошибки: 400 — валидация, 401 — нужен вход, 403 — недопустимый Origin, 404 — аниме не найдено, 413 — слишком большой JSON, 429 — частые комментарии, 503 — недоступна БД/миграция/конфигурация. Комментарии загружаются по курсору (created_at, id), без смещения страниц при появлении новых сообщений. Новые сообщения показываются первыми. Ответы подгружаются по раскрытию ветки.

## Достижения и транзакции

`award_achievements` вызывается внутри record_episode/create_comment в той же транзакции и при чтении профиля, чтобы подхватить обновлённые метаданные каталога. Для нового условия добавляется запись в achievements; новая метрика требует расширения community_metrics и CHECK списка метрик.

- Марафонец: 100 уникальных завершённых серий.
- Путь героя: 10 полностью завершённых тайтлов Сёнен.
- Есть что сказать: первый успешно сохранённый комментарий.

UNIQUE/ON CONFLICT защищает от повторной выдачи. Изменения одного пользователя сериализованы транзакционной advisory-блокировкой, включая комментарии и просмотры. Достижения остаются полученными после снятия отметки; текущая статистика пересчитывается. Это сознательная политика постоянных наград.

Метаданные аниме берутся сервером из существующего объединённого каталога. Добавлено сохранение жанров/демографии Shikimori: один только список жанров AniList обычно не включает Сёнен. При временном сбое локализации уже известные жанры не теряются. Обновление метаданных выполняется при очередной записи к аниме, кеш — сутки; фонового обновления всех тайтлов здесь нет. Если источник ещё не отдал жанр/финальное число серий, соответствующая награда появится после обновления каталога и следующей проверки профиля.

## Комментарии и доступ

Обязательное поле isSpoiler — boolean; обязательное наличие чекбокса не означает, что он должен быть всегда отмечен. Скрытый спойлер заменён плашкой, текст не попадает в доступное дерево до раскрытия. Плашка работает мышью и клавиатурой. React отображает текст как текст, без dangerouslySetInnerHTML, поэтому HTML и скрипты не исполняются.

Пустые сообщения, текст длиннее 4000 символов, неверный parent_id и слишком глубокие ответы отклоняются. Между новыми комментариями одного пользователя должно пройти 10 секунд. Повтор с тем же request_id возвращает ранее созданный комментарий без дубля даже после сетевого таймаута.

Авторы отображаются публичным псевдонимом «Участник <часть UUID>», без email. Чужие приватные profiles не запрашиваются. Редактирование, модерация и удаление отдельных комментариев не входят в текущие эндпоинты.

RLS закрывает чужую историю и награды. Прямые пользовательские INSERT/UPDATE/DELETE на новые таблицы запрещены; запись идёт только через разрешённые SQL-функции с фиксированным search_path. Приватные функции расчёта не доступны клиенту. Service role используется сервером только для каталога; для истории и комментариев используется пользовательская сессия.

## Изображения и интерфейс

Подключены существующие экспорты твоих PNG: `/public/ui/animebox-mascot.webp` для пустого состояния, три ранга для достижений и sparkles для стандартного баннера. `/public/ui/animebox-divider.svg` используется в обсуждении. Оригиналы png/ и svg/ сохранены.

Большие SVG из папки svg содержат встроенный PNG, то есть являются растровой картинкой в SVG-обёртке; они не дают преимуществ настоящего вектора. Для рангов и маскота использованы уже подготовленные компактные WebP. Декоративным изображениям задан пустой alt, размеры зарезервированы. Адаптивные стили вынесены в app/community.css.

## Проверки

Проверены TypeScript, production-сборка `next build --webpack`, SQL-миграция и интеграционные сценарии на локальном PGlite (PostgreSQL). Windows node_modules из исходного архива потребовали восстановления Linux-бинарников только в проверочной среде. В готовом архиве зависимостей нет: npm ci установит их под твою ОС. package.json/package-lock.json приложения не менялись.

Тесты БД включают скачок 18→29, дубль, снятие отметки, время, полностью завершённый тайтл, 100 серий, 10 Сёнен-тайтлов, изоляцию статуса, RLS, неправильную серию, гостей, повторный комментарий, ограничение частоты, ответ к другому аниме, глубину 8, пустой текст и отсутствие флага спойлера. Отдельно проверено объединение проигранных интервалов при перемотке и повторе.

Для воспроизведения локальных тестов, не подключаясь к рабочей базе:

```bat
npm install --no-save --package-lock=false @electric-sql/pglite@0.5.8
node tests/community-database.mjs
node tests/played-coverage.cjs
npx tsc --noEmit
npm run build
```

Полноценная браузерная визуальная проверка и проверка на живом аккаунте Supabase в этой среде не выполнены. До публикации проверь вход, ручной просмотр, автоматический просмотр собственного видео, отправку/раскрытие спойлера и мобильную ширину. Миграция в твоём Supabase автоматически не запускалась.

Официальные справочники: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Database functions](https://supabase.com/docs/guides/database/functions), [Next.js Route Handlers](https://nextjs.org/docs/app/api-reference/file-conventions/route).
