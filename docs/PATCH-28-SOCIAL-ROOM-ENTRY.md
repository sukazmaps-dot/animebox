# Patch 28 — Social & Watch Together: Room Entry and Invitations

## 1. Задача продукта

Сделать путь «получил приглашение → вошёл в нужную комнату → позвал друга» предсказуемым. Убрать бесконечное ожидание, неодинаковую проверку ссылок на клиенте и сервере, двойные операции и ошибки состояния списка друзей при переходе между комнатами.

Основа: main 2ffa0c6e. Патч 27 опубликован отдельно как draft PR #175; этот патч не требует его merge. Рабочая ветка: patch-28-social-room-entry.

## 2. Что уже существует

В проекте есть друзья, уведомления, public rooms, секрет приглашения в URL fragment, PeerJS, резервный relay, восстановление при offline/online и возвращении вкладки, смена хоста, чат, голосования и темы комнат. Эти системы не создаются повторно. Существующий protocol version 6 и максимум 50 участников сохраняются.

Эта итерация закрывает вход и социальные приглашения. Новая очередь тайтлов, совместные списки, scheduled events и переработка транспорта — отдельные следующие этапы: их нельзя объявлять готовыми после данного патча.

## 3. Пользовательские сценарии

1. Вставить корректную полную ссылку на youranimebox → перейти к указанной серии/комнате.
2. Вставить относительный путь текущего сайта → получить тот же результат.
3. Ввести короткий код без разделителей, с пробелом или дефисом → одинаковая нормализация.
4. Вставить ссылку чужого сайта, обманный поддомен или ссылку с credentials → показать ошибку, не переходить.
5. Дважды нажать создание/вход до React rerender → одна операция.
6. Не дождаться сервера → через 12 секунд получить ошибку и доступную кнопку.
7. Покинуть hub в процессе ожидания → отменить запрос, не перенаправлять уже закрытый экран.
8. Выбрать комнату, которая заполнилась после загрузки списка → проверить свежий resolve snapshot и показать, что мест нет.
9. Открыть список друзей → фокус оказывается внутри диалога; Tab и Shift+Tab остаются в нём.
10. Escape или клик по backdrop → закрыть диалог и вернуть фокус кнопке «Друзья».
11. Загрузка друзей не удалась → отличать ошибку от пустого списка; предложить повторную загрузку.
12. Приглашение отправлено → отметить только соответствующего друга в текущем приглашении.
13. Ссылка комнаты/серии изменилась → очистить локальные sent acknowledgements предыдущего приглашения.
14. Ответ приглашения потерян → не выполнять автоматический повтор POST. Пользователь может повторить явно; серверные ограничения продолжают действовать.

## 4. Единый контракт ссылки

Новый lib/watch-party-entry.ts используется hub и POST /api/friends/invite.

Ограничения:

- длина входа: максимум 2048 символов;
- разрешены только http/https;
- нет URL username/password;
- origin совпадает с текущим origin либо точно равен https://youranimebox.com или https://www.youranimebox.com;
- production-host с нестандартным портом не считается production-origin;
- путь строго /watch-together/{slug}/episode/{positive integer};
- episode от 1 до 999999 без ведущего нуля;
- декодированный slug не содержит slash, backslash и управляющих символов;
- ровно один query party: 24 строчных hex-символа;
- ровно один fragment partyKey: 32 строчных hex-символа;
- дублирующиеся party/partyKey отклоняются;
- ошибка percent decoding отклоняется;
- fragment-secret не переносится в query, HTTP API path или event metadata.

Канонизация:

- сохраняется целевой путь;
- query пересобирается с party;
- partyTheme сохраняется только для ограниченного текстового значения; entitlement/тема всё равно проверяются существующей системой;
- fragment пересобирается только с partyKey;
- произвольные tracking query/fragment удаляются;
- backend сохраняет в notification только каноническую ссылку.

Граница проверки: корректность URL не доказывает, что комната активна или что у пользователя есть роль хоста. Это проверяют существующие room/session endpoints и transport handshake.

## 5. Короткие коды

normalizeWatchPartyCode — чистая функция.

- принимает 6–12 символов до удаления разделителей;
- разрешены латинские буквы, цифры 2–9, whitespace и дефис;
- удаляет только whitespace/дефис;
- приводит к uppercase;
- после нормализации строго шесть символов [A-Z2-9];
- URL, пунктуация и произвольные тексты не превращаются в якобы корректный код удалением всех неподходящих символов;
- код отправляется существующему resolve endpoint;
- ввод неверного кода не вызывает API-запрос.

## 6. Resolve snapshot и переход

Перед buildWatchPartyUrl проверить runtime payload:

- roomId и joinSecret соответствуют формату;
- slug — непустой текст до 300 символов без slash/backslash/control;
- episode — safe integer в допустимом диапазоне;
- participantCount — неотрицательное целое;
- maxParticipants — целое 1–50;
- status — waiting/watching/paused/voting;
- participantCount >= maxParticipants означает заполненную комнату;
- созданная ссылка проходит ту же canonical validation;
- отменённый signal исключает запись shortcut и переход.

Проверка заполненности — снимок состояния, не резервирование места. Окончательное решение о допуске остаётся за сервером/handshake. Не увеличивать лимит участников на клиенте.

## 7. Ограниченные запросы

Новый requestWatchPartyJson<T>:

- общий timeout 12 секунд для fetch и чтения JSON;
- собственный AbortController;
- поддержка внешнего signal;
- при timeout отменяет fetch и возвращает понятный текст;
- caller cancellation остаётся AbortError;
- очищает timer и abort listener в finally;
- не повторяет запрос автоматически;
- возвращает response и typed payload: вызывающий код обрабатывает HTTP status;
- malformed JSON является ошибкой, не успешной операцией.

Применение: hub create POST, hub resolve GET, friends GET и friend invite POST. Existing public room refresh, report flow и transport loop сохраняются.

Синхронный ref-lock hub покрывает create, public join и code join: competing entry action блокируется до окончания текущей операции. Создание UUID/секрета и построение URL входят в try/finally, чтобы ошибка подготовки не оставила lock.

При unmount hub отменяет текущий запрос. При завершении операции очищается только принадлежащий ей controller.

Ограничение POST: таймаут клиентского ожидания не означает откат уже принятой сервером записи. Нельзя обещать exactly-once delivery без серверного idempotency key; данный патч обеспечивает отсутствие автоматических дублей и повторных кликов, а не транзакционную гарантию.

## 8. Диалог приглашения друзей

Существующий popover/sheet сохраняет desktop/mobile компоновку.

Доступность:

- role=dialog и aria-modal;
- при открытии фокус на первом доступном button;
- Tab с последнего элемента возвращается на первый;
- Shift+Tab с первого возвращается на последний;
- Escape закрывает;
- backdrop закрывает только при клике по самому backdrop;
- при cleanup фокус возвращается конкретной исходной trigger-кнопке;
- animation frame отменяется при закрытии;
- keyboard/resize/scroll listeners очищаются;
- видимый focus outline;
- основной текст минимум .875rem, заголовок 1rem;
- основные кнопки минимум 2.75rem высотой.

Данные:

- friends GET отменяется при закрытии/unmount;
- повторная загрузка запускается отдельным reload token;
- loading, empty и failure — разные состояния;
- ошибки ответа показываются пользователю;
- synchronous invite ref-lock предотвращает несколько POST до rerender;
- пока идёт POST, другие invite buttons disabled;
- sent set обновляется только после успешного HTTP ответа;
- компонент keyed по inviteUrl: состояние предыдущего room/episode не переносится;
- при unmount pending invite request отменяется;
- не выполнять пробную отправку реальным друзьям во время тестирования.

## 9. Auth и backend

userClient, assertAcceptedFriendship, проверка 30-секундного интервала и лимит 20 приглашений/час сохраняются. Не предоставлять friendId из клиентского списка без серверной проверки отношений. Не менять RLS, storage, SQL, право private/public entry или правила Premium. Общий parser не заменяет authorization.

## 10. Аналитика

Имена существующих watch_party_room_created, watch_party_public_join_click, watch_party_code_joined и watch_party_invite_shared сохраняются. Событие успешного friend invite отправляется после HTTP success. Секрет комнаты не добавляется в metadata, лог ошибок или тестовый production запрос.

Прямое открытие ссылки остаётся переходом, а не утверждением о состоявшемся подключении. Существующие transport joined/reconnected события измеряют фактический результат отдельно.

## 12. Критерии приёмки

A. Canonical parser принимает корректные own/production ссылки и отвергает foreign origin, credentials, duplicate keys, malformed secret, invalid episode, encoded slash.
B. Коды ABC234, abc234, ABC-234 и ABC 234 эквивалентны; чужой URL не преобразуется в код.
C. Resolve payload с invalid status/count/capacity/slug отклоняется до навигации.
D. Таймаут завершает ожидание и не повторяет POST.
E. Caller abort отменяет запрос и не превращается в timeout error.
F. Hub lock снимается в finally, включая ошибку подготовки URL.
G. Ошибка друзей имеет отдельное состояние и кнопку повторной загрузки.
H. Invite sent state относится к текущей ссылке.
I. Keyboard focus остаётся в диалоге, после закрытия возвращается trigger.
J. TypeScript, targeted ESLint, новые tests, прежний prebuild и production build проходят.

## 13. Проверка и выпуск

Поведенческие tests/watch-party-entry.cjs покрывают парсер, нормализацию, runtime snapshot, успешный ответ, timeout без повторного POST и внешнюю отмену. patch28:check подключён к prebuild.

Ручная матрица: desktop keyboard, mobile 360/390px, denied auth, empty friends, network error, slow request, valid/invalid link, full room, переход между сериями и повторное открытие invite sheet. Не создавать реальные social notifications в тестах без отдельной команды пользователя.

Порядок выпуска: green local checks → commit → отдельный draft PR → CI → визуальная/двухклиентская проверка → merge/deploy по существующему процессу. Не считать успешную сборку доказательством двухклиентской синхронизации. SQL не требуется.

Откат: revert одного commit; данные и протокол совместимы с предыдущей версией. Старые invite links правильного формата остаются действительными.

Полный прежний prebuild и Next production build завершились успешно. Проверки Patch 28 запускаются после обязательного первого release-consolidation gate.
