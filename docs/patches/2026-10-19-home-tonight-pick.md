# ТЗ: «Что посмотреть сегодня?» — один понятный вариант

## Цель первого среза

После выбора настроения посетитель видит один конкретный тайтл и причину
выбора, может открыть просмотр, описание или попросить другой вариант.
Проверяем полезность этого сценария внутри существующего блока рекомендаций.
Перестановка hero, расписания и Watch Together — следующий отдельный срез.

## Сценарий и интерфейс

1. Секция рекомендаций получает заголовок «Что посмотреть сегодня?».
2. Сохраняется существующий компактный переключатель пяти настроений с
   клавиатурной навигацией, состояниями выбора и объявлениями загрузки.
3. Сразу под ним показывается одна компактная карточка: вертикальный постер,
   название, только известные рейтинг/год/формат, короткое очищенное описание
   при наличии, одна понятная причина выбора.
4. Действия: «Смотреть», «Подробнее», «Другой вариант». Используются
   существующие canonical URL и маршрут просмотра; статус доступности не
   выдумывается, серверный контроль плеера сохраняется.
5. «Другой вариант» перебирает уже рассчитанный пул без дополнительных
   сетевых запросов. Это не «Не интересно», не меняет Taste Graph и не скрывает
   аниме в лентах. До исчерпания пула варианты не повторяются.
6. После просмотра всех вариантов можно явно начать перебор заново. При
   единственном варианте кнопка смены отключена; каталог остаётся доступен.
7. Основной вариант не меняется от фонового ранжирования, если выбранный ID
   остаётся допустимым. После удаления из допустимого пула выбирается следующий.
8. Смена настроения начинает новый выбор. Во время пересчёта не показывать
   старый тайтл как ответ на новое настроение. После ошибки без нового пула
   показывать конечное пустое состояние, а не вечную загрузку.
9. Обычные ленты остаются ниже и сохраняют #281/#282, собственную пагинацию,
   закрепление карточек и ограничения запросов. Промо-тайтл может встречаться
   среди обычных рекомендаций; новая карточка не перераспределяет их владение.

## Выбор и честность объяснений

- Использовать уже готовые RankedRecommendation из HomeFeedRuntimeProvider.
  Нового API, дополнительной модели, повторного ранжирования и миграций нет.
- Сохранить порядок текущего ранжирования. Исключить дубликаты ID, некорректные
  записи, явно недопустимые для публичной главной тайтлы и продолжения, для
  которых требуется ещё не пройденная предыдущая часть.
- Для конкретного настроения выбирать только strong/good по существующему
  mood scorer. Если уверенного совпадения нет, честно показать пустое состояние.
  Режим «Мой вкус» использует общий допустимый пул.
- Причина берётся из существующих explanation-данных. Гостю не приписывать
  историю просмотров. Не писать вымышленные «идеально для тебя», проценты
  уверенности, точную длительность марафона или неподтверждённую доступность.
- Неизвестные рейтинг, год, описание и формат не заменять фиктивными числами.
- HTML провайдера выводится только очищенным обычным текстом.

## Верстка и доступность

- Один CSS Module для нового компонента. Глобальный каскад и палитру не менять.
- ПК: постер слева, текст и действия справа; карточка не занимает целый экран.
- Телефон 360–412px: небольшой постер и текст, действия ниже; без горизонтального
  overflow. Области нажатия не меньше 44px, длинные названия переносятся.
- Светлая/тёмная тема через существующие semantic tokens, без !important,
  декоративного стекла и дополнительных фоновых артов.
- Существующий AnimeImage сохраняет fallback. Ошибка постера не скрывает
  название, объяснение или действия. Новый постер не получает high priority
  и не конкурирует с hero/LCP.
- Загрузка резервирует геометрию. Переключение не двигает фокус; результат
  объявляется через aria-live. Анимация не обязательна.

## Метрики и проверки

- Использовать существующую событийную систему для видимости блока и переходов
  из него с отдельным source. Переход «Смотреть» не считать успешным стартом видео.
- Чистая функция: фильтрация, строгие настроения, дедупликация, причины гостя.
- Реально смонтированный компонент: другой вариант, отсутствие повторов,
  явный перезапуск, новый mood, стабильность при фоновом reorder, удаление
  выбранного ID, пустой пул, busy и исчезновение старой ссылки при смене mood.
- Проверки SSR/разметки: очистка HTML, реальные ссылки, нулевые/неизвестные
  факты, отсутствие CTA в loading/empty, низкий приоритет постера.
- TypeScript, targeted lint, полный prebuild, production build и GitHub Quality
  Gate с существующей responsive-матрицей. Дополнить браузерную проверку
  сценариями выбора нового блока, сохранив все старые проверки главной.
