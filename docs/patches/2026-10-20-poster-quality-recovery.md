# ТЗ: качество постеров и адаптивная резервная загрузка

База: main 2221bb4f. Ветка: fix/poster-quality-recovery.
Второй патч серии «Ленты → Постеры → Проверка надёжности».
Первый патч: PR #289, CI success; на момент начала работы ещё не слит.
Этот PR независим: поведение пагинации не меняется.

## Цель и подтверждённые причины

1. Compact-карточки выбирают large перед extraLarge. Размер производной 540/720px
   не восстанавливает детали, отсутствующие в уменьшенном исходнике.
2. SmartRecommendationCard передаёт quality=62: лестница [60,70,80] округляет его
   к 60. AnimeCard явно передаёт 60. Уровень q70 предусмотрен для card preset.
3. AnimeImage и AnimeImageCascade выставляют responsive srcset только на первом
   источнике. Резервный media endpoint получает одну default-width картинку.
4. rootMargin общего observer не расширяет отсечение внутри горизонтального
   scroll-контейнера. Современные браузеры предоставляют scrollMargin.

## Требования к разрешению и качеству

- Для compact + card/large/hero использовать extraLarge, затем large и известные
  резервные URL того же тайтла. Tiny и вызов без preset сохраняют прежний выбор.
- src и srcset должны использовать один и тот же исходник и preset.
- Сохранить card widths 240/360/540/720, tiny 96/144/240, large 360/540/720/1080.
- AnimeCard и SmartRecommendationCard использовать канонический q70.
- Не увеличивать число вариантов лестницы и не добавлять новые API-запросы
  метаданных на каждую карточку. Не обещать деталей выше качества исходника.

## Резервная загрузка

- При переходе на настроенный резервный media origin заново собрать srcset
  для этого origin и того же исходного изображения.
- AVIF/WebP в picture также следуют активному резервному endpoint.
- Для прямых оригиналов, локальных изображений, /api/image, произвольных origin,
  неподходящего пути и вложенного media URL не создавать responsive media URL.
- Никогда не переносить srcset упавшего primary на резервный src.
- Смена тайтла сбрасывает источник/loaded/retry до commit; поздние события старого
  источника не отмечают новый источник загруженным. Cache completion — через RAF
  с cleanup, без синхронного каскада setState из effect.
- Сохранить независимые источники одного тайтла, серверный путь Shikimori,
  конечный placeholder, лимиты повторов и существующий media circuit breaker.

## Предзагрузка в горизонтальной ленте

- Сохранить один общий IntersectionObserver, без observer на каждую карточку.
- При поддержке scrollMargin расширять только горизонтальные границы вложенных
  контейнеров. Вертикальный rootMargin и budget мобильного старта не увеличивать.
- Без поддержки оставить существующий rootMargin; без observer — native lazy.
- Повторные callbacks не должны запускать постер второй раз; cleanup снимает
  подписку скрытого/удалённого элемента.

## Кэш и расходы

- Используются действующие CDN-кэш, чтение существующих R2-объектов и proxy cache.
- MEDIA_R2_WRITES_ENABLED остаётся выключенным по умолчанию; новые записи,
  инфраструктура, lifecycle-правила или массовый прогрев в этот выпуск не входят.
- q70 и другой исходник создают новые cache keys: возможен временный рост
  холодных запросов и байтов изображения. Это осознанная плата за качество;
  экономию/стоимость нельзя заявлять до production-сравнения.
- Ограниченный постоянный R2-кэш требует отдельной политики объёма/удаления;
  существующий флаг не даёт такого ограничения и здесь не включается.

## Проверки и приёмка

- Реальный helper выбирает extraLarge для card и прежний large для tiny.
- Проверить точные ширины/качество, одинаковый исходник src и srcset.
- Смонтировать настоящие AnimeImage и AnimeImageCascade, вызвать error primary:
  src/srcset/picture должны перейти на резервный origin. Следующий error на
  прямой/proxy путь удаляет media srcset и picture source.
- Неподходящие/рекурсивные URL не получают преобразований.
- Общий observer в поддерживающем браузере получает только горизонтальный
  scrollMargin; в старом — только прежний rootMargin. Активация однократная.
- Сохранить тесты metadata outage, ограниченного каскада, WebP decode, coalescing,
  no-storage defaults, offline/hidden recovery и двух конечных повторов.
- Новый regression-тест входит в poster-reliability:check и CI/prebuild.
- Targeted ESLint, TypeScript, полный prebuild, production build и Quality Gate.
