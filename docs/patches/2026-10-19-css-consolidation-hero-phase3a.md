## Проблема и обоснование выбора

В AnimeBox большое количество перекрывающих глобальных CSS-файлов. Аудит Phase 2 обнаружил 217 CSS, из них 95 CSS Modules, 6 682 декларации с !important и 1 212 повторяющихся глобальных селекторов между файлами. Наиболее сложные общие компоненты — sidebar и topbar — определяются в 11–15 разных глобальных файлах. Их перенос без проверки итогового computed style и разных медиа-состояний может сломать navigation, responsive и Telegram Mini App.

Для первой **реальной**, но безопасной консолидации выбраны три соседних импорта на уровне app/layout.tsx: Hero navigation, Hero copy, Hero swipe. Поиск по репозиторию показал, что все три CSS используются приложением через root layout; архивные ТЗ только упоминают один из файлов. Три файла не содержат @import и url(...), поэтому относительные ресурсы при переносе не пострадают.

## Конкретные изменения

- `app/hero-controls-v5.css` + `app/hero-teaser-v6.css` + `app/hero-swipe-v7.css` → **`app/styles/hero-interactions.css`**.
- Содержимое сохраняется в исходном последовательном порядке. Не менять селекторы, CSS-декларации, значения, specificity, `!important`, @media или @supports.
- Разрешены только редакционные изменения комментариев, убирающие устаревшие версии. Нормализованный CSS после удаления блочных комментариев должен совпадать с прежней конкатенацией текстов.
- `app/layout.tsx`: заменить три **соседних** импорта одним на точно той же позиции. Количество глобальных импортов **76 → 74**.
- `tests/hero-css-ownership.cjs`: фиксирует fingerprint CSS без комментариев, количество правил/деклараций, сохранение ключевых селекторов, проверку путей и порядок импорта.
- `package.json`: команда `npm run hero-css:check`; запуск в начале `prebuild`.
- `.github/workflows/animebox-quality.yml`: быстрый собственный check до остальных CI-шагов.

## Проверка эквивалентности

1. До коммита проверить, что три импорта действительно соседние.
2. Убедиться, что CSS не содержит `@import` и `url(...)`.
3. Проверить равенство всего CSS-текста после удаления комментариев.
4. Сверить точную исходную последовательность: navigation → copy → swipe.
5. Убедиться, что root layout не содержит старых путей и при этом содержит 74 CSS-импорта.
6. Сохранить baseline из 29 CSS-правил, 101 декларации и 76 `!important` в трёх исходных файлах суммарно.
7. Запустить `npm run hero-css:check`, `npm run prebuild`, `npm run build`, TypeScript, targeted ESLint, GitHub Quality Gate.
8. Browser QA: 360 / 390 / 412 / 768 / 1366 / 1920 px, dark/light, mouse/touch, стрелки, свайп и reduced motion. Проверить главную в начальном и settled состоянии с настоящими компонентами, без перекрытия CTA/hero navigation.
