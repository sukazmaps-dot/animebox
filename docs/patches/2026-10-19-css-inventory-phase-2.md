# CSS Inventory — Phase 2

**Дата:** 19.10.2026  
**Ветка:** `chore/css-inventory-phase-2`  
**База:** `main` (`b8d47636`)  
**Тип изменения:** анализатор, тесты и CI; без изменений UI, CSS, API, схем БД или инфраструктуры

## 1. Исходные данные

В `main` обнаружено 217 CSS-файлов, из них 95 `*.module.css`; в `app/` — 124 CSS-файла. `app/layout.tsx` содержит 76 глобальных CSS-импортов. Предыдущий PR #274 начал переход к предметным именам, но на момент подготовки этой фазы ещё находился в Draft; PR #272 (recommendation rails/R2) также не закрыт.

Проблема — многочисленные глобальные стили, исторически названные по патчам, смешанные владельцы селекторов и возможные непреднамеренные переопределения. Без измерений массовая чистка может нарушить темы, адаптивность, Telegram Mini App и каскад на страницах просмотра.

## 2. Результат этой фазы

Выпускается воспроизводимая диагностическая система, которая:

1. Находит CSS-файлы во всех каталогах репозитория, исключая `node_modules`, `.next`, сборку и артефакты.
2. Классифицирует глобальные CSS и CSS Modules.
3. Через TypeScript AST находит статические импорты стилей из JS/TS/TSX и связывает их с CSS-файлами. Не пытается притворяться полноценным runtime-анализатором.
4. Разбирает CSS через PostCSS AST и считает правила, объявления, `!important` и число уникальных селекторов.
5. Выделяет одинаковые селекторы, встречающиеся в разных CSS-файлах; учитывает положение в @media/@supports/@container. Результаты отмечаются как **кандидаты на ревью**, а не как гарантированные ошибки.
6. Показывает CSS-переменные и частоту их определений, чтобы планировать работу с токенами.
7. Показывает файлы без найденных статических импортов, но **не удаляет их**: ссылки могут формироваться динамически или находиться за пределами проверяемых источников.
8. Отмечает отсутствующие локальные CSS-импорты и ошибки CSS-парсера, которые должны приводить к ошибке CI.
9. Создаёт читаемый Markdown-отчёт и подробный JSON для последующего сравнения между релизами.

## 3. Изменения в репозитории

- `scripts/css-inventory.cjs` — read-only анализатор с режимами `--check` и `--report`; флаг `--root` нужен для изолированных тестовых фикстур.
- `tests/css-inventory.cjs` — минимальный тестовый проект, проверяющий CSS Modules, повторения селекторов, `!important`, отсутствующие импорты и ошибки CSS.
- `package.json`:
  - `npm run css:inventory` — построение локального отчёта;
  - `npm run css:inventory:check` — проверка фикстуры и исходного дерева проекта.
- `.github/workflows/animebox-quality.yml`: отдельная проверка после `npm ci`, затем выгрузка JSON и Markdown в артефакт `css-inventory`.
- `.gitignore`: игнорирование локальных `artifacts/css-inventory/`.
- Документ с ограничениями, результатами и следующим планом работ (этот файл).

## 4. Формат артефакта

`artifacts/css-inventory/inventory.json` содержит `schemaVersion`, `sourceSha`, общие показатели, глобальные импорты root layout, показатели по каждому CSS-файлу, повторяющиеся селекторы, переменные, отсутствующие статические импорты и ошибки парсера.

`artifacts/css-inventory/summary.md` содержит сводную таблицу, топ повторяющихся селекторов, топ по `!important`, кандидатов без статического импорта и ограничения методики.

Артефакт генерируется во время CI и хранится 14 дней. Динамический снимок не следует коммитить в код, чтобы не зашумлять историю и не создавать мерцающие изменения на каждом релизе.

## 5. Проверки и инварианты

**Hard failures (должны ломать check):**
- Ошибка PostCSS-парсинга какого-либо CSS-файла.
- Новый отсутствующий локальный CSS-импорт (кроме единственного явно учтённого исторического случая ниже).
- Превышен текущий бюджет в 76 импортов CSS в `app/layout.tsx`.

**Только диагностические наблюдения (не должны ломать check):**
- Много `!important`.
- Повторяющиеся селекторы в нескольких файлах.
- Несколько определений CSS-токена.
- Нет обнаруженного статического импорта CSS.
- Повторения селекторов из разных @media / dark-light theme / override layers.

**Обязательная матрица проверки:**
- `node tests/css-inventory.cjs`;
- `npm run css:inventory:check`;
- `npm run css-cascade:check`;
- `npm run css-route-scope:check`;
- `npx tsc --noEmit`;
- штатный `npm run prebuild` и `npm run build`;
- общий GitHub Quality Gate.

Проверить JSON-схему и целостность Markdown; отсутствие новых runtime-импортов. Если существующие файлы не проходят новый строгий check из-за исторических особых случаев, сначала разобраться в первопричине, а не скрывать ошибки и не удалять защиту.

### Найденный исторический дефект

Первый запуск на `main` выявил `components/ScrollRow.tsx`, который импортирует отсутствующий `components/ScrollRow.module.css`. При этом активная реализация находится в `components/ui/ScrollRow.tsx` и использует существующий `components/ui/ScrollRow.module.css`. Это похоже на устаревший компонент; окончательное решение (удаление, восстановление или миграция) требует отдельного анализа использования. Пока единственная точная пара importer → missing CSS явно допускается как известный baseline, **остаётся в отчёте и не скрывается**; любой другой отсутствующий локальный CSS должен приводить к ошибке CI. Это исключение нужно удалить после отдельной уборки legacy-компонента.

Первый полный отчёт показал 217 CSS-файлов, 95 CSS Modules, 76 root-импортов, 6 682 декларации с `!important` и 1 591 селектор, встречающийся более чем в одном файле. Совпадения не равны подтверждённым визуальным конфликтам.

## 6. Критерии приёмки

1. Ни один рабочий файл CSS, компонент или backend-модуль не изменён.
2. Анализатор работает с Node 22 без новых npm-зависимостей (TypeScript и PostCSS уже доступны в проекте).
3. Тесты фикстур проходят. Отсутствующие файлы и синтаксические ошибки обнаруживаются и формируют ненулевой exit code.
4. В артефактах CI доступны подробный JSON и читаемая Markdown-сводка.
5. Отчёт не заявляет, что отсутствие импорта означает мёртвый файл, и не объявляет каждое совпадение селектора конфликтом.
6. PR изолирован, остаётся Draft до завершения Quality Gate и код-ревью. Не выполнять merge/deploy автоматически.

## 7. План Phase 3 (не входит в этот PR)

1. Из отчёта выбрать наиболее часто пересекающиеся селекторы и файлы с большим числом `!important`.
2. Для каждого кандидата построить таблицу: исходный файл → конкретные route/component → итоговое вычисленное правило в браузере → владелец CSS Module.

6. Сравнивать размер CSS bundle и число `!important` до/после; если улучшение не доказано, откатывать.

## 8. Откат и безопасность

Поскольку патч не меняет исполняемые стили/маршруты, откат ограничивается удалением скрипта, теста, npm-команд, CI-шага и документа. Не нужны миграции, изменение секретов, пересоздание R2, Railway rollout или ручное обслуживание Supabase. Не вмешиваться в активные PR #272–274.
