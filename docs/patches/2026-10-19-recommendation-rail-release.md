# ТЗ: надёжная подгрузка рекомендаций и заполнение по ширине

Дата: 19 октября 2026. Репозиторий: sukazmaps-dot/animebox.

## Проблема и ожидаемый результат

На широком экране пять карточек могут полностью помещаться в ряд. Старый
механизм ждёт взаимодействия для следующей страницы, хотя прокручивать нечего,
а стрелка скрыта. Дополнительно bootstrap считал достаточными пять карточек
вне зависимости от ширины контейнера. В результате остаются пустые участки,
хотя сервер ещё может вернуть подходящие рекомендации.

После изменения видимый короткий ряд заполняет доступную ширину с небольшим
запасом, без обязательного клика или свайпа. Дальнейший просмотр остаётся
управляемым пользователем. Ошибки и нехватка подходящих кандидатов дают
понятное ручное восстановление, а не бесконечные фоновые запросы.

## Состав выпуска

1. PR #281: восстановление запуска подгрузки в видимом ряду без overflow,
   общий latch для геометрии и observer, проверка после взаимодействия,
   fallback при отсутствии IntersectionObserver, остановка автозагрузки
   после ошибки с сохранением кнопки повтора.
2. Отдельная доработка поверх #281: перенести только frontend-часть #272,
   измеряющую вместимость ряда; согласовать оба механизма и обновить реальные
   lifecycle-тесты. Не включать Worker и R2 из #272 в этот выпуск.
3. Сначала зелёный Quality Gate и слияние #281. Следующее изменение проверять
   относительно актуального main; не сливать старый #272 параллельно.

## Функциональные требования

### Заполнение видимой области

- Измерять clientWidth реального scroll-контейнера, ширину реальной карточки
  и вычисленный column-gap. Не рассчитывать по window.innerWidth.
- Цель bootstrap: ceil((ширина контейнера + gap) / (ширина карточки + gap))
  плюс одна карточка; диапазон 5–12. До валидного измерения применять минимум 5.
- На телефоне не запрашивать настольную норму карточек.
- Ближний bootstrap запускается в существующей зоне 520px вокруг viewport.
  Дозаполнение через ScrollRow без взаимодействия допустимо только когда
  сам ряд видим и ещё не имеет горизонтального overflow.
- После расширения окна разрешать новую, большую цель. Повторное событие
  того же размера не запускает повторный поиск по каталогу.
- Сохранять уже показанные карточки, порядок рядов, scrollLeft и touch momentum.

### Запросы, ошибки и ограничения

- Использовать общий поток кандидатов, общий in-flight Promise, cache и cursor.
  Не создавать отдельный API-запрос для каждого ряда на одну страницу.
- Для пустого ряда сканировать максимум три страницы за попытку bootstrap;
  для уже непустого — максимум две. Существующий предел обычной пагинации
  не увеличивать.
- Если ограниченной попытки не хватило для цели, приостановить этот ряд и
  оставить «Показать больше похожих аниме». Не просматривать автоматически
  весь каталог ради заполнения одного ряда.
- Ошибка API блокирует автоматические повторы. Явная кнопка «Повторить»
  запускает новую попытку; частично полученные карточки сохраняются.
- При завершении источника не отправлять новые страницы. Не объявлять
  временную ошибку или неподходящую страницу окончательным концом каталога.
- При смене настроения или unmount отменять устаревшую работу; её результат
  не меняет новую сессию и не снимает её флаг загрузки.
- Дедупликация по anime.id и закрепление карточек за рядами сохраняются.
- «История продолжается» содержит только допустимые продолжения франшиз.
  Если подходящих тайтлов мало, короткий ряд допустим. Не добавлять дубликаты,
  неподходящие тайтлы или вымышленные постеры ради плотности.
- Лимит виртуализированного DOM остаётся 36 карточек на ряд.

## Границы

Изменения касаются компонентов лент, их regression-тестов и этого ТЗ.
Новые глобальные CSS-патчи, изменения API-контракта, ранжирования, Supabase,
авторизации, платежей, плеера и инфраструктуры не требуются.
R2, Worker, его публикация и MEDIA_R2_WRITES_ENABLED остаются отдельной задачей.
Vercel исключён из целевого выпуска: статус Account is blocked не означает
ошибку приложения и не заменяет проверку GitHub Quality Gate.

## Проверки и критерии приёмки

- Unit/regression: реальное вычисление вместимости при мобильной ширине,
  широком контейнере, 4K, нулевой геометрии и дробном gap.
- Lifecycle: несколько видимых рядов делят запрос, desktop получает больше
  пяти карточек, повторный resize не создаёт fetch storm, расширение окна
  поднимает цель, пустая выдача и 400/429/503 имеют ограниченный recovery.
- Сохранить тесты отмены предыдущей сессии и защиты от устаревших результатов.
  Если DOM mock не содержит измеряемый узел, дополнить mock реальной геометрией;
  не удалять старые сценарии ради прохождения теста.
- ScrollRow: видимый короткий ряд дозаполняется; ряд вне экрана, загружаемый,
  исчерпанный или ошибочный ряд не запускает автоматический запрос; overflow
  сохраняет interaction gate; быстрые стрелки и мобильная инерция не ломаются.
- Проверить браузерную геометрию при 390, 1366, 1680 и 1920px на изолированных
  данных; отдельно указать, что fixture не доказывает доступность production API.
- TypeScript, targeted ESLint, полный prebuild, production build и Quality Gate.
- После слияния проверить состояние выпуска и, при доступе, реальную главную:
  прокрутка, смена настроения, возвращение назад и ручной повтор после ошибки.
  Не сообщать об успешном деплое только по факту слияния.

## Порядок отката

При регрессии откатить соответствующий frontend-коммит через revert, сохранив
отдельный исправляющий коммит #281, если проблема относится только к вычислению
вместимости. Не откатывать main целиком и не затрагивать сторонние изменения.
