# Единый hero AnimeBox и мобильные действия рекомендаций

## Проблема и цель

На главной одновременно существуют большая карусель и отдельный выбор на вечер.
Стрелки, счётчик, точки и широкие CTA перегружают телефон; символ закладки
в старом hero выглядит как отсутствующий глиф. На карточках рекомендаций
мобильный CSS скрывает меню обратной связи, предлагая искать его долгим нажатием.

Сделать одну выразительную поверхность выбора и доступные действия карточек.
Основой служат стабильный выбор #283 и композиция #284. Не использовать iframe,
автовоспроизведение видео, новые хранилища или новые источники данных.

## Композиция

1. Серверный HomePageShell сохраняет существующие провайдеры и порядок DOM.
2. Реальное продолжение просмотра — первым, включая локальный прогресс гостя.
   Без незавершённых просмотров полка не занимает места.
3. HomeDiscoverySection становится единственным hero: заголовок H1 «Что посмотреть
   сегодня?», компактные пять настроений, один выбранный тайтл.
4. Удалить mount и импорт старого HomeHeroSection из главной. HomeHeroCarousel
   может оставаться для прежних потребителей и изолированных регрессионных тестов;
   он не должен загружаться как второй hero на главной.
5. Дальше: совместный просмотр, расписание, один feed, каталог, гостевой prompt,
   чат, персональные вторичные блоки и поддержка — как в #284.

## Внешний вид hero

- ПК: текст слева, известный banner справа, плавное затемнение к тексту;
  при отсутствии banner — вертикальный постер справа с object-fit: contain.
- Телефон: вертикальный cover занимает фон, focal point из существующих
  метаданных, вертикальный градиент обеспечивает контраст текста и CTA.
- Одна активная цепочка AnimeImage с имеющимися источниками, retry и fallback.
  Не загружать одновременно скрытые mobile/desktop картинки, не делать API
  запросы за дополнительным артом. Выбор вида арта обновляется при resize.
- Заголовок страницы тематический; название аниме — H2, не больше трёх видимых
  строк, полный текст остаётся доступным. Год/оценку/формат показывать только
  при наличии. Описание очищать; максимум две строки на ПК, скрывать на телефоне.
- Сохранять объяснение рекомендации, честное для гостя и выбранного настроения.
- Фон арта тёмный в обеих темах; заголовок страницы, picker и окружающая страница
  используют существующие семантические токены.
- Ориентир высоты: около 400–440 px на ПК и 360–400 px на телефоне. Контент может
  увеличивать высоту при длинном названии, увеличенном шрифте и сообщении ошибки;
  не обрезать кнопки ради фиксированного размера.
- CSS владельцы: существующий HomeTonightPick.module.css и HomePageShell.module.css.
  Новых глобальных слоёв, !important в модулях и постоянного свечения не добавлять.

## Действия hero

- Смотреть / Подробнее используют существующие canonical anime URL.
- Другой вариант сохраняет локальный цикл без повторов до явного сброса,
  не является отрицательным taste feedback и не запускает новый candidate API.
- Ни стрелок, ни точек, ни счётчика, ни автоматического переключения.
- SVG-закладка: 44×44 px, доступное имя, состояние busy/saved/error, повтор ошибки.
  Для гостя — существующая auth modal; mutation только после нажатия пользователя.
  Изолировать сохранение между разными тайтлами и учётными записями, запретить
  двойной запрос, отправлять library-updated только при успешном сохранении.
- Смена настроения не должна выдавать старый ranked pool за новый. Сохраняются
  stable choice, strict candidates, prerequisites, public filtering и attribution.
- Loading/empty — часть того же hero, без вечного spinner и без фиктивного CTA.
  Решение появляется после существующего ранжирования; старый SSR-карусельный
  контент больше не является независимым первым тайтлом.

## Меню рекомендаций на телефоне

- Закладка и ⋯ постоянно видны, каждая с областью нажатия минимум 44×44 px,
  контрастной подложкой и SVG. Положение — столбиком в правом верхнем углу постера.
- Править существующий владелец app/patch17-6-home-recommendation-actions.css:
  удалить правило, делающее overflow-кнопку прозрачной и некликабельной.
- Сохранить onContextMenu как дополнительный shortcut; долгий жест не должен
  быть единственным способом обнаружения настроек.
- Использовать прежний dialog: нравится / уже смотрел / причины скрытия,
  закрытие по Escape и отмене, возврат фокуса, undo и прежние события.
  Не вкладывать кнопки внутрь ссылки и не переходить на тайтл при нажатии ⋯.

## Приёмка и проверки

- Ровно один hero/choice, один H1, один picker и один feed в реальном DOM.
- Обновить устаревшие проверки, требовавшие два отдельных hero/discovery mount,
  пояснив замену. Оставить exactly-once, server shell, единственный runtime,
  bounded infinite rails, lazy budgets и остальные защитные контракты.
- Mounted тесты: сохранение гостя/пользователя, двойной клик, ошибка/повтор,
  смена тайтла во время mutation; desktop/banner/mobile/poster выбор арта.
- Браузерная матрица: обе темы, 360–430, 768, 1024, 1366, 1440, 1920 px,
  landscape, banner и poster fallback; отсутствие overflow и перекрытий,
  кнопки >=44 px, смена mood/варианта с сохранением фокуса.
- На настоящем touch viewport проверить видимые две кнопки, открытие dialog
  обычным нажатием, закрытие/возврат фокуса и feedback/undo без перехода страницы.
- Отдельно проверить ошибку изображения: содержимое и действия hero доступны.
- Полный prebuild, TypeScript, целевой ESLint, production build, браузерный CI и
  просмотр скриншотов. При недоступном локальном Chromium не выдавать unit за UI QA.
- Публиковать только после успешных проверок; deployed version подтверждать
  в Railway по SHA и SUCCESS. #284 и этот патч имеют отдельные статусы выпуска.
