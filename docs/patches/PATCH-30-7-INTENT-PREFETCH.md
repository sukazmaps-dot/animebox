# Patch 30.7 — Предзагрузка тайтлов по намерению

Дата: 15 октября 2026. База: main `008440ce`.
Ветка: `patch-30-7-intent-prefetch`.

## Проблема и подтверждённые источники

`AnimeCard.tsx` принудительно задаёт `prefetch={true}`. В
`SmartRecommendationCard.tsx` это делают две ссылки: постер и название.
`TopAnimeItem.tsx` оставляет автоматическую политику Next Link по умолчанию.
Появление ссылок в viewport способно запускать спекулятивную загрузку
маршрутов, даже когда посетитель только просматривает полки. Это
дополнительная конкуренция за сеть и потенциальная серверная работа.
Фактический объём экономии CPU и CWV пока не измерен.

## Цель и границы

Сохранить возможность заранее подготовить заинтересовавший тайтл,
убрав запуск этой работы от одного появления карточки в viewport.
Не менять CSS, источники постеров, DOM-геометрию, API, БД,
авторизацию, рекомендации и фоновую подкачку следующей страницы ленты.
Не менять предзагрузку следующего эпизода в плеере.

## Поведение

1. Общий `AnimeIntentLink` рендерит настоящий Next Link с `prefetch=false`.
2. Mouse pointerenter ставит таймер на 180 мс. Pointerleave, pointercancel,
   blur и unmount отменяют ожидание. Быстрое пересечение карточек не
   должно запускать запросы страниц.
3. Фокус с `:focus-visible` прогревает маршрут сразу. Это позволяет
   клавиатурному пользователю получить ту же подготовку без hover.
4. Touch/pen pointerenter не запускают таймер. Фокус от касания без
   focus-visible также не запускает прогрев. Обычный клик работает сразу.
5. Перед прогревом проверяются видимость вкладки, offline, saveData,
   effectiveType slow-2g/2g/3g. Отсутствие Network Information API не
   блокирует обычный desktop intent.
6. Используется стандартная политика `router.prefetch(href)`, без
   принудительной полной загрузки динамической страницы. Дедупликацией
   маршрутов между ссылками управляет Next router; одна смонтированная
   ссылка также не прогревает один href повторно. Смена href снимает флаг.
7. Ошибка спекулятивного вызова не мешает переходу; можно повторить
   попытку при новом намерении. Никаких preventDefault на клике.
8. Сохраняются href, target, aria-label, title, className, children,
   onClick и внешние pointer/focus callbacks. defaultPrevented
   пользователя запрещает запуск по соответствующему событию.
9. Нет глобальных обработчиков scroll, новых IntersectionObserver,
   fetch на карточку при mount, новых библиотек или глобального состояния.

## Интеграция

- Обычные карточки на главной, в каталоге и связанных тайтлах — AnimeCard.
- Постер и название рекомендаций — SmartRecommendationCard.
- Список верхних позиций — TopAnimeItem.
- Не менять другие ссылки без доказанной необходимости.

## Критерии приёмки

- До намерения ни одна ссылка из этих компонентов не запускает route prefetch.
- Hover менее 180 мс и отменённый pointer не прогревают маршрут.
- Долгое наведение и фокус с клавиатуры прогревают нужный href.
- Касание/свайп не запускают предзагрузку от pointerenter.
- Экономия трафика/медленное соединение/offline/hidden блокируют прогрев.
- При unmount и смене href таймер старого назначения удаляется.
- Аналитический onClick вызывается как раньше; новый tab сохраняется.
- Внешний вид 360–412 и 1440–1920 не изменяется: общий компонент
  не добавляет обёрток и не трогает stylesheet.

## Проверки и доказательства

`tests/anime-intent-link.cjs` выполняет транспилированный настоящий
React-компонент с тестовым Next router, управляемыми таймерами и
Network Information API. Проверяет mount без запросов, dwell,
отмену, touch, focus-visible, сетевые ограничения, callback, href,
cleanup и ошибку prefetch. Это проверка логики событий, а не замер
production RSC-запросов или полная браузерная проверка Next Link.

Обязательные проверки: `npm run patch30-7:check`, targeted ESLint,
TypeScript, полный prebuild и production build. Новая проверка включена
в prebuild и Quality Gate. Для реального замера после публикации:
сравнить одинаковые сессии без кликов на production, количество RSC
prefetch запросов и Railway CPU. Не объявлять ускорение в процентах
без этих наблюдений.

## Риски и выпуск

Мобильный пользователь без hover может ждать загрузки маршрута после
тапа: это осознанная экономия фоновых запросов. Клиентская граница
добавляется только вокруг ссылки; карточка не становится целиком
клиентским компонентом. Новых SQL миграций нет.
Оформить отдельный PR; автослияние/деплой в рамках этой реализации
не выполняются. Откат — revert PR. Проверки не требуют секретов БД.
