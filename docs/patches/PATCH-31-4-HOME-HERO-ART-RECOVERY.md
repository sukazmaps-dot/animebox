# Patch 31.4 — качество и восстановление артов главной

## Подтверждённые причины
- На главной сохранённый каталог выдаёт poster_url одновременно как cover.large и cover.extraLarge, без bannerImage. Детальная страница того же тайтла получает отдельный горизонтальный баннер.
- До обновления Cloudflare media v5 отдавал 204 / origin-403. Пользователь опубликовал v6 и включил MEDIA_ORIGIN_RELAY_ENABLED=true.
- После обновления запрос w1440 для Precure возвращает origin-relay-fill, JPEG 460×651. Это настоящий постер, а не широкоформатный арт; параметр w не создаёт детали.
- Карусель не включала существующий серверный /api/image в резервную цепочку. Индексы попыток сбрасывались микрозадачей после смены ID.

## Требования и реализация
1. Добавить серверное обогащение art-полей для ID из первого экрана: один пакет, максимум 24 уникальных ID, таймаут 2 секунды, кеш результатов 15 минут, объединение одновременных запросов. Оно выполняется только при заполнении общего пяти­минутного кеша главной. На холодном кеше допустима дополнительная задержка до 2 секунд. Провайдерный сбой возвращает исходный feed.
2. Сопоставлять результаты только по ID и проверять MAL ID при наличии. Не менять порядок, состав, название, рейтинг, эпизоды, slug или доступность. Сохранять заданные mobileHeroImage/mobileHeroPosition. Подставлять bannerImage и реальный extraLarge из ответа провайдера. Не сочинять URL заменой /large/ на /extraLarge/.
3. Desktop: баннер, специальный арт, постер. Mobile: специальный арт, крупный постер, прочие исходники, баннер. Один picture/img, без загрузки двух отдельных картинок.
4. Основной media/R2 путь сохраняется. После отказа — same-origin /api/image с fallback=error для доступных исходников, затем прямые оригиналы. Никаких SVG-заглушек с успешным HTTP в резервной цепочке.
5. Состояние изображения принадлежит компоненту с ключом ID + источники. Смена слайда или URL создаёт новое состояние. Индексы ограничены длиной цепочки. Зависший запрос переводится дальше через 8 секунд; таймер очищается при смене попытки/слайда. Активное изображение загружается eager, высокий приоритет только у первого слайда. Автопрокрутка по-прежнему включается только после взаимодействия.
6. Desktop poster fallback: отдельная правая область шириной 43%, высота 92%, contain вместо cover. Мобильный full-bleed арт и точка фокуса сохраняются. Редактировать существующий CSS-владелец геометрии, без нового глобального patch CSS.
7. Если все источники отказали, сохранить текст, кнопки, пагинацию и фон. Не зацикливать запросы.

## Проверки
- Сервер: пакетная дедупликация, кеш, таймаут/отказ, неизвестные ID, MAL-конфликт, сохранение метаданных и curated-полей.
- Реальный React-компонент в Chromium: 360/412/1440/2560; выбор mobile/desktop источника; CDN 204 → proxy; proxy error → origin; полный отказ; смена слайда во время старого запроса; watchdog; poster fallback и отсутствие переполнения.
- Существующие проверки home/art/availability/image delivery; TypeScript; targeted ESLint; prebuild и Next production build в CI.

## Границы релиза
Миграций БД нет. Код/настройки Cloudflare не меняются. Отдельная ветка и PR; слияние и production-деплой выполняются по отдельной команде пользователя. Реальную детализацию ограничивает исходный арт; качество q не восстанавливает отсутствующие пиксели.
