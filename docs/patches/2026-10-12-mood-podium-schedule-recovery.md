# ТЗ: меню настроений, рамка лидера, сетка расписания и восстановление постеров

Дата: 12.10.2026. База: main, 34ef4dca. Ветка: fix/mood-podium-schedule-recovery.
Основание: три новых скриншота после предыдущего деплоя.

## 1. Цель

Меню настроений должно полностью раскрывать доступные пункты на компьютере и телефоне. Рамка лидера должна сохранять размер и композицию, не перекрывая никнейм и уровень. Четыре записи расписания должны образовывать предсказуемую сетку. При отказе media-сервиса мини-постеры должны использовать подтверждённый рабочий same-origin путь без перебора нескольких заблокированных прямых размеров.

Патч затрагивает MoodFilter, CSS рейтинга, маршрутные стили главной, порядок резервных источников tiny-изображений и подготовку обложек резервных провайдеров расписания. Алгоритм рейтинга, начисление опыта, учёт просмотров и ранжирование рекомендаций не изменяются.

## 2. Подтверждённые причины

### Меню настроений

В предыдущем патче высота рассчитывалась по getBoundingClientRect().top первого найденного элемента мобильной навигации. Этот элемент существует и на desktop, но скрыт. display:none даёт нулевые размеры и top=0. Вычисленная доступная высота отрицательна, Math.max(44, available) устанавливает 44 px. Заголовок занимает почти весь выпадающий список. Это регрессия предыдущего исправления и не ошибка списка настроений.

### Рейтинг

Leaderboard.module.css совмещает фиксированную высоту карточки, фиксированные строки для имени/статистики и рамку с inset:-18%. Визуальный размер рамки составляет 136% области аватара, но дополнительные 36% не входят в поток страницы. Имя оказывается под нижним украшением. Увеличение z-index не создаёт пространства и проблему не решает.

### Сетка расписания

HomeScheduleSection выводит до четырёх элементов, а home-visual-repair.css использует auto-fit с min 19rem. При доступной ширине около 1200 px получается три колонки, поэтому результат — три карточки и одна на следующей строке. Это закономерный результат CSS, не пропажа пятой записи: пятая доступна по ссылке «Все выпуски за день».

### Постеры

Выполнена проверка трёх тайтлов: «Я перевоплотился в гоблина, вопросы есть?», «Псайрен», «Военная хроника Ромелии». У актуального /api/schedule есть реальные AniList URL обложек.

| Путь | Результат для всех трёх |
|---|---|
| media.youranimebox.com/image, w=96/q=60/webp | HTTP 204, x-animebox-media=source-soft-fail, x-animebox-origin-error=origin-403 |
| youranimebox.com/api/image, тот же оригинал, fallback=error | HTTP 200, декодируемый JPEG/PNG, ширина 230 px |

Следовательно, источник не полностью недоступен: same-origin путь работает. Текущая цепочка обычного изображения пытается прямые оригиналы/размеры раньше прокси. Для tiny-постеров приоритет рабочего пути нужно изменить локально, сохранив media первым.

Резервное расписание Shikimori дополнительно теряет независимый original, если в каталоге найден poster_url: оба поля изображения заполняются одним URL. Jikan compact snapshot не сохраняет images, поэтому доступная обложка провайдера теряется ещё при загрузке недельного расписания.

## 3. Контракт меню настроений

### 3.1 Входные измерения

Использовать bounds триггера, а не текущего меню: меню меняет положение/высоту, поэтому измерение собственного top может создавать обратную связь и переключение направления.

ViewportTop = visualViewport.offsetTop либо 0. ViewportBottom = ViewportTop + visualViewport.height либо innerHeight. Это учитывает уменьшение видимой области экранной клавиатурой и панорамирование visualViewport.

Кандидаты нижней навигации: существующие классы .mobile-nav, .mobile-bottom-nav, .bottom-nav и [data-mobile-nav]. Элемент учитывается только если:

- computed display не none;
- computed visibility не hidden;
- getClientRects() не пуст;
- ширина и высота bounds положительны;
- элемент пересекает видимый viewport;
- его верхняя граница находится ниже триггера.

На desktop скрытая навигация должна игнорироваться. Если видимой нижней навигации нет, использовать viewportBottom, без искусственного вычитания 80 px.

### 3.2 Направление

Зазор от триггера 9 px, безопасный отступ от viewport/панели 12 px. Вычислить пространство сверху и снизу. Предпочесть вниз, если список помещается. Если не помещается и сверху больше места — открыть вверх. Желаемая высота ограничена 560 px и фактическим scrollHeight содержимого.

Нельзя заменять недостаток места произвольной высотой 44 px, выходящей за доступное пространство. maxHeight должен быть ограничен реально доступным местом. В экстремально маленьком viewport допустима внутренняя прокрутка; состояние не должно приводить к циклическому resize.

Направление задаётся data-direction=up/down на меню. Для up: top:auto, bottom:calc(100% + 9px), transform-origin:bottom left. Не менять DOM родителей и не переносить пользовательские события в непредусмотренный контейнер.

### 3.3 Пересчёт и доступность

Измерять при открытии, window resize/scroll, visualViewport resize/scroll. В cleanup удалять все добавленные listeners. Сохранить Escape, выбор стрелками/Home/End, Enter/Space через кнопки, закрытие вне компонента и возврат фокуса. Закрытое меню остаётся inert. Выбранная опция сохраняет aria-selected; триггер — aria-controls и aria-expanded.

Цвета используют существующие --ab-ui-*; меню остаётся непрозрачным. Light и dark работают через те же токены.

### 3.4 Приёмка

Desktop со скрытой мобильной панелью: высота не схлопывается до 44 px, все пункты достижимы. Телефон с видимой панелью: меню не перекрывает её. Триггер возле низа: меню открывается вверх. Клавиатура уменьшает viewport: высота обновляется. Длинный список прокручивается внутри, страница не получает непредусмотренную ширину.

## 4. Геометрия пьедестала

### 4.1 Сохранение рисунка

Размер аватара --podium-avatar-size сохраняется. Ранее рисунок рамки занимал область --podium-art-size × 1.36 из-за inset:-18%. Новый avatarStage занимает именно эту полную область в потоке страницы. Сама seasonFrameOverlay получает inset:0. Таким образом визуальный размер рамки остаётся прежним, а layout наконец резервирует место под него.

Круглая обрезка остаётся только у фотографии. Декоративная рамка не обрезается overflow:hidden. Уровень и никнейм не позиционируются абсолютно и не размещаются поверх frameAsset.

### 4.2 Карточка

Фиксированную сетку 14px/minmax(...)/52px/50px/50px заменить пятью строками auto: подпись места, область композиции, идентификация, статистика, footer. height:auto, разумная min-height для выравнивания пьедестала. Gap между строками 10 px.

Для первого места сохраняется большая минимальная высота, но контент может её увеличить. На мобильных старые height:324/348 также заменить на auto с соответствующей min-height, чтобы финальная media query не вернула пересечение.

Имя сохраняет существующее ограничение длинного никнейма. Бейдж уровня может переноситься и имеет overflow-wrap. Секция идентификации min-height вместо фиксированной высоты. Корона находится внутри зарезервированной композиции; seal не опускается ниже контейнера.

Порядок/места участников и одинокая карточка при единственном участнике не считаются багом и не заменяются вымышленными участниками.

### 4.3 Приёмка

Первое/второе/третье место с каждой сезонной рамкой. Видимый нижний край рисунка выше имени, между областями есть gap. Длинное имя и высокий уровень не обрезают карточку. Один участник сохраняет корректную карточку. Телефон, планшет и desktop не возвращают фиксированную высоту из старых CSS-слоёв.

## 5. Сетка расписания

На главной максимум четыре записи выбранного дня. Для доступной main-column ниже 76rem: две равные колонки, то есть 2×2 при четырёх записях. Начиная с container home-main 76rem: четыре колонки. На телефоне до 600 px: одна колонка. Breakpoint desktop зависит от ширины контейнера, а не всего окна с sidebar.

Сохранить семь дней, даты и выбранное состояние. Четвёртая запись не должна превращаться в единственную карточку второго ряда при трёх колонках. При 1/2/3 записях допустим незаполненный последний ряд; не дублировать данные для заполнения сетки. Ссылка на все выпуски и реальное количество записей сохраняются.

Обложки 36×54 px, названия максимум две строки, время не выдавливает текст. Нет горизонтального overflow страницы на 320 px. Пустой день и ошибка API остаются различимыми.

## 6. Восстановление tiny-постеров

Первый кандидат остаётся media-сервисом. Только для delivery.preset=tiny сразу после media-кандидатов идёт /api/image для основного оригинала. Далее — альтернативный источник и его прокси, затем локальные кандидаты/заглушка. Не добавлять повторные URL: Set сохраняет дедупликацию.

/api/image получает fallback=error. Ответ-заглушка со статусом 200 не должен выдаваться за успешно загруженный постер, мешая переходу к следующему источнику. Существующие ограничения доменов, запрет приватных адресов/редиректов, проверка MIME и размера остаются в proxy/Worker.

Прямые Shikimori URL в браузер не добавляются. Для обычных card/large сохраняется существующая цепочка: это локальная политика маленьких обложек, а не перевод всего каталога на origin-proxy. Успешный media-ответ по-прежнему требует один запрос.

Приёмка: media 204/403/502 приводит к следующему URL /api/image; рабочий raster отображается; отказ всех источников заканчивается стабильной заглушкой без бесконечных запросов; повторные URL не возникают; ограничение источников сохраняется.

## 7. Обложки резервного расписания

Добавить schedulePosterImage: нормализовать входные URL через существующий normalizeImageUrl, удалить дубликаты, отсутствующие значения и известные missing_/локальные брендовые заглушки. Если есть источники: large=основной, extraLarge=независимый резервный либо основной. Если нет — null.

Shikimori: передавать сохранённую обложку каталога и собственный оригинал провайдера, сохраняя оба, если различаются. Не превращать MAL ID в AnimeBox ID; привязка по существующему anime_availability сохраняется.

Jikan: сохранить поля images.jpg.image_url/large_image_url при compactAnime. Для сопоставленного тайтла использовать URL каталога с резервом провайдера; при отсутствующем poster_url допустимо использовать провайдерскую обложку. Старые сохранённые snapshots без images остаются совместимы; не запускать принудительный полный download ради версии формата. Новые снимки получают изображения после обычного обновления.

Не добавлять отдельный сетевой запрос для каждой карточки. Использовать уже загруженные metadata и snapshot. Не менять таблицы и не создавать миграцию.

## 8. Проверки

Новая поведенческая проверка helper меню: скрытая панель с нулевыми bounds; несколько панелей; видимая mobile navigation; нижний триггер; visualViewport с offset; маленький экран. Результаты проверяются по числам, а не присутствию строки в коде.

Проверка источников: реальная image-service функция tiny chain содержит same-origin основного раньше других browser fallback; исходные Shikimori не попадают напрямую в браузер; schedulePosterImage сохраняет два разных URL и исключает missing_; реальные compactAnime и getJikanSchedule сохраняют провайдерскую обложку.

Существующие регрессии: media-schedule-fix, media-edge-cooldown, SSR расписания, prebuild gates, TypeScript, ESLint изменённых файлов, git diff --check. Полная npm run build выполняется с NODE_ENV=production — случай предыдущего сбоя тестового act() не повторяется.

Визуальные критерии для новой версии: desktop меню имеет нормальную высоту; рамка не накрывает имя; четыре записи имеют 2×2 либо четыре колонки; реальный телефон учитывает нижнюю навигацию. До публикации изменённого UI нельзя считать браузерную проверку завершённой только по успешной сборке.

## 9. Поставка и ограничения

Поставка: отдельная ветка и PR, это ТЗ, поведенческие проверки и описание результата. Деплой этого патча требует дальнейшего поручения пользователя. Не смешивать успешную сборку с опубликованной версией.

Live-проверка доказала рабочий proxy для трёх конкретных AniList изображений в момент выполнения. Она не гарантирует доступность всех внешних оригиналов, других провайдеров или любых регионов. Если все кандидаты реально недоступны, отображается заглушка; не подменять её чужим постером по похожему названию.

## 10. Реализация и результаты

Изменения выполнены в перечисленных компонентах и helpers. Добавлен tests/mood-schedule-recovery.cjs; он включён в существующий home-tracker-recovery:check и полный prebuild. Уточнена старая проверка tiny-кандидатов: теперь она требует рабочего primary-proxy сразу после edge, сохраняя проверку независимого большого оригинала и прежнюю политику обычных card-постеров.

Проверено:

- Настоящий MoodFilter монтируется в React с невидимой нижней навигацией: получает 430px, direction=down.
- Helper проверяет desktop, видимую мобильную панель, открытие вверх, смещённый visualViewport и ограниченное пространство.
- Настоящие функции image-service/schedulePosterImage сохраняют альтернативы, исключают известную заглушку, не выводят прямой Shikimori и ставят primary same-origin раньше других tiny fallback.
- Настоящий getJikanSchedule с контролируемым клиентом данных возвращает провайдерский постер при null poster_url каталога и сохраняет корректное сопоставление ID.
- NODE_ENV=production npm run build — PASS: полный prebuild, TypeScript и production Next build.
- ESLint изменённых TS/TSX — без ошибок; остаётся существующее предупреждение неиспользуемого _malId.
- git diff --check — PASS.
- Live-ответы трёх оригиналов через /api/image: HTTP 200, декодируемые JPEG/PNG. Постер «Гоблина» дополнительно осмотрен визуально; это обложка тайтла, не логотип.

Ограничение: визуальная браузерная проверка изменённой геометрии на новой версии ещё не выполнена. Локальная среда не имеет доступного Chromium; опубликованный сайт до слияния обслуживает предыдущий патч. Исправления пока поставляются через отдельный PR, не объявляются опубликованными.
