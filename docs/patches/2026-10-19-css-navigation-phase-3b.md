# CSS Consolidation — Phase 3B: Navigation cascade

Дата: 19.10.2026. Ветка: `refactor/navigation-cascade-phase-3b`. База: `main` (`b8d47636`).

## Контекст и стратегия

Аудит CSS обнаружил, что `.sidebar`, `.topbar` и `.page-content` определяются во множестве глобальных CSS. Массовое удаление перекрытий опасно: в проекте существуют разные брейкпоинты, темы, Telegram Mini App, фиксированные visual-test контракты и специальные стили страницы просмотра. Прежде чем перестраивать собственность CSS Modules, проводим узкий, проверяемый проход по обычным CSS-декларациям.

Не объединять `globals.css` и `hierarchy-pass.css`: это изменит последовательность каскада. Не переносить общие shell-правила в CSS Modules до проверки computed styles в браузере.

## Объём реализуемой первой волны

В `app/globals.css` удалить только **шесть** деклараций, которые безусловно повторяются более поздним файлом `app/hierarchy-pass.css` с теми же селекторами и значениями:

| Селектор | Свойство | Значение владельца |
| --- | --- | --- |
| `.sidebar` | `display` | `flex` |
| `.sidebar` | `flex-direction` | `column` |
| `.sidebar__item` | `gap` | `12px` |
| `.sidebar__item` | `color` | `var(--ab-ui-muted)` |
| `.sidebar__label` | `color` | `var(--ab-ui-muted)` |
| `.topbar__search input::placeholder` | `color` | `var(--ab-ui-muted)` |

Последний ранний селектор целиком удаляется, поскольку содержал только одно дублирующее объявление. Поздний владелец остается на месте.

Селекторы имеют одинаковую специфичность; все шесть поздних деклараций находятся вне @media/@supports/@layer и не имеют другого `!important`. Поэтому при штатном порядке глобальных импортов удаление затенённых ранних значений не должно менять computed style.
