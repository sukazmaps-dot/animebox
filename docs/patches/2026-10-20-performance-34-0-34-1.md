# AnimeBox Performance 34.0 + 34.1 — Field Baseline & Instant Home First Choice

Date: 2026-10-20. Target: Next.js App Router production `main`, Railway, mobile Chrome, Telegram Mini App.

## 1. Incident baseline (measured, not estimates)

From a bounded recent Railway HTTP-log sample (500 requests, route sample sizes small):

| Route | n | HTTP p50 | HTTP p95 |
|---|---:|---:|---:|
| `/` | 25 | 11 ms | 14 ms |
| `/search` | 18 | 802 ms | 1268 ms |
| `/chat` | 15 | 1537 ms | 2778 ms |
| `/api/anime` | 29 | 420 ms | 2208 ms |
| `/api/recommendations` | 9 | 581 ms | 1939 ms |
| `/api/search/instant` | 26 | 111 ms | 1506 ms |

These are origin/proxy timings, NOT end-to-end user loading, LCP or p75 Core Web Vitals. No browser/user-journey before/after data exists for this release. The latest 24-hour Railway resource sample had RAM avg ~0.62 GB and CPU_USAGE avg ~0.069 (unit as reported by Railway).

## 2. Root causes & scope

- Public home HTML has ISR and a 300 s saved-first feed. The server already sends available cards, but `HomeDiscoverySection` immediately renders `HomeTonightLoading` because `hydrated=false` and recommendation ranking runs later via an idle-loaded JS chunk.
- `HomeTonightPick` previously used `next/dynamic(..., {ssr:false})`, guaranteeing no SSR choice image on first paint. This is critical for the above-the-fold image and makes cold mobile loads feel empty.
- No sampled first-party browser Core Web Vitals collector in the current root layout; Railway fast HTTP 200 does not prove actual LCP/INP.
- Do NOT move personalization to server, change recommendation scoring, touch Kodik, replace cache policy, force eager loading of other page sections, or add image re-requests.

## 3. Changes

### 34.0 — Low-cost field diagnostics

- Mount `FieldWebVitals` in root client layout, use Next's `useReportWebVitals` hook (no external script or npm dependency).
- Only a 2% per-document random sample on non-localhost browsers uses the EXISTING `/api/analytics/product` batched event queue. New allowlisted event: `field_web_vital`.
- Report metric names LCP, INP, CLS, FCP and TTFB with bounded values and units. Whitelist rating + navigation type; capture mobile/desktop and standalone/browser.
- Strict route grouping: `/`, `/search`, `/list`, `/schedule`, `/anime/[slug]`, `/anime/[slug]/watch`, `/profile/[id]` etc. **Never include search terms, title slugs, user profile IDs, full URLs or admin paths in performance metadata/path.**
- Telemetry is best-effort and never blocks content, auth or player progress. Existing product event envelopes still carry their normal session/anonymous IDs; this is route-anonymized telemetry, NOT an anonymous analytics system.
- Per-metric-ID deduplication avoids noisy repeated calls. As this patch reports first emissions for that ID, measurements can differ from the FINAL CWV measurement for long-lived pages. Future dashboards must document this limitation; this is a starting sample.
- Localhost and 127.0.0.1 never report Web Vitals. Preview hosts can still be sampled; dashboards must filter production origin if required. No client-side private environment variable reads.
- No unbounded queue, new DB table/migration, Cloudflare worker change, or public endpoint.

### 34.1 — Server-visible first choice

- Use the verified first-screen `popular` + `ongoing` items already supplied by `HomeFeedRuntimeProvider` to render a PUBLIC provisional choice on the server, while personalized engine and idle chunk load.
- Candidate deduplication / public eligibility run on persisted metadata only. Do not guess remote content ratings; public preview does not claim personal similarity.
- Make `HomeTonightPick` statically importable and SSR-compatible; preserve real title/watch links, responsive poster pipeline, bookmark, focus and choice actions. Keep `SmartRecommendationFeed` dynamic/deferred.
- Clearly distinguish provisional content (`data-home-tonight=preview`, public copy) from personal rank (`ready`). Never send `home_section_view` / `recommendation_click` attribution for an unranked preview.
- A user-selected non-default mood still waits for its OWN ranking: never show a stale public pick labeled as a chosen mood. Existing responsive shape and pending/error states remain.
- Do not change `/api/recommendations`, server-side saved feed, Supabase RLS, artwork resolution, or DB indexes in this stage.

## 4. Release gates

1. `npm run perf34:check`: mounted via `prebuild`. Checks route sanitization, bounded metric values, 2% sampling, duplicate protection, app mount and server-first hero invariant.
2. `npm run home32:check`: current SSR and browser home fixture plus new real SSR hero/no-skeleton assertion, mood switch, bookmark, poster and click attribution tests.
3. Full prebuild, TypeScript, targeted lint and production Next build in GitHub Quality Gate.
4. Manual browser QA: guest, logged-in, no saved feed, existing watch history, Android 360/390/412px, desktop 1366/1920px, Telegram WebView, light/dark. On first visit verify server HTML contains real choice and image, not just a placeholder. Verify no image swap after a user has clicked and no repeated media requests; measure LCP and long tasks.
5. Canary for `field_web_vital`: rate no more than ~2% of browser visits * metrics, no dynamic paths, no sensitive metadata; no 429 traffic increase at API. Confirm downstream monitoring queries before claiming improvements.

## 5. Exit criteria / goals (NOT current measurements)

- Perceived above-the-fold content is meaningful without waiting for recommendation import or `requestIdleCallback`.
- No regression to client-side route transitions, personalized mood protection, allowed artworks or saved library actions.
- CWV p75 targets mobile: LCP <= 2.5 s, INP <= 200 ms, CLS <= 0.1. Performance goals require subsequent real-user measurements; this PR cannot claim them yet.
- Follow-up Patch 34.2: cache- and request-timing audit for search/catalog. Later 34.3 focuses on anime detail/watch, 34.4 tracker, 34.5 schedule/social, 34.6 media/JS and 34.7 production hardening.
- Hold merge/deployment for green CI and review. Vercel blocked status is unrelated; Railway is the active production origin.
