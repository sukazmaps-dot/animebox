# Patch 32.0 — Cinematic Home

## Задача и границы

Главная должна помогать выбрать аниме и вернуться к просмотру. Приоритет — полноценная новая композиция `/`, а не косметический слой поверх Patch 30–31. Фиолетовая идентичность AnimeBox, светлая тема и существующая навигация приложения сохраняются. Каталог, профиль, плеер, авторизация, платежи и серверные API не переписываются.

База: main после Patch 31.19, commit 435cd9e9a578b2ecaec271f721387d57563cd7a6. Отдельная ветка patch/32-0-cinematic-home. Результат проходит Quality Gate перед слиянием; rollback — revert одного merge commit.

## Референсы, просмотренные до реализации

* `Netflix Design System 2024 (Website ver.) 🎥 (Community)(1).zip`: HeroBanners.png, ContentBlocks.png, MoviePreview.png, Typography.png, Colors.png. Это community kit, а не официальная спецификация Netflix. Берём крупное изображение, текст слева, переход в фон, тесную связь Hero с полками и отсутствие панелей вокруг каждого ряда. Чужие изображения, логотипы и красная брендовая палитра не переносятся.
* `Wibuplex Anime Stream Platform UI Kit (Community)(1).zip`: Dark.png, Light.png. Мобильная плотность, читаемые названия и простые полки.
* `Animax - Anime Streaming App UI Kit (Preview)(1).zip`: лист превью и экраны приветствия. Полноценного комплекта экранов главной в архиве нет; не приписывать ему несуществующие решения.

## Выявленные проблемы текущей главной

1. Конкуренция первого экрана с правой колонкой, которая повторяет популярное и расписание.
2. Повторение метаданных Hero в отдельных desktop/mobile узлах и разрозненное управление ими через каскад.
3. Декоративные и рекламные поверхности между полками: настроение как самостоятельный большой блок, карточки навигации и длинные пояснения.
4. Шесть route CSS импортов, включая последовательные исправления геометрии. Новая композиция не должна зависеть от победы очередного глобального patch CSS.

Это выводы из кода и референсов, не результаты пользовательского исследования или замеров конверсии.

## Информационная архитектура

Порядок: Hero → продолжить просмотр (только при наличии истории) → персональные рекомендации и настроение → популярное/онгоинги → расписание → Watch Together → персональные сигналы/компактное сообщество → полезные ссылки и поддержка.

Правая колонка и четыре большие карточки быстрых переходов удаляются из композиции главной. Доступ к каталогу, расписанию, трекеру и комнатам остаётся в навигации и текстовых ссылках. Нет пустой полки продолжения у гостя. Персональное расписание остаётся условным и использует общий runtime. Рекомендации, их порядок, причины, обратная связь и undo сохраняются.

## Первый экран

* Desktop: одно изображение на ширину доступной области приложения, текст слева, изображение справа, затемнение слева и снизу. Без рамки и внешней тени панели. Высота ориентировочно 560–680 px; типографика 40–68 px с ограничением строк для длинных названий.
* Mobile ≤768 px: вертикальное изображение с существующей точкой фокуса; текст внизу, две кнопки высотой ≥44 px, компактная единая строка года/жанра/рейтинга. Высота адаптируется к viewport; длинный заголовок не перекрывает кнопки и пагинацию. Landscape проверяется отдельно.
* Заголовок — реальное название тайтла; короткий синопсис только если он есть. Никаких выдуманных логотипов или маркетинговых абзацев. Основное действие «Смотреть», второе «Подробнее».
* Текущая пагинация, свайп, пауза при фокусе, reduced motion и запрет автопереключения до взаимодействия остаются.
* Один responsive picture, прежние R2/srcset и ограниченная цепочка восстановления. Если есть только постер, он не растягивается в горизонтальную иллюстрацию.

## Полки и настроение

* Заголовки 20–28 px, минимум служебного текста и декоративных иконок. Вертикальный ритм 32–48 px, карточки без внешней панели вокруг ряда.
* Постеры сохраняют пропорцию 2:3: для всех тайтлов нет гарантированного качественного landscape-арта. Не превращать вертикальные постеры в растянутые баннеры ради копирования Netflix.
* Desktop: 5–6 читаемых карточек, стрелки с реальным disabled-состоянием. Mobile: около 2.3 карточки с видимым продолжением, горизонтальный свайп без горизонтального скролла всей страницы.
* Настроение — компактная горизонтальная группа radio chips с видимым выбранным состоянием. Все существующие варианты, клавиатурные стрелки/Home/End, aria-checked и статус обновления сохраняются. В компактном режиме не загружать декоративные иллюстрации.
* История: реальные эпизод, время возобновления, прогресс и атрибуция. Не заменять реальные данные декоративной заглушкой.
* Watch Together: короткий заголовок, одна понятная точка создания комнаты, открытые комнаты, корректные guest/error/empty состояния и прежний lifecycle polling.

## Архитектура и ограничения

Новые стили — CSS Modules рядом с компонентами. Новая главная получает отдельный namespace вместо legacy home-page/home-grid: старые исправления остаются доступными историческим fixtures, но не управляют новой геометрией. Не добавлять импорт глобального patch CSS в root layout. Не выполнять массовое удаление старых CSS, используемых вне главной, без отдельного аудита.

Сохраняются Server Component shell, ISR 900 секунд, metadata/canonical, общий HomeFeedRuntimeProvider и HomeScheduleRuntimeProvider. Персональные данные по-прежнему загружаются клиентом; не включать их в публичный ISR. Не добавлять зависимости, fetch, polling, новые серверные кеши, видео или iframe в Hero. Сохраняются оптимизации памяти/изображений 31.19, исправления доступности Supabase 31.15–31.16 и редактор 31.18.

## Приёмка и проверки

1. Независимые `home32:check` и `home32:browser`; существующий prebuild/Quality Gate, TypeScript, ESLint и production build.
2. Реальные React-компоненты в контролируемом browser fixture: 360, 390, 412, 768, 1024, 1366, 1920 px, светлая/тёмная темы, длинное название, отсутствие истории, история, смена настроения, пагинация и rail navigation. Отдельно landscape и poster-only fallback.
3. Нет overflow страницы, пересечений CTA/пагинации, невидимого заголовка, сломанных картинок, hydration ошибок; кнопки и radio ≥44 px; keyboard focus видим.
4. Существующие тесты media fallback, рекомендаций, истории и Watch Together остаются. Проверки прежнего порядка/импорта CSS меняются только там, где ТЗ намеренно заменяет композицию; функциональные ограничения не ослабляются.
5. Скриншоты desktop/mobile — для визуального ревью. Детерминированные fixtures не выдавать за замеры production LCP или реальную пользовательскую персонализацию.
6. Без стресс-тестов production и изменения пользовательских данных. Изменение RAM/egress/конверсии не заявлять без наблюдения после релиза.

## За пределами Patch 32.0

Полный редизайн поиска, карточки тайтла, плеера, профиля и общесайтовой навигации; замена рекомендательного алгоритма; глобальная очистка всех исторических CSS; платная инфраструктура. Это отдельные задачи после проверки новой главной.
