# ТЗ: подсказки расписания и устойчивость доставки постеров

## 1. Цель и границы патча

Устранить перекрытие соседних ссылок текстовыми подсказками расписания. Уменьшить повторную сетевую нагрузку от резервного прокси изображений и обеспечить ограниченное восстановление после временного отказа. Сохранить геометрию постеров, тему, ссылки на тайтлы, клавиатурную навигацию и ограничения безопасности.

Патч затрагивает TooltipLink, AnimeImage, точную политику кеширования /api/image и проверки этих компонентов. Он не меняет идентификаторы аниме, сбор расписания, рекомендации, авторизацию, БД, CSP или настройки Cloudflare. Изменение Worker требует отдельного доказательства и доступа к его развёртыванию: отказ origin-403 зарегистрирован, но причина отказа upstream этому каналу ещё не установлена.

## 2. Исходные доказательства

1. TooltipLink размещает панель в document.body, position:fixed, z-index:10000. Панель имеет pointer-events:auto и отменяет таймер закрытия при pointerenter. В результате длинный текст перехватывает наведение и клики по соседним карточкам. Открытие немедленное; mouse focus может удерживать панель после клика.
2. В запросах медиасервиса для Goblin, Psyren и Romelia зарегистрированы HTTP 204, X-AnimeBox-Media:source-soft-fail и X-AnimeBox-Origin-Error:origin-403. Тот же оригинал через /api/image возвращал HTTP 200 с растровым постером. Это доказательство отказа канала, а не отсутствия картинки.
3. При живой проверке текущего сайта первые 20 постеров расписания загрузились через /api/image с data-image-source-index=1. Это подтверждает работоспособность tiny fallback, но не исключает периодических отказов.
4. /api/image выставляет публичный TTL для успешных изображений. Однако публичный allowlist edge-cache-policy не содержит этот путь; proxy.ts перезаписывает ответы API на private,no-store. Сохранённый реальный ответ имеет именно эти заголовки.
5. AnimeImage после исчерпания цепочки делает одну повторную попытку с начала цепочки; она может снова ждать медиасервис, уже отказавший нескольким постерам. Изображения без URL вообще не имеют доступного удалённого кандидата и должны оставаться честной заглушкой.
6. Предупреждение CSP о запрете eval и предупреждения о размерах картинок не являются доказательством причины отказов постеров. CSP нельзя ослаблять для этого исправления.

## 3. Подсказки: функциональные требования

### 3.1 Мышь и соседние ссылки

- Открывать после 350 мс непрерывного наведения на ссылку. Быстрый проход через несколько карточек не показывает панель.
- Pointer типа touch не запускает hover; на телефоне нажатие сохраняет обычный переход по ссылке.
- Текстовая панель не содержит действий и не перехватывает указатель: pointer-events:none. Соседние ссылки под её прямоугольником остаются доступными для наведения и клика.
- При уходе с ссылки закрывать через 150 мс; наведение на другую ссылку закрывает предыдущую панель сразу, включая ожидающее открытие.
- В каждый момент допускается одна активная/ожидающая TooltipLink.
- При клике закрывать и отменять таймер. Mouse focus не должен удерживать подсказку после ухода указателя.
- Удаление компонента освобождает таймеры и обработчики.

### 3.2 Клавиатура и экран

- При focus-visible открыть сразу; использовать role=tooltip и aria-describedby только для открытой панели.
- При blur, Escape, прокрутке и изменении размера окна закрыть панель и отменить отложенное открытие.
- Escape не вызывает потерю фокуса и не переводит по ссылке.
- Сохранить Portal, динамическое размещение выше/ниже ссылки, отступ 12 px от краёв, ширину не более 320 px и перенос длинных слов.
- Не заменять раскрытие полного названия многоточием; маленькие колонки продолжают показывать компактный текст, полный текст остаётся в подсказке.

## 4. Прокси: кеширование и ошибки

- В публичный allowlist добавить только точный /api/image для GET/HEAD. /api/image-other и небезопасные методы не получают исключения.
- Успешный ответ получает единые Cache-Control, CDN-Cache-Control, Cloudflare-CDN-Cache-Control и Vercel-CDN-Cache-Control: browser TTL 7 дней, edge TTL 30 дней, SWR 30 дней.
- Маркер доставки успешного ответа остаётся proxy-v2 для совместимости диагностики.
- Отсутствующий/неподдерживаемый URL, локальный URL, запрещённый host, превышение лимитов и strict fallback ошибки получают no-store во всех слоях. Общий allowlist не должен превращать ошибку в кешируемую.
- Совместимая legacy SVG-заглушка без fallback=error сохраняет короткий TTL 15 секунд; strict=true возвращает HTTP 502 и позволяет браузеру продолжить цепочку.
- Сохранить allowlist внешних HTTPS host, проверки credentials/port/redirects, лимит 10 MB, upstream timeout 8 секунд и rate limit 600 запросов/мин/IP.
- Не кешировать персональные API и не менять защиту origin/CSRF.

## 5. Постеры: ограниченное восстановление

- Сохранить первоначальную цепочку источников и tiny-приоритет same-origin proxy. Не вводить параллельный fan-out и загрузку всей страницы eager.
- После полного исчерпания цепочки разрешить максимум две автоматические повторные попытки на набор URL.
- Первая повторная попытка после детерминированного jitter 20–45 секунд начинает с same-origin /api/image, если такой кандидат существует. Она не обязана ждать глобальный cooldown медиасервиса: этот серверный путь независим от отказавшего Worker.
- Вторая попытка может повторить исходную цепочку после cooldown медиасервисов; если блокировка продолжается, отложить её, не расходуя бюджет.
- Offline, скрытая вкладка и постер вне окна не расходуют попытку. Проверять возможность восстановления позднее с ограниченной частотой; событие online использует jitter 1–6 секунд.
- Отсутствие удалённых кандидатов не запускает бессмысленные retries.
- Смена набора источников сбрасывает бюджет; успешная загрузка отменяет pending retry; unmount отменяет таймер/online listener.
- Сохранить размеры img 400×600, размеры контейнеров, srcSet на первом media-кандидате и native lazy scheduling.
- Диагностика только DOM, без новых сетевых событий: data-image-retry-count, data-image-last-failure-stage и data-image-last-failure-reason. Стадия: media/proxy/origin/local; причина: network-or-decode/timeout. Не утверждать HTTP-код из img.onerror: браузер его не предоставляет.

## 6. Проверки и приёмка

| Сценарий | Ожидаемый результат |
|---|---|
| Быстро провести мышью через карточки | Подсказка не вспыхивает на каждой карточке |
| Остановиться на длинном названии | Полный текст появляется через 350 мс |
| Переместить указатель на соседнюю ссылку под панелью | Соседняя ссылка получает события и доступна для клика |
| Tab, Escape, scroll, resize | Фокус доступен; подсказка закрывается без перехода |
| Touch pointerenter | Hover не открывается |
| Media отказал, proxy здоров | Настоящий постер, без преждевременной заглушки |
| Все источники отказали, затем proxy восстановился | Первая повторная попытка обращается к proxy, постер восстанавливается |
| Offline/скрытая вкладка/вне viewport | Retry budget сохраняется |
| Постоянный отказ | Не больше двух автоматических повторных проходов |
| Смена тайтла/успех/unmount | Нет старого таймера, бюджет/диагностика корректны |
| GET успешного /api/image через proxy.ts | Публичные image cache headers не перезаписаны |
| GET ошибки /api/image и приватный API | no-store сохраняется |
| POST /api/image и похожий путь | Нет публичного исключения |

Автоматические тесты должны выполнять реальные компоненты и route handler с управляемыми таймерами/сетевыми отказами. Дополнительно обязательны TypeScript, ESLint изменённых файлов, существующие media/security/cache gates и полный NODE_ENV=production npm run build. Локальные проверки не заменяют проверку CDN после деплоя: итоговые cache headers на публичном домене проверяются после публикации. До этого нельзя заявлять о полном устранении origin-403.

## 7. Публикация и откат

Подготовить отдельную ветку и reviewable PR с этим ТЗ, причинами и результатами проверок. Откат — revert коммита патча; миграции и изменения секретов отсутствуют. Production deploy и повторный браузерный smoke фиксируются отдельным результатом после публикации.

## 8. Результат реализации и проверки

Реализованы разделы 3–5. Дополнительно исправлена повторная смена набора URL A → B → A: компонент больше не возвращается к старому терминальному fallback. Добавлена проверка реальных TooltipLink и AnimeImage через React renderer с управляемыми таймерами; выполняются реальные GET image route и proxy.ts с mocked upstream/rate limiter. Проверены hover delay, единственная панель, touch, mouse/keyboard focus, Escape, scroll/resize, offline, hidden/outside viewport, независимый proxy retry во время media cooldown, второй проход, предел попыток, успех, unmount и отсутствие URL.

Полный NODE_ENV=production npm run build завершился успешно, включая все prebuild gates и TypeScript. ESLint изменённых TypeScript/TSX файлов и git diff --check прошли. Старый тест image route обновлён для загрузки настоящего cache-policy helper; статический media gate проверяет конкретные TTL через общий helper, а не старую строку заголовка.

Ограничения: локальная проверка браузерного hit testing не выполнена — Chromium недоступен. Production CDN cache headers и реальную региональную доставку необходимо проверить после публикации. Патч не исправляет причину origin-403 внутри Cloudflare Worker; он обеспечивает независимое восстановление и сокращает повторную нагрузку. Watchdog native lazy остаётся прежним: этот патч не запускает timeout для ещё отложенного браузером запроса.
