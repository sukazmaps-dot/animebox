# Patch 31.9 — профиль как рабочая область Discord
Дата: 17 октября 2026. База: main / PR #251 / 4c680c55.
Статус: реализовано, локальные проверки пройдены; ожидает CI и ревью. Референсы: приложенные скриншоты Discord и AnimeBox.

## 1. Проблема и визуальная цель
После фазы 2 вкладки объединены правильно, но композиция осталась формой: центральные поля огромны, подписи 9–12 px, превью справа показывает только шапку, ниже него пустота. Референс устроен иначе: компактный инспектор слева, полноценная идентичность в центре, персональная доска справа. Перенести именно эту иерархию, сохранив стиль AnimeBox, фиолетовый акцент и существующие данные. Не копировать чужие логотипы, Nitro, игровые данные или фиктивную активность.

## 2. Что входит в патч
1. Перестроить рабочую область Profile, сохранив четыре назначения: Профиль, Оформление, Витрина, Награды.
2. Слева объединить навигацию и компактный инспектор: имя, био, аватар, коллекция рамок, баннер.
3. В центре показать полноценную карточку профиля, включая полный текст био, выбранную рамку, дату регистрации и действительный Premium-статус.
4. Справа показать персональную доску из уже существующей модели ProfileWidgetsData: любимые тайтлы, текущий просмотр, оценки, жанры и активность — только доступные и разрешённые блоки.
5. Добавить явные состояния загрузки, ошибки, пустой/скрытой витрины и действие перехода к её настройке.
6. Устранить зависимость полноэкранной геометрии редактора от контейнеров основной страницы.
7. Проверить историю/черновики и существующие строковые контракты; обновлять только ожидания, которые прямо меняет новый layout.

Не входят: схема БД, новые платежи, изменение публичного профиля, транспорт загрузки/сжатия фото, права Premium, миграции, переменные Cloudflare/Railway, полный редизайн встроенного Premium Studio.

## 3. Контракт данных и сохранения
- Источник состояния один: ProfileEditorWorkspace. Инспектор, центральное превью и диалог читают один draft.
- Не создавать копии username/bio/media/frame в новых компонентах.
- Существующие saveProfile, cancelChanges, useProfileEditorHistory, IndexedDB, восстановление файлов, account key, Ctrl+Z/redo/Ctrl+S и Compare сохраняются.
- Выбор рамки остаётся локальным до общего Save. GET leaderboard-rewards остаётся один на смонтированный Surface, включая StrictMode; события косметики могут обновить инвентарь.
- Коллекция рамок раскрывается локально, без запроса при каждом раскрытии.
- Витрина использует существующий GET profile-widgets и общий cache состояния showcase. Разрешить загрузку в Profile, повторно использовать результат при переходе в Витрину. Не загружать витрину при каждом редактировании имени/скролле.
- Параллельные эффекты StrictMode и переход Profile→Showcase используют один in-flight Promise; результаты предыдущего аккаунта не попадают в новый workspace.
- Витрина сохраняется существующим ProfileWidgetEditor отдельно. Центральный Profile Save не присваивает себе её изменения. После onSaved правая доска получает актуальные данные.
- Compare показывает сохранённую идентичность/рамку/цвет и сохранённые Premium-настройки, сохраняя текущий draft.
- Клики в превью выбирают настройки без открытия клавиатуры, файлового picker или автоматического сохранения.

## 4. Desktop layout
### 1180–1920 px
- Контент шириной не более 1400 px, центрирован; наружная оболочка помещается в viewport.
- Три колонки: инспектор около 280–300 px; профиль с достаточной шириной для полного имени и био; остальная доступная ширина — доска.
- Навигация компактна над инспектором, а не отдельная четвёртая колонка.
- Карточка профиля и доска начинаются на одной линии под общей шапкой, закрепляются с безопасным отступом.
- Инспектор использует обычную прокрутку корня. Не создавать отдельные колёсные ловушки в колонках.
- Шапка содержит название, доступное закрытие и один статус сохранения.
- Блок инструментов истории остаётся в инспекторе, кнопки минимум 44 px.
- Редактируемые секции разделяются линиями; убрать большие декоративные панели, радиальные подсветки и массивные тени внутри инспектора.
- Поля и основной текст 14–16 px; вспомогательный текст 12–13 px; заголовки 15–18 px. Не масштабировать интерфейс transform:scale.
- Био в инспекторе компактное, допускает вертикальный resize. В центральной карточке — полный текст с переносом длинных слов.
- Кнопки медиа компактны и не превращаются в центральные широкие CTA. Цвета перестраиваются по ширине инспектора через container query.
- Коллекция рамок по умолчанию свёрнута. Заголовок показывает назначение/количество; все фильтры и исходные действия доступны после раскрытия.
- Переход к якорю frame раскрывает коллекцию до вычисления координат.

### 900–1179 px
- Две колонки: инспектор слева, профиль и доска справа вертикально.
- Верхние четыре раздела остаются горизонтальными; чипы учитывают высоту закреплённой навигации.
- Доска не сжимается в третью непригодную колонку.

- Витрина и Награды получают основную доступную ширину; центральное превью Profile и доска там скрыты, не оставляют пустую зарезервированную колонку.
- ProfileDirectEditSurface остаётся смонтированным, скрытым через hidden при уходе из Profile.

## 6. Геометрия и обрезанный левый край
На скриншоте виден обрезанный левый край. Точная первичная причина требует воспроизведения: нельзя объявлять виновником zoom без проверки.
- Публичная страница имеет app-shell с боковым margin и route-контейнеры, которые могут создавать containing block.
- Редактор вынести в портал к document.body, сохранив React context. Его fixed-корень должен иметь явные left/right, width:100%, min-width:0, max-width:none, margin:0 и box-sizing:border-box.
- Серверный HTML и первый клиентский render портала согласованы; подключать портал после hydration, без чтения document на сервере.
- Поля не получают фокус из-за mount. При смене аккаунта прежнее состояние не наследуется.
- Регрессионный тест должен создавать смещённого/трансформированного предка и доказывать, что root.left=0, root.right=viewport, шапка и левая колонка внутри viewport.
- Измерять элементы и scrollWidth, а не только скрывать overflow.

### Точные изменения адаптивных контрактов
В scripts/profile-editor-responsive-smoke.cjs:
```js
if(width>=1180&&tab==='style')assert(geometry.nav.right<=geometry.settings.left+1,label+' compact desktop rail');
if(width>=1180&&tab==='profile')assert(geometry.settings.width>=260&&geometry.settings.width<=320,label+' compact inspector width');
if(width>=1440&&tab==='style')assert(geometry.settings.width>500,label+' use wide screen');
```
Это заменяет прежнюю проверку меню слева от широкой формы и общий порог 500 px. В Profile навигация над инспектором той же колонки; в Style остаётся отдельное меню и широкая область. Проверки overflow, sticky, дока, HEX и IndexedDB сохранены.

Статическая fixture передаёт full:true и тестовую дату, включает область profile-editor-v33__board. Реальный browser smoke проверяет портал со смещённым предком, обе темы, три колонки, полный диалог, frame details, длинные данные и короткую высоту. Якоря выбираются по data-profile-anchor-link, независимо от перевода.

В package.json:
```json
"editor-workspace:check": "node tests/profile-editor-workspace.cjs && node tests/profile-editor-navigation.cjs && node tests/profile-editor-discord-workspace.cjs"
```
В Quality Gate внешние инструменты дополнены esbuild@0.28.2; шаг редактора получает ESBUILD_MODULE_PATH и запускает npm run editor-unified:browser. Runtime-зависимости сайта не расширены.
