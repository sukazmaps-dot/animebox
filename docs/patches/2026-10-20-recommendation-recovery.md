# ТЗ: восстановление рекомендаций и доступность загруженного контента

База: main, 2221bb4f. Ветка: fix/recommendation-rail-recovery.
Первый выпуск из серии «Ленты → Постеры → Проверка надёжности».

## Цель

Устранить подтверждённые остановки ленты: пустой старт, недоступные карточки
последней страницы API и пропуски после скрытия тайтла. Сохранить существующий
добор по реальной ширине контейнера, стабильность рядов и ограничение запросов.
Этот выпуск не заявляет достигнутые 99%: показатель требует production-измерений.

## Диагностика актуального main

1. buildRecommendationRailLayout возвращает пустой список рядов при пустых
   исходных рекомендациях даже при hasMore=true. Фоновый prefetch сохраняет
   страницу в кэше, но без ряда никто не потребляет её и не показывает retry.
   Старый lifecycle-тест подменял layout и всегда создавал два ряда.
2. Глобальный hasMore=false блокирует ensureRailDepth и стрелку подгрузки,
   даже если filtered содержит ещё подходящие, не показанные карточки.
   Конец API ошибочно означает конец уже загруженного локального пула.
3. После «Не интересно» bootstrap остаётся помеченным как выполненный для
   прежней цели. Без новой геометрии или взаимодействия вакансия не добирается.

## Функциональные требования

### Пустой старт

- Пока источник допускает продолжение, создать обычный ряд «Ещё для тебя» даже
  при пустом пуле. Использовать его существующие skeleton, bootstrap и retry.
- Не создавать фиктивные карточки и не менять правила ранжирования.
- Пустой окончательный ответ завершает загрузку существующим empty state.
- Ошибка оставляет видимый ручной повтор, resize не повторяет ошибочный запрос.

### Локальная и сетевая пагинация

- Различать доступность следующей API-страницы и доступность карточек в памяти.
- При конце API разрешать раскрытие локального пула с прежним размером порции.
- В первую очередь использовать загруженные кандидаты и расширять лимит ряда.
- Учитывать карточки, уже закреплённые за этим рядом за пределами его лимита.
- Не брать карточки другого ряда и не показывать один anime.id дважды.
- Сохранять строгие критерии тематических рядов, включая продолжения франшиз.
- Локальное раскрытие не делает новых запросов после hasMore=false.
- После исчерпания локального пула прекращать подгрузку, не оставляя вечный цикл.

### Скрытие карточки

- Сбросить отметку bootstrap и локальную паузу только у ряда скрытого тайтла.
- При наличии вакансии снова применить прежнюю цель заполнения 5–12 карточек.
- Скрытый тайтл не возвращается при доборе; другие ряды не перезапускаются.
- Ошибки API по-прежнему требуют явного «Повторить».

### Сохранённые ограничения

- Общие cursor, cache и in-flight запросы; никакого API-запроса на каждый ряд.
- Bootstrap: максимум 3 страницы для пустого ряда, 2 для непустого.
- Обычная пагинация: существующий предел 6 просмотренных страниц.
- Предзагрузка рядом с viewport, interaction gate для дальнейшей прокрутки.
- Не менять scrollLeft, порядок видимых карточек и поведение touch momentum.
- Виртуализация остаётся с лимитом 36 DOM-карточек на ряд.
- Смена настроения и unmount изолируют устаревшие результаты.

## Границы выпуска

Только frontend-поведение лент, layout на пустом входе, regression-тесты и ТЗ.
Без миграций, изменений API-контракта, новых глобальных CSS, Worker/R2,
изменений алгоритма вкусового ранжирования или плеера.
Резерв постеров, разрешения изображений и R2-кэш входят во второй патч.

## Приёмка

- Реальный layout и реальный Feed восстанавливаются с items=[]; не только mock.
- Все 20 карточек окончательной API-страницы доступны через конечную локальную
  пагинацию без повторного fetch, дублей и зависания.
- Терминальная пустая выдача даёт empty state; ошибка пустого старта — retry.
- Скрытие карточки запускает добор при той же ширине без свайпа/resize.
- Существующие тесты desktop fill, shared requests, resize budget, offscreen
  rows, cancellation, session ownership и momentum продолжают проходить.
- TypeScript, targeted ESLint, полный prebuild и production build.
- Production-доступность и реальный процент успешных загрузок проверяются
  отдельно после выпуска; локальные fixtures их не доказывают.

## Откат

Revert коммита этой ветки. Не откатывать main целиком или предыдущие UI-фиксы.
