# AnimeBox — Patch 32.0: Cinematic Home · release-ready technical specification

**Статус:** implementation branch `patch/32-0-cinematic-home`, PR #268, базовый production commit `435cd9e` (Patch 31.19). Этот документ задаёт подробные критерии приёмки, а не объявляет релиз завершённым.

## 0. Цель и измеримые результаты

- Заменить визуально разрозненную домашнюю страницу единым стриминговым сценарием: выбрать тайтл → смотреть, либо продолжить начатый.
- Первая видимая область: один кинематографичный Hero, основное и вторичное действие, читаемые достоверные метаданные.
- Следом персональный прогресс при его наличии, рекомендации, популярное и онгоинги, расписание, совместный просмотр, служебные и community-разделы.
- Полностью исключить появление горизонтального document overflow на ширинах 320–3840 CSS px, включая 320, 360, 390, 412, 768, 1024, 1366, 1920.
- Исключить перекрытие текста кнопками, пагинацией и всплывающими панелями.
- Не добавлять backend-запросов, интервалов/polling, серверных кешей, постоянного прогрева изображений или автоматического видео.
- Сохранить SEO и ISR 900 с, публичную/персональную границу данных; не выдавать искусственные fixtures за наблюдения production.

## 1. Граница изменений

**Можно менять:** `app/page.tsx`, компоненты `Home*` и `components/home/*`, их локальные CSS Modules, точечно существующие CSS владельца recommendation actions, тестовые скрипты и workflow, документацию.

**Нельзя менять без отдельного патча:** страницы поиска/тайтла/эпизода/профиля, рабочий Kodik/iframe player, API авторизации, Supabase RLS/migrations, Telegram webhook, платежи, функции Premium, DNS, Railway ресурсы, серверное кеширование 31.19.

**Не допускать:** новых глобальных CSS импортов в `app/layout.tsx`; очередной слой `!important`; замену реальной логики рекомендаций на fixture; удаление fallback изображений; отключение тестов для получения зелёной CI.

## 2. Информационная архитектура

1. **Hero:** до первой полки; не оборачивается в карточку, не дублируется в desktop/right rail.
2. **Continue:** только когда есть прогресс; реальный тайтл, эпизод, время и переход к восстановлению просмотра. Гость без истории не получает пустой контейнер.
3. **Discovery:** единый provider рекомендаций, пять mood radio options, ясный выбранный статус, карточки действий.
4. **Catalog:** популярное и онгоинги с заголовками и горизонтальной прокруткой.
5. **Schedule:** календарные данные из прежнего runtime и прежние состояния загрузки/ошибки.
6. **Watch Together:** существующая логика создания и просмотра публичных комнат, без дополнительных сетевых циклов.
7. **Retention/community:** сохранять lazy-load и семантику доступа.
8. **Navigation/support:** компактные текстовые ссылки и один блок поддержки, без четырёх больших навигационных плиток.

## 3. Hero на desktop (769+ px)

- Высота 560–680 px, адаптированная к реальной доступной ширине контейнера; без рамки, box shadow и декоративного соседнего rail.
- Арт закреплён справа с затемнением слева и внизу; заголовок/факты/описание/CTA логически объединены слева.
- Надписи: реальный локализованный заголовок, год/тип/серии/рейтинг только при наличии достоверных значений; синопсис очистить от HTML и сократить без обрыва в слове.
- Заголовок не более 3 видимых строк, описание не более 3; длинные варианты не ломают layout; рабочий перенос длинных непрерывных слов.
- Primary CTA `Смотреть` ведёт по существующему маршруту просмотра, Secondary `Подробнее` — к странице тайтла. Не допускать двух одинаковых переходов.
- Если источники содержат только вертикальный постер, сохранять `contain` и безопасную область справа; горизонтальный `cover` запрещён.
- Пагинация должна оставаться внутри Hero, не заслонять CTA, не выходить за 100% ширины и показывать текущий индекс.

## 4. Hero на mobile (до 768 px)

- Один responsive `picture`: предпочтение отдельному mobileHeroImage; затем качественному постеру; прежняя ограниченная цепочка восстановления при ошибках edge/origin.
- Изображение должно покрывать фон только в режиме mobile, когда это допустимо для композиции; вертикальная точка фокуса задаётся существующим `mobileHeroPosition`.
- Заголовок и CTA расположены поверх нижнего scrim, контрастны при ярком изображении; метаданные могут переноситься без наезда на кнопки.
- CTA минимум 44×44 px (желательно 48 px высоты); соседние кнопки не сливаются и не выходят за границы на 320 px.
- Пагинация остаётся внутри Hero, без перекрытия действий на viewport 320×700, 360×800, 390×844, 412×915, 768×1024 и landscape 844×390.
- Не допускать обрезания названия, интерактивов и фоновой картинки при browser zoom и системном размере шрифта.
- Не автопереключать слайд до пользовательского взаимодействия; учитывать свайп/hover/focus и reduced motion.

## 5. Постеры и горизонтальные полки

- Пропорция `2:3`, единые радиусы 6 px, единая система заголовков и метаданных; не обрамлять каждую полку тяжёлой панелью.
- Desktop: при доступном месте показывать примерно 5 карточек, от 1600 px — 6; учитывать реальный page-container.
- Mobile: примерно 2.3 карточки видны, следующий постер выглядывает, скролл лишь в рамках viewport полки.
- Реальное disabled-состояние стрелок; кнопки 44 px; scroll-snap не препятствует touch drag.
- Страница не получает horizontal scroll; изображения lazy-load за пределами первого экрана; не дублировать медиа или запросы.
- Отсутствие изображения/названия/рейтинга обрабатывается из прежних fallback, без пустых DOM-карточек.

## 6. Настроение и рекомендации

- Сохранить все пять вариантов mood и существующий алгоритм персонализации/ранжирования.
- Mood — compact chips с `role=radiogroup`, радио 44px+, `aria-checked`, работающими Arrow/Home/End и видимым focus.
- Не загружать декоративный mood artwork в компактной строке.
- Сохранить `like-more`, `watched`, dismiss, reason/taste feedback, undo, optimistic state, error/retry, синхронизацию библиотеки.
- Native dialog: фокус, Escape, раскрытие/закрытие и touch targets проверять; диалог не должен быть под clipping полки.
- Клик по постеру и клики по действиям не должны неожиданно инициировать одно и то же событие.

## 7. Цвет и темы

- Основная палитра тёмная, нейтральный фон и фиолетовый акцент; использовать существующие theme variables вместо фиксированной тёмной заливки всей страницы.
- Light theme: видимые заголовки, контрастная мета, читаемые chips, границы, состояние disabled.
- Текст поверх артворка всегда контрастный независимо от theme. Проверить реальную геометрию текста и графические контрасты.
- CSS Modules — единственный владелец новой геометрии Hero и Shell; старые class namespaces на новую страницу не возвращать.

## 8. Производительность / Railway

- Рендерить Server Component оболочку и исходные публичные списки без личных данных в ISR-ответе.
- Не изменять `revalidate = 900`, canonical, OG/Twitter metadata, существующий API contract.
- Не добавлять автоплей фоновых клипов, timers или polling; применять existing image CDN variants.
- Сохранить memory bounds и image concurrency из Patch 31.19. Исключить параллельную загрузку невидимых full-res изображений.
- Замеры CPU, RSS, egress и LCP после релиза сравнивать с одинаковыми временными окнами; до измерений не утверждать экономию ресурсов или рост конверсии.
- Не создавать новую Railway службу или отдельный environment для этого frontend-релиза.

## 9. Автоматизированная матрица качества

1. `npm run home32:check`: static ownership / структура / защитные проверки.
2. `npm run home32:browser`: production fixture с реальными React shell/providers, не shallow моками компонентов.
3. Viewports: 360, 390, 412, 768, 1024, 1366, 1920 в светлой/тёмной теме; дополнительный 320 и landscape как стресс-кейсы.
4. Hero: обычный арт, длинный заголовок, poster-only, edge failure/origin fallback, индекс первого/последнего слайда.
5. Рекомендации: реальный ранжированный результат, mood keyboard, lazy load, feedback, undo.
6. History: guest пустая/непустая, точная серия и time progress, нет data leak.
7. Rail navigation: кнопки, свайпы, конец полки, фокус и отсутствие overflow.
8. Console: нет hydration errors, uncaught exceptions, неожиданных запросов production.
9. `npm run patch31-4:check`, `npm run patch31-4:browser` — проверка артворка и recovery.
10. `npm run hero-pagination:browser` — *legacy fixture*, изолированно загружающий прежний CSS cascade. Новую реальную композицию тестирует `home32:browser`. Не использовать old fixture как критерий расположения cinematic headline.
11. TypeScript `npx tsc --noEmit`, ESLint целевых файлов, `npm run prebuild`, `npm run build`, полный Quality Gate PR.
12. Фотоартефакты должны включать mobile и desktop в двух темах, geometry.json, poster-only и landscape; ручной визуальный review не заменять одной формальной проверкой координат.

**Patch 32.0 готов** только когда критические desktop/mobile UX критерии выполнены, последний full CI success, визуальные артефакты просмотрены, PR слит и Railway показал работающий release SHA. Пока любой из этих пунктов неизвестен, статус — **in review**, а не `deployed`.
