# Patch 30.8 — Мобильная витрина AnimeBox

Дата: 16 октября 2026. База: main `07d2aefe4195b8baa3dff71193d92c6082f78b8f`.
Ветка: `patch-30-8-mobile-hero-art`.

## 1. Проблема и результат

На приложенном скриншоте главной страницы постер Фрирен занимает узкую
область справа, слева остаётся тёмная пустота. Название и действия стоят
ниже изображения. Получается большая карточка каталога вместо витрины.

Результат: единая композиция на телефоне. Арт заполняет весь hero,
персонажи находятся преимущественно в верхней части, название и действия
расположены поверх плавно затемнённой нижней части. Следующий блок
появляется раньше благодаря устранению отдельного отступа под постер.

## 2. Проверенная причина в коде

- `HomeHeroCarousel.tsx`: уже используется один responsive picture/img.
- `getMobileHeroAttempts`: mobileHeroImage выбирается после coverImage.
- `app/patch30-0-home-streaming.css`: width min(42%, 200px), right 16px,
  top 18px, aspect-ratio 2:3, отдельный border-radius 12px.
- `app/patch29-1-home-mobile.css`: верхний padding до 345px, специально
  резервирующий место для отдельного постера, max-width заголовка 80%.
- Более ранние глобальные стили также задают hero размеры, opacity и blur.
  Их фактический итог проверяется в браузере со всем каскадом импортов.
- Тест пагинации закрепляет старую модель «заголовок ниже постера».
  Этот контракт заменяется проверкой нового расположения, остальные
  требования к фокусу, контрасту и целям нажатия сохраняются.

## 3. Границы

Входит: hero главной при ширине до 768px, выбор изображения, его точка
кадрирования, компактная строка достоверных фактов, действия, пагинация,
стык с продолжением просмотра, тесты и документация.

Десктоп сохраняет свой баннер и существующий responsive pipeline.
Карточки каталога, страница тайтла, плеер, авторизация, история, рекомендации,
SEO/ISR и база данных не меняют поведение. Нет новых зависимостей приложения.
Нет массового удаления старых CSS-файлов или нового глобального patch CSS.

## 4. Источники изображений

Мобильный порядок: curated mobileHeroImage → coverImage.extraLarge →
coverImage.large → image.original → image.large → image.medium → bannerImage.
Пустые/невалидные/повторяющиеся URL исключает существующий нормализатор.
Для первого источника сохраняются responsive edge-варианты и прямой origin;
при ошибке изображение переходит по конечной цепочке восстановления.
После исчерпания источников остаются градиент, заголовок и рабочие действия.

Отдельный арт должен быть официальным/предоставленным изображением нужного
тайтла. Этот патч не выдумывает наличие таких материалов и не подменяет
все постеры случайными картинками. При отсутствии curated-арта качественный
постер занимает всю площадь фона, а не отдельный прямоугольник справа.

## 5. Точка кадрирования

В Anime добавляется optional mobileHeroPosition {x, y} в процентах.
Оси ограничены диапазоном 0–100. Некорректное/неполное значение даёт
безопасный default 50% 20%. Значение применяется исключительно к мобильному
изображению через CSS custom property; desktop object-position прежний.
Это позволяет поставщику данных задавать арт и положение без CSS на тайтл.
Заполнение пропущенных метаданных сохраняет согласованную пару арт/позиция:
нельзя переносить координаты fallback-арта на другой primary-арт.
Административный редактор и миграция для хранения настроек в БД не входят.

## 6. Геометрия

- picture и img покрывают hero целиком: inset 0, width/height 100%.
- object-fit cover, без вытягивания пропорций и отдельного радиуса постера.
- Базовая минимальная высота мобильного hero: clamp(380px, 108vw, 460px).
- Контент остаётся в потоке, поэтому при увеличении текста блок растёт.
- Верхнее безопасное поле контента 150px; нижнее 64px под пагинацию.
- Горизонтальные поля 16px, на ширине до 390px — 14px.
- Заголовок занимает доступную ширину, максимум две строки, с переносом
  длинных слов. Полное название доступно через title и страницу тайтла.
- Отдельный размер шрифта для длинных названий остаётся.
- На низком landscape-экране до 768px min-height сокращается до 320px,
  поле над текстом — до 96px; контент не обрезается фиксированной высотой.
- Поворот телефона 769–1100px сохраняет существующий landscape-layout.

## 7. Свет и читаемость

Верхняя часть арта остаётся насыщенной: opacity 1, без blur/параллакса.
Нижний scrim усиливается к тексту; текст на изображении белый в обеих темах.
Фоновая поверхность самого hero остаётся темозависимой для ошибки медиа.
У кнопки Подробнее собственная тёмная поверхность и светлая граница.
Кнопки и пагинация не зависят от яркости исходного арта.
Никаких фальшивых логотипов, рейтингов и возрастных ограничений.

## 8. Содержание

После названия — одна компактная строка: год, первый локализованный жанр,
рейтинг. Каждый факт выводится только при валидных данных.
Рейтинг использует общий normalizedAnimeScore, 0 и отсутствующее значение
не показываются. Год должен быть целым 1900–2100. Жанр локализуется общей
таксономией, неизвестное название сохраняется; длинное обрезается.
Разделители появляются только между реально существующими фактами.
Строка мобильная, не перестраивает десктопную витрину.

## 9. Действия и навигация

Смотреть сохраняет animeWatchHref, Подробнее — animeHref.
Основная кнопка шире вторичной; обе имеют высоту не менее 44px.
Focus-visible видим; текст не выходит за пределы цели нажатия.
Мобильная третья кнопка совместного просмотра остаётся скрытой.
Свайп, вертикальная прокрутка, подавление клика после свайпа, пауза при
фокусе и выбор слайда сохраняются. Пять позиций доступны клавиатурой.
Пагинация остаётся снизу на устойчивой поверхности; цели 44×44px,
активный индикатор 24px, остальные различимы с контрастом не ниже 3:1.

## 10. Продолжение просмотра

Существующий HomeContinueWatching и его данные используются повторно.
Карточка остаётся компактной с постером, названием, серией/временем,
прогрессом при известных данных и одной стрелкой. Контейнер мобильной
ленты не должен выглядеть внешней таблицей с двойными разделителями.
Не менять resume URL, аналитику, историю, процент просмотренных серий.

## 11. Производительность и стабильность

Один picture и один img для выбранного слайда; не загружать все слайды.
Мобильный sizes соответствует полной ширине: calc(100vw - 32px),
а не устаревшим 42vw. Edge srcset ограничен существующим preset large.
Нет безусловного preload двух версий, базовая SSR-картинка детерминирована.
Автопереключение до взаимодействия и reduced-motion не меняются.
Высота не зависит от загрузки/ошибки изображения. Смена источника одного
слайда не должна менять расположение контента; более длинный текст может
увеличить блок при пользовательском масштабировании.

## 13. Матрица проверок

Браузер: 320×700, 360×800, 375×812, 390×844, 412×915, 430×932,
600×900, 768×1024, 844×390, 1024×520, 1440×900, 1920×1080;

Обязательные сценарии: длинное название, отсутствие фактов, неизвестный

## 14. Критерии приёмки

- На 360/390/412px арт покрывает hero по обеим осям с точностью 2px.
- Заголовок находится внутри нижней части арта, а не под отдельным постером.
- Все действия и пагинация внутри hero, между ними есть свободное место.
- Нет горизонтального overflow страницы, перекрытых/невидимых кнопок.
- При наличии mobileHeroImage браузер выбирает именно его на телефоне.
- На desktop браузер выбирает bannerImage, композиция не изменена.
- При потере всех изображений остаются читаемые название и обе ссылки.
- Целевые тесты, существующий prebuild и production build проходят.
- Результат визуально проверен по снимкам браузера; если браузер недоступен,
  это явно фиксируется и не подменяется заявлением о визуальной проверке.

## 16. Реализация и локальная приёмка

Реализованы полноразмерный арт, приоритет mobileHeroImage, focal point,
достоверные мобильные факты, компактная геометрия, исправление скруглений
и внешних разделителей продолжения просмотра. Изменены существующие
route CSS и CSS module; новых глобальных файлов стилей нет.

- 72 проверки пагинации: обе темы, 12 экранов, 3 выбранные позиции.
- 24 hydrated-сценария настоящего Hero/Rail/ContinueWatching, включая
  360/390/412px, 2K/4K, реальное переключение длинного названия.
- 4 сценария отказа медиа: edge, ultra-wide origin, все источники.
- SSR настоящего Carousel: пустые/невалидные факты, неизвестный жанр,
  единственный img, curated source и ссылки без изображения.
- Проверены координаты и согласованность слияния метаданных.
- ESLint, TypeScript, полный prebuild и production build прошли.

Браузерные снимки используют детерминированную тестовую иллюстрацию,
чтобы проверять композицию независимо от внешнего CDN. Отдельный новый
официальный арт Фрирен в production-данные этим патчем не добавлен.
Локальная сборка не имеет production service-role secret; использует
предусмотренный fallback при недоступности внешних источников данных.
