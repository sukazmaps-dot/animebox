# Repository Cleanup — CSS Ownership / Phase 1

**Дата:** 19.10.2026  
**Ветка:** `refactor/css-ownership-phase-1`  
**База:** `main` (`b8d47636`)  
**Тип:** структурный рефакторинг, без изменений runtime и API

## 1. Предпосылки

AnimeBox работает на Next.js App Router, React 19 и TypeScript, использует Supabase, Cloudflare, Railway и Telegram Mini App. В дереве `main` есть 124 CSS-файла в `app/`; у 63 из них в имени присутствует `patch`. `app/layout.tsx` напрямую импортирует 76 глобальных CSS-файлов. Проверка `css-cascade-ownership-check.cjs` закрепляет верхний лимит 76 и часть порядка каскада.

Названия файлов напоминают историю правок, а не карту ответственности за интерфейс. Однако глобальные CSS содержат перекрывающиеся правила и завязаны на тесты с фиксированными путями. Автоматически переименовывать/объединять десятки файлов нельзя.

## 2. Цели патча

1. Начать переход от файлов по номерам релизов к именам по смыслу и владельцу стилей.
2. Не допустить визуальных и функциональных изменений: селекторы, декларации, порядок правил и @media остаются прежними.
3. Обновить все исполняемые ссылки на перемещённые CSS.
4. Добавить статический контроль существования каждого глобального CSS-импорта, дублей и позиции критических стилей.
5. Зафиксировать методику последующих безопасных этапов CSS-консолидации.

## 5. Строгие запреты

- Не менять CSS-декларации, селекторы, значения переменных, брейкпоинты и порядок правил.
- Не добавлять новое `!important`, новые глобальные CSS и зависимости.
- Не менять runtime код, backend, API, Supabase RLS/SQL, пути роутов, SEO, плеер, auth и Telegram.
- Не трогать `patch-32-2-smart-r2-and-rail-fill` и другие открытые PR.
- Не удалять исторические документы и миграции ради эстетики.
- Не сливать PR и не выполнять деплой без ревью и успешного CI.

## 6. Проверки до публикации PR

1. Сравнение исходных CSS после удаления *только комментариев*: все оставшиеся байты/правила должны быть идентичны.
2. Убедиться, что переносимые файлы не содержат относительных `url(...)` и `@import`.
3. Проверить, что app/layout.tsx содержит ровно 76 CSS-импортов.
4. Поиск исполняемых ссылок на старые пути: все тесты и импорты обновлены; архивные ссылки не считаются runtime-зависимостью.
5. Провести ревью diff по каждому изменённому файлу, запретить неожиданные участки.

## 7. Release Quality Gate

В CI обязательно прогнать:
- `npm run visual:check`;
- `npm run mobile-shell:check`;
- `npm run css-cascade:check`;
- `npm run css-route-scope:check`;
- `npx tsc --noEmit` и ESLint;
- полный `npm run prebuild` и `npm run build`;
- существующий GitHub Actions Quality Gate.

Браузерная матрица после изменений: 360, 390, 412, 768, 1366, 1920 px; обе темы; главная, модальные окна регистрации, пустые состояния трекера, настройки уведомлений, страница тайтла и просмотра. Отдельно `prefers-reduced-motion`, focus-visible и режим Telegram Mini App.

Успешные статические тесты не заменяют browser QA, если появились регрессии в DOM/cascade.

## 8. Acceptance criteria

- Оба новых пути существуют, оба старых пути удалены.
- Ни одна CSS-декларация не изменилась.
- Все глобальные стили импортируются в прежнем порядке (76 импортов).
- Все встроенные проверки работают и не ослаблены.
- GitHub Actions Quality Gate завершился успешно на HEAD PR.
- PR имеет только ожидаемые файлы и остаётся draft до ревью; production без изменений.

## 9. План отката

Пока PR не слит — закрыть PR/удалить ветку. Если обнаружен баг после merge — revert конкретного commit, без SQL или инфраструктурных изменений. Никаких force push в main.

**Phase 5 — Scripts & Docs.** Нормализовать имена тестов/скриптов, каталогизировать документацию, не переписывая миграции и не ломая package.json/prebuild.

Каждая фаза требует отдельного PR, собственного diff и успешного Quality Gate.
