# Patch 31.20 — проверка ограничений памяти Railway

**Статус:** код и проверка добавляются в release-ветку; production-результат ещё не подтверждён.

## Цель

Снизить риск роста RSS и OOM из-за фоновых проверок доступности каталога и незавершённых запросов. Работать в рамках текущего стека AnimeBox: без новых сервисов, Redis и изменений схемы БД.

## Исходные данные

В предыдущих наблюдениях Railway фиксировались средняя RAM около 691 MB, текущее значение около 1.18 GB и пик около 1.94 GB. Это историческая точка отсчёта, а не гарантированное текущее состояние. Цель 100–200 MB пока не подтверждена измерениями.

## Изменения

1. Сохранить лимит четырёх активных проверок провайдеров, очередь не более 16 задач и тайм-аут ожидания 8 секунд.
2. Сохранить предел 32 разных незавершённых чтений реестра. При превышении не запускать дополнительный запрос к БД; использовать только ранее проверенные снимки и помечать результат как degraded/unhealthy.
3. Ограничить размер одного фонового batch двадцатью элементами — суммой активных и ожидающих слотов. Большая выборка продолжит обрабатываться следующими проходами, а не создаст очередь сверх бюджета.
4. Считать обновлёнными только результаты, которые реально вернули запись; null не должен повышать метрику успешной обработки.
5. Добавить изолированный синтетический регрессионный тест без сетевых запросов к production, пользовательских данных и записей в реальные сервисы.

## Критерии приёмки

- 33 параллельных уникальных чтения не открывают больше 32 запросов к реестру.
- При одновременном запросе большого количества разных тайтлов активно не выполняется больше четырёх внешних проверок; очередь ограничена шестнадцатью ожиданиями.
- Фоновый batch не обрабатывает больше двадцати тайтлов за один проход; метрика refreshed не считает null успешным обновлением.
- Проходят npm run railway-cost:check, общий Quality Gate и production build.
- Нет изменений SQL/миграций, секретов или инфраструктурных зависимостей.

## Проверка production

После успешной сборки и запуска точного SHA в Railway сравнить RSS/peak RAM, CPU, throughput, 5xx и OOM до/после на сопоставимой нагрузке. Локальный scripts/railway-memory-drill.cjs — синтетическая проверка передачи изображений, а не замена измерению полного production-процесса. Числовую цель по RAM объявлять достигнутой только по наблюдаемым метрикам Railway.

## Внешний блокер

Сбой BuildKit с ошибкой монтирования overlay и invalid argument возникает до обычной сборки приложения. Его нужно перепроверить повторной сборкой или диагностировать как инфраструктурный сбой Railway; изменение прикладного кода само по себе не доказывает устранение этой ошибки.
