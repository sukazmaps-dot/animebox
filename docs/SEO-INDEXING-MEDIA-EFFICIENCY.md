# ТЗ: стабильная индексация публичного каталога и оптимизация постеров

Дата: 11 октября 2026, Asia/Qyzylorda. Патч продолжает визуальную основу PR #188.
Выпуск в production в рамках этой задачи не выполняется.

## 1. Основания и ограничения диагностики

На первом приложенном скриншоте Google Search Console показывает:

- 1188 URL в группе «Индексирование страницы запрещено тегом noindex»;
- 32 просканированных, но не проиндексированных URL;
- 39 URL с проблемой выбора канонического варианта;
- по одному URL с 404 и переадресацией;
- 31 обнаруженный, но не проиндексированный URL.

Это разные причины. Патч noindex не является исправлением всех перечисленных групп.
На втором скриншоте есть публичные страницы аниме среди страниц с кликами.
Их наличие не доказывает, что весь каталог доступен поисковым роботам сейчас.

Скриншот не содержит экспорт списка 1188 URL. Поэтому нельзя утверждать,
что все они — аниме, все ошибочно закрыты или все исправлены этим патчем.
Кабинеты и служебные маршруты могут правильно входить в эту группу.

Приложенный текст PageSpeed сообщает:

| Наблюдение | Значение из отчёта | Следствие для работ |
|---|---:|---|
| Возможная экономия изображений | 2451 КиБ | Проверить первичные и резервные источники |
| Сеть за загрузку | 3804 КиБ | Большие исходники заметно увеличивают трафик |
| Выполнение JavaScript | 2,1 с | Не добавлять новые клиентские библиотеки |
| Главный поток | 5,2 с | Сократить ненужные анимации и повторную работу |
| Потенциально неиспользуемый CSS | 80 КиБ | Продолжить маршрутное владение CSS из визуального патча |
| Потенциально неиспользуемый JS | 153 КиБ | Отдельно исследовать покрытия чанков перед удалением |

В отчёте видны исходные JPG AniList по 100–150 КиБ в слотах шириной 44–58 px.
Значения относятся к предоставленному замеру; это не новый лабораторный тест.
`width=400`, `height=600` и `sizes` у обычного img сами по себе не уменьшают файл.
Для этого нужны реальные варианты и srcSet либо меньший резервный файл.

## 2. Проверенные источники noindex

### 2.1 Публичные тайтлы

`lib/anime-seo.ts`: `shouldIndexAnime` ранее требовал quality_score >= 2.
Недостаток описания, года, жанров и постера мог дать noindex настоящему тайтлу.
`lib/seo-anime-index-server.ts` использовал такой же порог для sitemap-реестра.
Следовательно, менять только robots в шаблоне было бы недостаточно.

`app/anime/[slug]/page.tsx` также возвращал noindex при исключении загрузки.
Временная ошибка получения данных не должна становиться постоянной SEO-политикой.

### 2.2 Серии

`lib/episode-seo.ts` требовал свежего подтверждения провайдера.
Ответ unknown при сбое закрывал серию, даже если она уже подтверждена и опубликована
в sitemap. Проверка вызывалась и из metadata, и из тела страницы.

Запреты правообладателей, некорректные номера и никогда не подтверждённые серии
сохраняют отдельные проверки. Количество серий в аниме само по себе не доказывает,
что конкретная серия уже вышла и доступна.

### 2.3 Общие настройки

В `next.config.ts` не обнаружено общего X-Robots-Tag для HTML каталога.
В `proxy.ts` заголовок noindex применяется к API-ответам; его оставляем.
Корневой layout разрешает индексацию. `robots.ts` не блокирует `/anime/`.
Индивидуальные layouts кабинетов, входа, настроек, админки остаются закрытыми.

### 2.4 Проверка production до патча

Read-only GET с обычным User-Agent выполнены для главной, входа и двух публичных
URL со скриншота: `/anime/yani-neko-201141` и его `/episode/1`.
Главная: 200, index/follow, без X-Robots-Tag.
Вход: 200, ожидаемый noindex/nofollow.
Оба URL аниме: 200 с noindex/nofollow и дополнительным noindex от notFound.
Это указывает на ветку отсутствующего тайтла; проверка не установила,
почему конкретная запись отсутствует в доступных источниках production.
Факт совпадения URL со скриншотом не заменяет проверку записи в базе.

## 3. Требуемое поведение

| Ситуация | Решение |
|---|---|
| Тайтл с положительным безопасным ID, названием, catalogEligible != false | index/follow |
| Такой тайтл без описания/жанров/постера | index/follow, качество хранится отдельно |
| Нет названия или недопустимый ID | Не считать индексируемой записью |
| catalogEligible=false | Не разрешать индексирование |
| Данные внешнего каталога отсутствуют, есть локальная запись | Сохранить существующий локальный fallback |
| Нет локальной записи, есть indexable запись SEO-реестра | Построить минимальную публичную страницу из реестра |
| Нет записи ни в одном источнике | Сохранить notFound, не создавать фиктивный тайтл из slug |
| Исключение generateMetadata | Не подменять исключение успешным ответом с noindex |
| Серия подтверждена в действующем SEO-реестре | Сохранить index без свежего запроса к провайдеру |
| Серия отсутствует в реестре, провайдер подтверждает номер | index после текущей проверки |
| Серия отсутствует в реестре, провайдер unknown/unavailable | noindex |
| Действующее ограничение правообладателя на серию | noindex; запрет просмотра не меняется |
| Кабинеты, настройки, вход, API | Сохранить noindex |

## 4. Изменения серверной части

### 4.1 Общая политика тайтла

Изменить shouldIndexAnime на проверку настоящей каталожной идентичности.
Сохранить animeSeoQualityScore для диагностики и качества контента.
Не выдавать наличие rich results за следствие index=true.
Оба robots поля — robots.index и robots.googleBot.index — используют одно решение.
Canonical и социальные метаданные остаются прежними.

### 4.2 Sitemap-реестр

Запись indexable вычисляется через общий shouldIndexAnime.
Quality_score сохраняет прежний расчёт, не смешивается с доступностью для робота.
Схема, RLS, grants, секреты и роли Supabase не меняются.

Ранее сохранённые indexable=false строки не обновляются автоматически при деплое:
нужен следующий цикл существующего SEO-index cron. Плановый обход покрывает
70 исходных шардов за 10 дней. Для ускорения оператор может выполнить существующий
авторизованный refresh; патч не делает массовых production-записей.

### 4.3 Минимальный fallback тайтла

Добавить getSeoAnimeDetailFallback(animeId):

1. Отклонить недопустимый ID до запроса.
2. Прочитать существующий seo_anime_index серверным клиентом.
3. Выбрать только anime_id, slug, title, image_url, status.
4. Ограничить anime_id и indexable=true; получить максимум одну запись.
5. При пустом названии вернуть null.
6. Построить Anime с сохранённой идентичностью, постером и статусом.
7. Не придумывать описание, эпизоды, оценки, MAL ID или видео.

В resolveAnimeRoute использовать этот fallback только после текущего внешнего
и локального источников. Сохранённый slug имеет приоритет над slug, вычисленным по неполному русскому
названию, чтобы fallback не менял canonical.
Внешние данные по-прежнему обогащают полноценную страницу.
Если SEO-реестр недоступен, логировать сбой и сохранить текущую ветку отсутствия.
Этот патч не превращает все ошибки источников в корректный HTTP 503:
для полного различения missing/temporary_failure нужен отдельный контракт resolver.

### 4.4 Подтверждённые серии

В isEpisodeIndexable сначала проверить номер и действующие copyright ограничения.
После этого читать подтверждённую indexable=true запись SEO-реестра.
Если запись есть, не обращаться к внешнему провайдеру ради robots.
Иначе использовать существующую проверку доступности и синхронизацию реестра.

Обернуть функцию в React cache для повторного использования metadata/body
в рамках одного серверного render. Это не глобальное кэширование пользовательских
данных и не постоянный кэш ограничений между запросами.

Реестр должен поддерживаться существующими refresh/удалением ограниченных записей.
Патч считает его действующим подтверждением; мгновенную переоценку всех старых
серий по живому провайдеру он намеренно не выполняет.

## 5. Оптимизация медиа и загрузки

### 5.1 Маленькие постеры

Для preset=tiny сохранить первичный качественный источник и Worker srcSet
с ширинами 96/144/240. Если Worker недоступен, следующей попробовать medium
версию, если она предоставлена источником. Большие варианты остаются дальше
в резервной цепочке для восстановления, доступность изображения не жертвуем.

Первичный URL src и upstream srcSet должны совпадать и при preference=quality,
и при preference=compact. Не подменять large/extraLarge в основном пути.
Для card/large/hero сохранить прежние приоритеты и качество изображения.
Не выдумывать размеры файлов medium: используем исходные URL из данных.

### 5.2 Анимация

Убрать animate-pulse с фонового placeholder массового AnimeImage.
Сохранить статическую подложку, зарезервированную геометрию, alt, lazy/near загрузку,
таймеры восстановления и fade готового изображения.

### 5.3 Что требует следующего измерения

Новый Lighthouse на том же устройстве/профиле сети после выпуска.
Фактическая передача Worker-вариантов: Content-Type, байты, ширина, cache hit.
Если Worker возвращает raw оригинал при softFail, порядок fallback это не исправляет.
Нужна отдельная диагностика трансформаций Worker; health ok не доказывает resize.

Большие чанки и CSS нельзя безопасно удалять только по проценту неиспользования
на одной странице. Следующий этап — Coverage и привязка тяжёлых компонентов
к маршрутам/видимости. В текущем патче новых клиентских библиотек нет.
Яндекс Метрика уже отложена до взаимодействия/30 секунд; её не отключаем.
Предыдущий визуальный патч переносит часть домашнего CSS в маршрутный файл.

## 6. Приёмка и тесты

Автономный тест `npm run seo-indexing-media:check` включён в prebuild и запускает реальные
функции через TypeScript с изолированными внешними сервисами и проверяет:

- публичный минимальный тайтл при quality_score=0 разрешён в обоих robots полях;
- исключённый, безымянный и некорректный тайтлы не разрешены;
- подтверждённая серия не вызывает провайдер;
- copyright ограничение сохраняет приоритет;
- неизвестная новая серия закрыта, подтверждённая свежая открыта;
- повторная проверка серии использует тот же результат;
- запрос fallback имеет фильтр indexable=true;
- resolver восстанавливает существующую запись, не создаёт отсутствующую;
- tiny цепочка начинает с Worker и затем меньшего изображения;
- обычные карточки сохраняют прежний порядок;
- кабинеты и админка сохраняют noindex.

Дополнительно: TypeScript, ESLint изменённых файлов, существующие SEO/media
инварианты, полный prebuild и production build. Исторический структурный SEO-тест
обновлён под новую политику; его остальные проверки не ослаблены.

## 7. Выпуск и Search Console

1. Сначала выпустить визуальную основу PR #188 либо включить её в общий review.
2. Проверить патч и слить только после решения о выпуске.
3. Дождаться успешного deployment Railway.
4. Проверить несколько URL из экспорта группы noindex обычным GET и live URL test.
5. Проверить header X-Robots-Tag, robots и googlebot meta, canonical и содержимое.
6. Убедиться, что страница действительно содержит аниме, а не recovery/notFound.
7. Дождаться refresh sitemap-реестра или выполнить существующий авторизованный refresh.
8. В Search Console запустить проверку исправления для ошибочно закрытых URL.
9. Для нескольких важных аниме запросить индексацию, проверить sitemap-index.
10. Повторить одинаковый замер PageSpeed и проверить работоспособность постеров.

Google должен заново обойти URL; снятие noindex не гарантирует включение в индекс.
Не делать массовую заявку для кабинетов и не открывать их robots ради нуля в отчёте.
