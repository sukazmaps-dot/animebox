# Патч 29.4 — компактный и читаемый мини-профиль

## 1. Цель и границы
Сделать всплывающий профиль понятным на ПК и телефоне: статистика читается полностью, действия связаны с содержимым, карточка не выходит за viewport, клавиатура остаётся внутри открытого диалога. Работать с существующими данными и сценариями дружбы.

В этом PR: ProfilePreview, его CSS Module и только вариант profile-preview компонента FriendActionButton. Общий StreakDisplay получает локальный класс через уже существующий className; остальные варианты серии активности не меняются.

Следующие отдельные патчи: общая палитра информационных страниц/друзей, адаптивность редактора, расписание и выбор настроения. Не добавлять их в этот PR. Не менять API, Supabase, права доступа, хранение, расчёт XP, серии, приватность или Premium-настройки.

## 2. Подтверждённые дефекты
1. На desktop в мини-профиле naarch подпись «Серия не начата» обрезана в узкой половине строки.
2. В CSS compactCopy strong/em и metaCard strong/em применены nowrap и ellipsis. Статистика теряет смысл до того, как появляется перенос.
3. Локальные подписи имеют размеры 7–9px и полупрозрачные цвета; их трудно читать.
4. Два CSS-модуля независимо включают одноколоночную раскладку действий при <=640px. Получаются три полноширинных ряда: «В друзьях», «Удалить», «Профиль».
5. Кнопка закрытия 32px — ниже продуктового стандарта 44px для интерактивов.
6. Диалог объявлен aria-modal=true и закрывается Escape, но не содержит явного начального фокуса/Tab-loop/возврата фокуса.

Не считать доказанным наличие огромных пустых блоков во всех состояниях. Оценивать реальные размеры и доступность действий, а не заполнять пустоту фиктивными данными.

## 3. Информационная архитектура
Порядок: обложка → аватар/имя/бейджи → описание при наличии → серия активности и дата регистрации/XP → дружба и профиль.
- Не резервировать место под отсутствующее описание.
- Не вводить фиксированную общую высоту или spacer до действий.
- Существующие поля статистики остаются без смысловых изменений.
- Не добавлять последние просмотры/онлайн/любимый жанр: дополнительных разрешённых данных в текущем PreviewData нет.
- Сообщение API об ошибке остаётся рядом с действиями, переносится и не перекрывает контент.

## 4. Размеры и сетка
- Desktop: ширина min(380px, 100vw - 24px); 12px минимального зазора до краёв окна, включая позиционирование.
- Mobile <=640px: существующий bottom-sheet; доступная ширина окна за вычетом внешних отступов, не растягивать карточку по высоте.
- Максимальная высота: 100dvh минус внешние отступы; body имеет min-height:0 и overflow-y:auto.
- Внутренний горизонтальный padding: 16px desktop, 12px mobile.
- Шаг расстояний: 4/8/12/16px; действия отделены от статистики на 12px.
- Статистика: две колонки minmax(0,1fr); при внутренней ширине <=300px — одна. Переключение основано на container query body, не на ширине монитора.
- Значения strong и подписи em могут переноситься, min-width:0, overflow-wrap:anywhere. Ellipsis не применять к смысловой статистике.
- Иконка серии занимает 32px в локальном варианте; рядом остаётся пространство для значения.
- Не менять размеры/позиционирование сезонных и identity-рамок, Premium-обложки и медиа-трансформации.

## 5. Типографика и палитра
- Описание: 13px, line-height 1.55, без opacity.
- Метаданные/лейблы: минимум 11px, line-height 1.45.
- Основные значения: 13px, line-height 1.4, weight 650.
- Действия: 12px, line-height 1.4, weight 600, высота минимум 44px; рост высоты допустим при длинном тексте.
- Основной текст/вторичный текст/панели используют --ab-ui-text / --ab-ui-muted / --ab-ui-surface / --ab-ui-raised / --ab-ui-border, с fallback.
- Декоративные акценты, аватар, баннер, nickname effect и Premium identity сохраняют пользовательские настройки.
- Обычный текст: целевой контраст >=4.5:1 на фактически отрисованной поверхности обеих тем; нельзя заявлять соответствие по одному скриншоту.
- Disabled остаётся различимым; не маскировать ошибку низкой прозрачностью.

## 6. Действия дружбы
Сохранить варианты guest/self/none/pending_outgoing/pending_incoming/accepted/loading/error и существующие обработчики.
- Accepted в preview: «В друзьях» и компактное раскрываемое «Ещё»; внутри — «Удалить из друзей» с тем же removeFriend.
- Меню реализовать нативным details/summary, без новых зависимостей, абсолютного popover или портала. Открытый пункт увеличивает высоту в нормальном потоке, не обрезается скроллером.
- summary имеет понятное доступное имя и 44px поверхность.
- Busy блокирует повторную мутацию через существующий disabled/busy; ошибка остаётся видимой. Не менять сетевые запросы.
- Вне variant=profile-preview оставить прежнее видимое удаление и существующую раскладку.
- Профиль находится рядом с блоком дружбы; сетка minmax(0,1fr) minmax(0,112px); профиль может переноситься при увеличенном тексте. При переполнении тексты переносятся, не уменьшать шрифт до 8–10px.
- Для владельца, когда FriendActionButton возвращает null, ссылка «Профиль» не должна попадать в узкий случайный столбец.

## 7. Позиционирование и клавиатура
- Сохранить desktop-позицию относительно trigger, clamp до viewport, выбор above/below и ResizeObserver после загрузки.
- При открытии установить фокус на кнопку закрытия после монтирования portal; не прокручивать страницу.
- Tab/Shift+Tab циклически проходят доступные интерактивы внутри диалога. Скрытые пункты закрытого details не включаются.
- Escape закрывает; после закрытия вернуть фокус trigger, если он ещё существует в DOM.
- Mobile scroll lock сохраняется. Backdrop и fullscreen portal не меняются.
- Закрытие получает минимум 44×44px и не перекрывает имя/аватар.
- Reduced motion сохраняет поведение, отключая декоративную анимацию.

## 8. Проверка
Локально: TypeScript, ESLint изменённых TSX, существующие prebuild-checks, browser geometry/interaction fixtures с CSS Modules, скомпилированными Next plugins.
В CI: все Quality Gate проверки и production build.
Матрица viewport: 320/360/390/640/768/1024/1440/1920px; dark/light; короткое/длинное имя; нет/длинное bio; 0/длинная серия; guest/self/accepted/pending; loading/error; меню закрыто/открыто; text scale 100/125/200%; короткий viewport 400px.

Проверяем:
1. Карточка, действия и контент не выходят за viewport по горизонтали.
2. «Серия не начата» доступна полностью и не обрезана ellipsis.
3. Все primary действия и summary/close >=44px; длинный текст может увеличить высоту.
4. При маленькой высоте scrollHeight body > clientHeight, последнее действие доступно прокруткой.
5. Открытие меню не перекрывает соседнюю кнопку; пункт удаления доступен клавиатурой.
6. Escape и Tab-loop работают, trigger получает фокус обратно.
7. Default FriendActionButton не изменён по поведению.
8. Не добавлены запросы, таймеры, внешние библиотеки или SQL-миграции.

Browser fixtures проверяют CSS/DOM и фокус; они не доказывают работоспособность live API, авторизации, всех Premium-медиа или Android. Реальные проверки мутаций дружбы не выполнять на чужих данных ради QA.
