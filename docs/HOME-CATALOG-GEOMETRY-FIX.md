# ТЗ: стабильная геометрия главной и каталога

## 1. Цель и исходные наблюдения

Патч подготовлен по скриншотам пользователя от 11 октября 2026 года.
Основная цель — убрать зависимость внешнего вида от числа загруженных карточек,
согласовать три промокарточки и устранить конкретный риск расхождения SSR/браузера.

Наблюдения и степень подтверждения:

| Наблюдение | Подтверждение | Решение |
| --- | --- | --- |
| 1–2 рекомендации выглядят горизонтально, соседний ряд вертикально | Скриншоты и CSS по data-recommendation-rail-items | Один вертикальный формат при любом числе результатов |
| При дозагрузке третьего тайтла возможна перестройка | Следствие существующего CSS; пользовательский сценарий ещё не воспроизведён | Удалить условное переключение формата |
| Промокарточки различаются шрифтами и положением CTA | Скриншоты и разные компоненты/стили | Общий каркас в пределах home footer |
| Каталог имеет большие промежутки между элементами управления | Скриншоты и отдельные блоки tabs/filterBar | Одна переносимая панель |
| «Сохранённые тайтлы» путаются с личными сохранениями | Ответ API использует эту формулировку для savedCatalog | «Резервный каталог AnimeBox» |
| React #418 | Скриншот консоли; источник не установлен | Проверить SSR-пути, устранить найденное вычисление локальных дат |
| Логотипы вместо части постеров расписания | Скриншоты | Диагностировать отдельно; CSS не восстанавливает отсутствующие изображения |
| ERR_BLOCKED_BY_CLIENT/ADBLOCKER | Скриншот консоли | Не обходить блокировщик и не связывать с #418 без доказательств |

## 2. Границы патча

Включены:
- геометрия рекомендаций на главной;
- визуальное согласование tracker/support/Telegram footer;
- панель каталога и точный текст резервных данных;
- детерминированный первый рендер дней домашнего расписания;
- загрузка cached taste graph каталога после первого рендера.

Не включены:
- изменение алгоритма подбора, порогов качества и порядка рядов;
- принудительное заполнение пустых мест неподходящими аниме;
- изменение платежей, webhook, прав доступа и базы;
- изменение Cloudflare, DNS, R2 и секретов;
- обещание устранения всех возможных причин React #418;
- обход блокировки рекламы расширениями.

## 3. Контракт рекомендаций

### 3.1. Независимость формы от количества

1. 1, 2, 3 и 6 карточек имеют один вертикальный формат.
2. Постер сохраняет прежние пропорции и адаптивную ширину текущей карусели.
3. Пагинация добавляет карточки, не изменяя layout существующих.
4. Небольшое число совпадений оставляет свободное пространство справа.
5. Не использовать селектор количества как переключатель display/grid/width.
6. Сохранить ключи rail.id:anime.id и существующий механизм ownership.
7. Сохранить feedback, планирование, скрытие и отмену действий.
8. Не менять виртуализацию, предел DOM и scroll-end загрузку.

### 3.2. Приёмка

- При переходе 1 → 2 → 3 первые карточки сохраняют ширину, пропорции и структуру.
- На мобильном горизонтально прокручивается только сама лента.
- Длинное название не растягивает страницу.
- Скрытие карточки не переключает остальные на горизонтальный формат.
- Изменение настроения остаётся явным действием пользователя.

## 4. Контракт промокарточек

### 4.1. Область действия

Общий визуальный контракт применяется к home-utility-grid.
Telegram на Watch Together и правой панели сохраняет свои отдельные варианты.
Кнопка закрытия Telegram остаётся доступной и не перекрывает текст бренда.

### 4.2. Размеры и поток

- Внешние поля: 1.25rem; внутренний промежуток: .875rem.
- Состав: шапка → заголовок/описание → дополнительные элементы → CTA.
- Иконка шапки: 2.5rem; не сжимается при длинном тексте.
- Заголовки h2/h3 получают единые размер, вес и line-height.
- Описание: .8125rem, line-height 1.5.
- CTA: min-height 2.75rem, разрешён перенос длинного текста.
- CTA прижат вниз через margin-top:auto.
- На одной строке карточки растягиваются до общей высоты по контенту.
- На узком экране высота определяется контентом без обрезания.
- Цвета и фокус наследуют существующую систему тем.

### 4.3. Telegram

Добавить общие классы только для placement=home_footer.
Сохранить локальные классы для бренда, бейджей, закрытия и аналитики.
В footer убрать промежуточный flex-контейнер из геометрии через display:contents,
чтобы CTA участвовал в том же вертикальном потоке, что у двух других карточек.
Не менять условия показа, частоту и localStorage key скрытия.

### 4.4. Приёмка

- Верхние и нижние края трёх карточек согласованы.
- CTA лежат на одной нижней линии при одной строке.
- Размер текста и отступы описаний одинаковы.
- Кнопка Telegram может быть шире из-за подписи, но имеет ту же минимальную высоту.
- Скрытие Telegram не оставляет интерактивную пустую карточку.
- Light theme сохраняет читаемость, keyboard focus виден.

## 5. Каталог

### 5.1. Панель управления

Перенести вкладки из page-heading в filterBar.
Слева вкладки, затем настроение; фильтры занимают свободное место справа.
На малом экране вкладки получают полную строку, остальные элементы переносятся.
Не дублировать кнопки, не менять handlers applyView/commitMood/toggleFiltersPanel.
Сохранить aria-expanded и доступность интерактивных элементов.
Не добавлять новую задержку поиска или дополнительный сетевой запрос.

### 5.2. Резервные данные

Текст должен описывать источник данных, а не личную библиотеку.
Обычный fallback: «Показаны результаты из резервного каталога AnimeBox.
Данные могут быть неактуальными.»
Частичный scan: указать доступную часть резервного каталога и предложить уточнить запрос.
Неподдерживаемые фильтры: указать конкретные недоступные условия.
Не писать «Обновляем», если активного обновления нет.
Не менять wire source='saved', TTL, пагинацию и выбор данных.

## 6. Гидратация

### 6.1. Подтверждённый риск расписания

createScheduleDays использует new Date и локальное форматирование.
На SSR и в браузере могут отличаться календарный день, ключи и названия будней.
Главная действительно рендерит эти tabs сервером, в отличие от SmartRecommendationFeed,
который подключён с ssr:false и сам не объясняет SSR-mismatch этой главной.

### 6.2. Исправление

- scheduleDays=[]; выбранный день=''; clockNow=0 на первом рендере.
- Вместо отсутствующих дней выводятся семь неинтерактивных placeholders.
- После mount requestAnimationFrame заполняет локальные даты и время.
- Таймер раз в минуту обновляет время и проверяет переход суток.
- Если выбранный день ещё существует в новой неделе, выбор сохраняется.
- Иначе выбирается первый день новой недели.
- Очистить RAF и interval при unmount.
- Не применять suppressHydrationWarning и не отключать SSR всей страницы.

### 6.3. Cached taste graph каталога

Первое состояние null одинаково на сервере и в браузере.
Чтение браузерного кэша выполняется в уже существующем mount effect.
Сохранить загрузку свежего графа и подписку на taste-graph-updated.

### 6.4. Приёмка и ограничения

Проверить SSR в UTC и Asia/Qyzylorda на одной временной точке около полуночи.
Исходный HTML расписания должен совпадать независимо от TZ.
После mount браузерные дни должны соответствовать локальному времени.
Это проверка конкретного исправления; #418 может иметь другие источники,
включая расширения браузера, которые надо отличать отдельным воспроизведением.
