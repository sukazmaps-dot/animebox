## 1. Цель и пользовательский результат

Пользователь на телефоне должен видеть все позиции главного баннера, понимать,
какая выбрана, и переключать рекомендации без случайного открытия страницы тайтла.
В трекере прогресс должен читаться в обеих темах, а «Продолжить» иметь удобную
область нажатия. Проверки должны отличать реальный дефект от промежуточного кадра
CSS-перехода и останавливать выпуск при устойчивой регрессии.

## 3. Границы и порядок работ

### Этап A — завершить существующий трекерный патч

1. Сохранить тематические токены текста/счётчиков из PR #226.
2. Сохранить минимум 44 CSS px по высоте у «Продолжить», включая старый mobile CSS.
3. Перед измерением computed styles дождаться применённой темы и закончить
   конечные CSS-переходы через Web Animations API. Не добавлять случайные задержки.
4. Не снижать порог 4.5:1 и не исключать landscape из теста.
5. Считать фон у самого измеряемого текста: поднятая подложка progress и выбранная
   подложка resume отличаются от общего surface. Прозрачные цвета композить.
6. Проверить подпись, заголовок серии, количество серий и текст ссылки resume.
7. Бизнес-логику статусов, trackedEpisodes, процентов и URL продолжения не менять.

### Этап B — исправить пагинацию с нового скриншота

1. Выделить маленький `HomeHeroPagination` с CSS Module и единственным владельцем
   размеров/цветов. Не передавать исторические global классы dot/nav/counter.
2. Вход: массив `{id,title}`, активный индекс и callback выбора.
3. Источник слайдов, максимум 5, deduplication, персонализация, SSR/LCP-порядок,
   autoplay, swipe и блокировка случайного клика остаются в HomeHeroCarousel.
4. При 0/1 слайде пагинация не выводится. При 2–5 число кнопок равно числу слайдов.
5. Счётчик форматируется как `01 / 05`, при выборе последней позиции — `05 / 05`.
6. Активная позиция отличается длиной отметки (24px против 8px) и цветом;
   различие не должно зависеть только от цвета.
7. Неактивные отметки используют читаемый `--ab-ui-muted`, активная —
   `--ab-ui-accent`. Убрать зависимость отметки от ambient RGB постера.
8. Область нажатия каждой кнопки по возможности 44×44px на штатных телефонах
   320px и шире; отдельные кнопки не перекрываются и находятся внутри баннера.
9. Нижний контент баннера резервирует место: социальная ссылка завершается выше
   пагинации минимум на 8px. Не увеличивать фиксированную высоту всего баннера.
10. При длинном названии и переносе CTA высота определяется содержимым;
    заголовок, «Смотреть», «Подробнее» и социальная ссылка остаются доступными.
11. Пагинация не накрывает действия прозрачным интерактивным слоем.
12. На desktop сохранить счётчик и компактные позиции; не менять постер/hero media.
13. Удалить уже ненужное правило nav в текущем home mobile stylesheet;
    новую глобальную таблицу стилей и новые root imports не добавлять.

### Этап C — доступность и взаимодействие

- Нативные `button type=button`, `aria-pressed`, понятный `aria-label` с названием.
- Общая группа «Выбор рекомендации», счётчик декоративный для screen reader.
- Одна активная кнопка. Callback получает реальный индекс соответствующей кнопки.
- Enter/Space используют нативное поведение кнопки; фокус виден и не обрезан.
- Нажатие на кнопку распознаётся существующим `closest('a, button, ...')` в hero
  и не должно открыть страницу тайтла.
- Не добавлять live region, который озвучивает каждую автоматическую смену.
- Reduced motion не должен скрывать отметки или менять выбранную позицию.

## 5. Требования к достоверности тестов

A. Actual built HTML: /list и /settings, реальные assets из production build.
Это не авторизованный сценарий и не доказательство всех состояний после hydration.
Отдельный settings-guest-smoke проверяет реальную гидратацию и local persistence.

B. Для динамических каталога, тайтла, профиля и auth tracker использовать явно
обозначенные source-equivalent DOM fixtures с реальными стилями. Не выдавать их
за запрос к SSR с рабочими данными пользователя.

C. Пагинация: рендерить настоящий React-компонент с его CSS Module. Проверять
индексы реальных обработчиков отдельно от геометрии. Не подменять компонент
рукописной копией кнопок. Полная гидратация autoplay/swipe сюда не входит.

D. Сеть в fixtures отключена. Скрипты не входят в чужие аккаунты, не пишут в БД,
не отправляют сообщения и не запускают плеер. Скриншоты — только внутренняя QA.

E. Ошибка содержит тему, viewport, состояние и название элемента. Ни retries,
ни lowering thresholds, ни общий overflow:hidden не считаются исправлением.

## 9. Исключения и следующий цикл

В этом патче не восстанавливаются исторические рейтинги, не изменяются
источники видео, поиск, R2, cron, Supabase или монетизация. Остальные старые
скриншоты проверяются по конкретным страницам; дефект не объявляется исправленным

потребует отдельного аудита всех маршрутов: здесь изолируется один конфликтующий
компонент и завершается уже открытый PR.
