# Patch 29.16 — устойчивые подсказки расписания

Дата: 15.10.2026. База: `main` после PR #227, `ab030daf`.
Ветка: `fix/patch29-16-tooltip-interactions`.

## 1. Задача патча

Завершить стабилизацию уже существующих подсказок недельного расписания.
Пользователь должен читать полное название, свободно переходить к соседним
карточкам и пользоваться клавиатурой без мигания и зависших подсказок.
Закрытые элементы не должны создавать обработчики глобальных событий.

Это узкий патч поведения одного компонента. Он продолжает ранее заявленную
задачу надёжных tooltip и не является редизайном всего каталога.

## 2. Что уже работает

- `TooltipLink` используется в недельном расписании `/schedule`.
- Текст содержит полное название и номер/план выхода эпизода.
- Панель создаётся portal в `document.body` и использует fixed positioning.
- Положение вычисляется по геометрии ссылки и панели, с отступом 12px от окна.
- Сначала пробуется размещение сверху, затем снизу.
- Панель не перехватывает указатель: соседние ссылки остаются доступными.
- Есть задержка наведения 350ms и задержка ухода 150ms.
- Keyboard focus использует `:focus-visible`, панель связана `aria-describedby`.
- Escape, scroll и resize закрывают панель.

Не объявлять уже реализованный portal или flip новым исправлением.
Сохранить перечисленные свойства и проверить их в настоящем Chromium.

## 3. Подтверждённые причины

### 3.1. Постоянные глобальные подписки

Существующий effect устанавливает scroll/resize/keydown для каждого mount
`TooltipLink`. При N ссылках число слушателей равно 3N даже в покое.
Это установленный по исходникам расход подписок, а не измерение пользовательского
FPS или доказательство конкретной величины ускорения страницы.

### 3.2. Возврат курсора во время отложенного закрытия

Старый `claim` вызывает закрытие даже своего текущего владельца. Возврат в течение
150ms скрывает уже показанный tooltip и запускает новую задержку 350ms.
При повторных событиях также необходимо явно очищать предыдущий timer.

### 3.3. Ненужный timer после touch

Touch enter не открывает tooltip, но старый leave всё равно создаёт timer.
В неактивном состоянии leave должен быть пустой операцией.

## 4. Модель состояний

| Состояние | Панель | Глобальные подписки | Таймер |
| --- | --- | --- | --- |
| idle | отсутствует | 0 | нет |
| pending | отсутствует | 3 у владельца | открытие через 350ms |
| open | видна после измерения | 3 у владельца | нет |
| leaving | остаётся видимой | 3 у владельца | закрытие через 150ms |
| keyboard open | видна | 3 у владельца | нет |

`active` объединяет pending/open/leaving; переход pending → open не должен
переустанавливать подписки и очищать timer преждевременно.
Панель и позиция остаются локальным React state, единственный владелец —
существующая module-level ссылка на функцию dismiss.

## 5. Правила мыши

1. Первое наведение показывает текст только после 350ms.
2. Уход до 350ms отменяет открытие; панель не вспыхивает после ухода.
3. После показа уход оставляет панель до истечения 150ms.
4. Возврат за эти 150ms отменяет закрытие, сохраняет видимую панель и позицию.
5. Возврат не запускает ещё один opening timer для уже открытой панели.
6. Наведение на другую ссылку отменяет pending/close старой и закрывает её.
7. У новой ссылки сохраняется собственная задержка 350ms.
8. Одновременно существует не больше одного `role=tooltip`.
9. Ссылка остаётся ссылкой Next; href, children, классы и click navigation прежние.
10. Click закрывает tooltip; панель не вызывает preventDefault и не ловит click.

## 6. Клавиатура и касание

1. Tab до ссылки открывает подсказку без задержки hover.
2. `aria-describedby` указывает на существующий уникальный ID панели.
3. Escape закрывает её и убирает `aria-describedby`, фокус остаётся на ссылке.
4. Blur закрывает панель и сбрасывает признак keyboard focus.
5. Pointer leave не закрывает панель, открытую клавиатурой, пока фокус сохраняется.
6. Обычный mouse focus не имитирует keyboard focus.
7. Touch enter/leave не показывает tooltip, не создаёт timer и глобальные подписки.
8. Touch tap сохраняет обычное действие ссылки; длинное нажатие браузера не менять.
9. Нативные Android/iOS жесты и screen reader не объявлять проверенными
   на основании desktop Chromium с touch emulation.

## 7. Глобальные события и cleanup

1. При mount 100 неактивных ссылок — 0 собственных window listeners.
2. У pending/open владельца — scroll capture, resize и keydown: всего 3.
3. Подписки нужны уже в pending: прокрутка должна отменять отложенное открытие.
4. Любой scroll, включая вложенный scroller, dismiss активную подсказку.
5. Resize закрывает её; после нового наведения положение вычисляется заново.
6. Escape dismiss как открытую, так и ожидающую панель.
7. При смене владельца число подписок возвращается к 3, не растёт до 6N.
8. При переходе в idle removeEventListener с теми же handler/capture.
9. При unmount очистить timer, подписки, ResizeObserver и ожидающий RAF.
10. Не очищать module-level владельца другого экземпляра при cleanup старого.
11. Не оставлять callbacks после unmount, не добавлять document-level polling.
12. Не увеличивать бюджет обработчиков постоянной оболочки приложения.

## 8. Геометрия и тема

1. Portal остаётся прямым потомком body, вне overflow расписания.
2. Горизонтальная геометрия укладывается в окно с отступом 12px.
3. У верхнего края панель находится снизу ссылки; у нижнего — сверху.
4. Длинное русское/латинское название переносится; непрерывный токен тоже.
5. До 320px viewport не появляется горизонтальная прокрутка документа.
6. Для обычных названий высота панели полностью помещается в тестовое окно.
7. Текст и фон используют существующие `--ab-ui-*` tokens обеих тем.
8. Проверить computed contrast обычного текста >=4.5:1.
9. `pointer-events:none` сохраняется, hit testing соседней ссылки успешен.
10. Широкая панель не блокирует соседнюю колонку даже если визуально над ней.
11. Не добавлять новые z-index, глобальные theme overrides и CSS imports.
12. Чрезвычайно длинный контент высотой больше окна не считать поддержанным
    scrollable popover: компонент предназначен для названия и эпизода.

## 10. Браузерная методика

Исполнить настоящий TooltipLink с React DOM и настоящим CSS Module.
Собрать отдельный временный harness существующим webpack из Next, без изменения
приложения и без добавления тестового маршрута в production.
Next Link допускает тестовый adapter только если это явно записано в результате;
такой тест доказывает tooltip DOM/events, а не Next router/prefetch.

Расписание в harness — детерминированный контейнер с overflow и 100 ссылками,
а не настоящее dynamic SSR с внешними schedule API. Сеть полностью запрещена.
CSS темы брать из root imports в исходном порядке и настоящий CSS Module.
Проверять computed geometry, реальные focus/hover и отсутствие uncaught errors.

## 14. Фактические результаты

- Жизненный цикл переведён на active-владельца: idle=0 window listeners,
  pending/open/leaving=3. При возврате к своему открытому tooltip очищается
  отложенное закрытие, без повторного показа и новой задержки.
- Неактивный pointer leave не создаёт timer. Anchor вне окна при измерении
  вызывает полный dismiss, включая освобождение глобальных подписок.
