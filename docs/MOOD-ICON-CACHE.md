# Быстрая загрузка иконок настроения

## Задача

Иконки главной должны появляться при прокрутке до блока, без наведения или касания. Повторное посещение должно использовать сохранённые изображения. Оформление, названия настроений и подбор рекомендаций сохраняются.

## Причины задержки

`HomeMoodPicker` монтировал изображения только после pointer/focus-события. Прокрутка сама по себе их не запускала. Пять исходных изображений занимали 648 686 байт; чашка размером 1254×1254 занимала 536 708 байт для слота 38×38.

## Изменения

- Общий `observeNearViewportMedia` запускает загрузку при приближении блока к экрану; обработчики касания и фокуса также работают. Observer очищается при активации и размонтировании.
- Статичные WebP уменьшены до 128×128, сохраняя прозрачность и запас для экранов с высокой плотностью пикселей. Пять иконок главной занимают 22 170 байт.
- Общий реестр адресов используется главной и каталогом. Каждый новый адрес содержит первые 12 символов SHA-256 содержимого.
- Адреса дополнены `?v=mood-icons-v1`, чтобы обходить ответы 404, сохранённые CDN до первой публикации файлов. Хеш в имени продолжает управлять обновлением рисунка.
- Только каталог `compact/` получает `Cache-Control: public, max-age=31536000, immutable`. Более узкое правило следует после общего `/brand/` и переопределяет его TTL.
- Существующий service worker уже сохраняет `/brand/` по cache-first; новые адреса совместимы с ним. Принудительное предварительное скачивание иконок при установке worker не добавляется.
- Отложенный SSR, низкий приоритет запроса, фиксированные размеры и декодирование async сохраняются.

## Обновление рисунков

После изменения исходников выполнить `node scripts/optimize-mood-icons.mjs` и закоммитить новые файлы вместе с `lib/mood-icon-assets.ts`. Генератор отклоняет анимированные исходники, чтобы случайно не удалить анимацию. Старые опубликованные хешированные файлы сохраняются для открытых вкладок.

## Проверка

- `npm run build`, TypeScript и ESLint.
- `tests/mood-icon-cache.mjs`: реальные файлы, размеры, бюджет, соответствие хеша, порядок HTTP-заголовков; две загрузки страницы через настоящий HTTP-сервер должны дать ровно девять запросов изображений, без дополнительных запросов при втором посещении.
- `scripts/adaptive-visual-smoke.mjs`: реальные production HTML/JS/CSS; прокрутка без касания должна загрузить все пять иконок; затем проверяются 22 сочетания темы и ширины экрана.

Для browser-проверок нужны Playwright и Chromium; путь можно задать через `CHROMIUM_EXECUTABLE_PATH`. После публикации проверяется фактический `Cache-Control` на Railway: внешний прокси может переопределять заголовки. Очистка браузерного кэша, приватное окно и принудительное обновление могут вызвать повторное скачивание.
