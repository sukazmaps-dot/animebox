# ТЗ: стабильная главная на телефонах и авторизация после переноса

## Проблемы и подтверждённые наблюдения

Пользователь сообщает, что ряды рекомендаций («История продолжается», необычные рекомендации) меняются местами, пока он не прокрутил всю ленту. В коде первоначальный порядок уже фиксирован, но состав рядов меняется: недозаполненный ряд удаляется из DOM после исчерпания попыток и возвращается при новой порции кандидатов. Новые ряды вставляются выше ранее показанных. Первоначальная карта распределения карточек сохранялась только в ref, хотя следующий расчёт использовал state. CSS применяет `content-visibility: auto` одновременно ко всей многорядной секции и её внутреннему контейнеру, заменяя реальную высоту оценкой до появления в зоне отрисовки.

На скриншоте входа Google сообщает «Google-вход ещё не настроен», а его место остаётся пустой белой областью. Google и Telegram читают ID непосредственно из `NEXT_PUBLIC_*` клиентской сборки. При отсутствии переменных во время сборки последующее добавление их в окружение процесса не обновляет уже выпущенный JavaScript.

Проверка опубликованного сайта 7 октября 2026: `POST /api/auth/telegram/nonce` вернул HTTP 200 и nonce; email-вход с искусственными неверными данными вернул HTTP 401 «Неверный email или пароль». Это подтверждает доступность обработчиков, но не успешный вход реального пользователя, настройки OAuth или доставку сообщений ботом.

## Требуемое поведение главной

1. При первом отображении использовать существующий первоначальный порядок рядов.
2. В пределах выбранного настроения сохранять позиции всех уже показанных рядов. Поздно обнаруженный ряд добавлять ниже существующих, без вставки над ними.
3. Исчерпание попыток, завершение пагинации и повторная загрузка не должны удалять показанный ряд. Карточки сохраняются; скрытые пользователем карточки не восстанавливаются из снимка.
4. Сохранять распределение карточек сразу при первом расчёте. Последующие порции не могут переносить карточку в другой ряд или менять порядок ранее выделенных карточек.
5. Явная смена настроения создаёт новую композицию; фоновые обновления и пагинация её не сбрасывают.
6. На узких экранах и устройствах с грубым указателем учитывать реальную высоту секции рекомендаций и её контейнера до прокрутки до конца. Для рядов резервировать минимальную высоту. Существующая горизонтальная виртуализация и ленивая загрузка изображений сохраняются.

## Требуемое поведение авторизации

1. Добавить динамический `GET /api/auth/config`, читающий публичные ID из окружения запущенного сервера. Ответ только `{ googleClientId, telegramClientId }`, с `Cache-Control: no-store`.
2. Поддержать текущие имена `NEXT_PUBLIC_GOOGLE_CLIENT_ID`, `NEXT_PUBLIC_TELEGRAM_CLIENT_ID` и серверные альтернативы `GOOGLE_CLIENT_ID`, `TELEGRAM_CLIENT_ID`. Приоритет у существующих имён. Отсутствующий или некорректный Telegram ID возвращать как null.
3. Google получает конфигурацию перед инициализацией официальной кнопки. Вместо пустой области показывать загрузку или кнопку повторной попытки; ошибку загрузки не считать успешной инициализацией.
4. Telegram получает ID перед запуском входа. Серверная проверка токена использует тот же источник ID, сохраняя проверку подписи, issuer, audience, nonce и текущую защиту запросов.
5. Никогда не включать в ответ bot token, service-role key, webhook secret, OAuth client secret или всё окружение. Не менять ограничения частоты и проверку email/пароля.
6. Таймаут загрузки конфигурации — 10 секунд; не кешировать ошибку так, чтобы она блокировала следующую попытку.

## Выпуск и настройки хостинга

Патч не восстанавливает отсутствующие значения OAuth ID автоматически. На Railway должны быть заданы публичные Google и Telegram client ID по одному из поддерживаемых имён. Если старые `NEXT_PUBLIC_*` заданы, но неверны, исправить или удалить их перед использованием серверных альтернатив. После изменения окружения перезапустить/передеплоить сервис. В Google OAuth проверить разрешённый JavaScript origin `https://youranimebox.com`; в настройках Telegram Login — домен сайта. В Supabase Google provider должен оставаться включён с правильной конфигурацией, а серверные Supabase secrets — находиться в окружении нового хостинга.

Это отдельный патч от PR #179 с восстановлением webhook бота. Проверка входа через Telegram не доказывает работоспособность webhook и сообщений бота.

## Приёмка и автоматические проверки

- `node tests/home-rail-session.cjs`: поздняя вставка, исчезновение кандидатов, повторная загрузка, скрытые карточки, сброс композиции; также реальный компонент с последовательными обновлениями состояния и настоящий алгоритм распределения — сохранение owners, ограниченное число повторных render, завершение пагинации и порядок карточек.
- `node tests/public-auth-config.cjs`: чтение runtime ID, приоритет имён, allowlist без секретов, некорректные Telegram ID, no-store, отказ и последующее восстановление.
- TypeScript, ESLint изменённых TS/TSX, полный `npm run build` с существующими обязательными проверками. Новые regression checks добавлены в GitHub CI.
- Проверить production-сборку без ID на этапе build, но с искусственными ID при запуске: endpoint должен возвращать runtime значения. Реальные аккаунты для этой проверки не нужны.
- После выпуска: на телефоне открыть главную, прокрутить часть рядов, дождаться подгрузки, вернуться наверх, повторить при медленной сети; существующие ряды сохраняют взаимный порядок. Проверить смену настроения отдельно.
- После настройки ID: выполнить реальный Google/Telegram вход, email-вход с действующим аккаунтом, закрытие модального окна и сохранение сессии после перезагрузки. Эти проверки требуют действующего аккаунта и не подтверждены искусственными запросами.

Миграция базы данных для этого патча не требуется. Известное ограничение: автоматическая браузерная проверка геометрии не выполнена — исполняемый Chromium в рабочей среде отсутствует; CSS исправлен по установленной причине, мобильная приёмка остаётся обязательной.

## Результат проверки реализации

Полная production-сборка `npm run build` (включая prebuild checks), TypeScript, новые regression tests и существующий `tests/scroll-row-momentum.cjs` прошли. ESLint изменённых файлов завершился без ошибок; в SmartRecommendationFeed остались два ранее существовавших предупреждения о лишней зависимости tasteGraph. Production-сборка без OAuth ID при build была запущена с искусственными ID только в runtime: запрос к `/api/auth/config` вернул HTTP 200, ровно два публичных поля с runtime значениями и `Cache-Control: private, no-store` после обработки proxy. Успешный реальный вход и мобильная браузерная приёмка остаются непроверенными.
