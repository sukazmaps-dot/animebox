# Patch 27 — Personal Home & Retention

## 1. Цель и границы

Сократить путь возвращающегося зрителя: открыть главную → найти своё аниме → перейти к нужной серии. Существующие системы просмотра, рекомендаций, расписания, прогрессии и уведомлений переиспользуются. Патч меняет композицию главной, достоверность продолжения и качество измерения показов. Не вводит вторую recommendation pipeline, новый источник контента или новый способ начисления XP.

Основа: main 2ffa0c6e, Merge Hotfix 25.1 — Mobile LCP & Image Delivery Recovery. Номер 27 — рабочее название новой ветки, а не утверждение о завершённом production-релизе 26.

## 2. Сценарии пользователя

1. Гость с локальным прогрессом видит до четырёх недавно начатых тайтлов и открывает конкретную серию. Локальные записи старше семи дней не навязываются на главной; история в трекере сохраняется.
2. Авторизованный зритель получает серверное продолжение. Свежий локальный прогресс может перекрыть серверный только при более позднем времени записи и допустимом времени устройства.
3. Сервер уже завершил эпизод и предлагает следующий: локальная позиция в предыдущем эпизоде не возвращает пользователя назад.
4. Зритель отслеживает онгоинг: персональное расписание появляется непосредственно после продолжения, до настроения и рекомендаций.
5. Эфир ещё впереди: карточка ведёт на страницу тайтла, не обещая открыть ещё не вышедший эпизод.
6. Эфир прошёл: карточка может вести на целевую серию, но подпись сообщает только факт эфира. Наличие перевода и озвучки не выводится из времени японского эфира.
7. Персональных данных нет: пустое расписание скрыто; существующие рекомендации и activation flow остаются доступны.
8. Медленная или неработающая загрузка расписания не блокирует продолжение и рекомендации.

## 3. Композиция главной

Текущий hero сохраняется, чтобы не отменить последние работы по LCP. Внутри единственного HomeDiscoverySection порядок следующий:

- HomeContinueWatching;
- HomePersonalScheduleSection;
- HomeMoodPicker;
- единственный SmartRecommendationFeed.

Персональное расписание удаляется из midFeedSlot. Это исключает зависимость доступности расписания от загрузки и количества recommendation rails. Сам механизм midFeedSlot в компоненте рекомендаций остаётся совместимым с другими потребителями. HomePageShell не создаёт второй экземпляр расписания или второй runtime.

## 4. Достоверность Continue Watching

Выделить чистую политику в lib/home-retention-policy.ts.

Правила локального времени:

- updatedAt конечный, положительный;
- допустимое отклонение в будущее: максимум 60 секунд;
- возраст локального resume: максимум семь суток;
- локальное обновление должно опережать серверное более чем на две секунды;
- для serverMode=next локальный эпизод ниже целевого серверного не побеждает;
- текущая проверка hasResumePosition остаётся обязательной;
- не менять правила completion, реальные секунды просмотра, Trust Engine, награды или серверную историю;
- выбор локального/серверного состояния вычисляется только для отображения главной;
- сортировка по времени просмотра и лимит четыре карточки сохраняются;
- ссылки, attribution и события клика продолжают использовать один и тот же выбранный эпизод.

Известное ограничение: серверная completion integrity остаётся источником истины. Патч не пытается вывести завершение серии из локального таймкода.

## 5. Персональное расписание

Чистая функция selectPersonalHomeSchedule принимает общий массив, Set персональных ID и текущее время в секундах.

Фильтры:

- ID тайтла присутствует в персональном наборе;
- episode — положительное целое;
- airingAt конечный;
- окно: от шести часов назад до 72 часов вперёд;
- одна карточка на пару animeId:episode;
- максимум четыре карточки.

Порядок:

1. Прошедшие эфиры: от самого свежего к более старому.
2. Будущие эфиры: ближайший первым.
3. При равном времени — стабильный порядок по ID.

Функция не сортирует и не мутирует исходный массив: общий schedule runtime используется правой колонкой и глобальным расписанием.

Маршрутизация:

- будущий эфир → animeHref(media);
- прошедший эфир → /watch?ep=episode;
- рядом с расписанием сохраняется пояснение, что перевод/озвучка могут появиться позже;
- компактный countdown уменьшает частоту обновления с одной секунды до 15 секунд;
- ScheduleItem получает необязательный releasedLabel; прежние потребители сохраняют текущую подпись.

## 6. Аналитика видимых показов

Ввести useVisibleHomeImpression для двух поверхностей.

- IntersectionObserver threshold=0.25;
- отправлять показ только для видимого документа;
- одна отправка на сигнатуру в пределах mounted surface;
- повторные rerender и уход/возвращение к той же поверхности не дублируют показ;
- изменение состава карточек создаёт новую сигнатуру;
- скрытая вкладка не отправляет показ; visibilitychange проверяет её возвращение;
- observer и listener очищаются при смене сигнатуры и unmount;
- браузеры без IntersectionObserver не создают фиктивных показов;
- события клика отправляются немедленно, независимо от observer;
- персональное расписание перестаёт отправлять impression из provider до своего появления в viewport;
- имена существующих событий и структура metadata сохраняются.

Ограничение: это видимость поверхности, не доказательство прочтения каждой карточки и не dwell-time. D1/D7 требуют отдельной серверной когортной аналитики; не заявлять их готовыми этим патчем.

## 7. Производительность и безопасность

Не добавлять запросы API, polling, глобальные подписки, пакеты, изображения, персональные public cache keys или миграции. Не читать прогресс другого viewerKey. Сохранять существующие RLS/auth boundaries. Использовать общий schedule provider. Продолжение не зависит от ответа расписания. Показы не отправлять во время render.

Геометрия карточек и существующий adaptive CSS сохраняются. Скелетон расписания остаётся ограничен тремя карточками. Настроение и recommendation runtime сохраняют собственные правила стабильности.

## 9. Критерии приёмки

- Свежий серверный progress не перезаписывается старым local.
- Будущее/NaN local timestamp не побеждает.
- Локальный завершённый предыдущий эпизод не замещает server next.
- Новый local для целевой серии может победить старый server.
- Неперсональные, некорректные, слишком старые и дублирующиеся эфиры исключаются.
- Прошедшие эфиры предшествуют будущим, будущие упорядочены по близости.
- Общий массив расписания не мутирует.
- Ровно одна персональная schedule surface и один recommendation runtime.
- Будущий эфир не открывает watch route.
- Impression появляется только после видимости, не из provider.
- TypeScript, lint изменённых компонентов и полный prebuild проходят.
- Production build проверяется отдельно; отсутствие доступа/зависимостей явно фиксируется, успех не предполагается.
