# AnimeBox: единая палитра и адаптация — этап 1

## 1. Цель и границы

Сделать общий каркас и главную читаемыми при любой доступной ширине.
Сохранить узнаваемый тёмный интерфейс с фиолетовым акцентом, постеры,
карусели и существующие функции. Дать светлой теме согласованную палитру.

В этот этап входят:
- фон страницы, шапка, поиск, навигация, общие кнопки, фокус и футер;
- главная: основной контент, правая колонка, служебные карточки;
- компактное расписание главной и строки ближайших серий;
- переменные цветов, отступов и радиусов для последующего переноса.

Следующие этапы: отдельная миграция каталога/трекера, страницы аниме,
профиля/настроек, чата/Watch Together. Этот этап не обещает преобразовать
каждый компонент сайта. Персональные цвета Premium-профилей сохраняются.

## 2. Наблюдения по четырём скриншотам

На ширине 1270 px основная часть сжата правой колонкой. Три карточки
получают примерно 190 px каждая, название Telegram переносится по словам,
встречаются разрывы обычных слов и разные вертикальные позиции CTA.
Уменьшение текста не устраняет нехватку места.

На промежуточной ширине расписание показывает названия из одной буквы,
потому что четыре колонки делят узкую основную часть, а постер/время
занимают почти всю ширину карточки. На широком скриншоте содержимое
читается лучше. Нужна адаптация по контейнеру, а не только по viewport.

Скриншот 979 px показывает отдельную нижнюю правую колонку с топом и
ближайшими сериями. При переносе вниз её элементы должны пользоваться
доступной шириной, сохраняя порядок и читабельные строки.

Заглушки и цветной шум в постерах — отдельный источник/медиа-дефект.
CSS не исправляет испорченные изображения. ERR_BLOCKED_BY_ADBLOCKER и
ERR_BLOCKED_BY_CLIENT для рекламных доменов не доказывают ошибку сетки.
Не ослаблять CSP ради удаления предупреждения eval из консоли.

## 3. Палитра и семантика

| Роль | Тёмная тема | Светлая тема |
|---|---|---|
| Canvas | #0B0D14 | #F5F6FA |
| Surface | #141824 | #FFFFFF |
| Raised | #1C2232 | #ECEFF6 |
| Border | #30384A | #CBD2E0 |
| Text | #F1F3FA | #202536 |
| Muted | #A8B1C3 | #566176 |
| Accent text/focus | #A78BFA | #6941B5 |
| Primary fill | #7551C8 | #7551C8 |
| Primary text | #FFFFFF | #FFFFFF |

Правила:
1. Цвет выбирается по роли, а не по названию конкретной страницы.
2. Основной фиолетовый обозначает действие, выбор или фокус.
3. Успех, предупреждение и ошибка сохраняют отдельную семантику.
4. Жёлтый рейтинг, реальные изображения и профильная персонализация
   не перекрашиваются в фиолетовый.
5. Поверхности ровные, без постоянного большого свечения.
6. Проверить WCAG-контраст: обычный текст >=4.5:1; крупный >=3:1.
7. Вторичный текст не превращать в почти невидимый серый.
8. Старые --bg/--panel/--ab-vl-* связать с общей системой через aliases.

## 4. Владение CSS

Общий контракт размещается в существующем последнем общем файле
app/patch17-4-2-ui-precision.css. Новые глобальные imports не добавляются:
проект уже имеет бюджет общего CSS. Это именованный блок foundation v2.

Главная управляется app/home-visual-repair.css, подключённым в app/page.tsx.
Правила основной сетки, utility и компактного расписания сгруппированы
в этом файле. Не добавлять ещё один глобальный файл с home-селекторами.

Существующие home-only правила из patch17-4-service-experience.css
перенесены в начало home-visual-repair.css; общие controls/player остаются
в прежнем общем файле. Это освобождает около 4 КБ root CSS и сохраняет
проверяемый бюджет 76 imports / 830000 source bytes.

Старые важные правила временно перекрываются ограниченными селекторами.
Не удалять все исторические CSS-файлы без проверки других маршрутов.
Новые !important допустимы там, где старый слой уже использует их;
в документе и комментариях явно фиксируется причина.

## 5. Каркас

- Фон canvas; шапка и sidebar — surface.
- Поиск — raised; текст input наследует text, placeholder — muted.
- Поиск должен сжиматься в своей flex-ячейке: min-width:0.
- Размер текста input не меньше 16 px, чтобы не провоцировать zoom iOS.
- Размеры и переключения sidebar/mobile-nav первого этапа сохраняются.
- Не менять position/z-index плеера и Telegram Mini App.
- Активная навигация использует мягкий accent фон и видимый текст.
- У всех основных ссылок и кнопок видимый focus-visible.
- Футер переносит группы ссылок, не создавая горизонтальный скролл.
- Общий контейнер получает плавные горизонтальные отступы.

## 6. Главная: сетка по контейнеру

home-page становится named inline-size container.
Основная сетка по умолчанию одна колонка, правая часть ниже.
Две колонки включаются только при ширине home >=75rem:
основная часть minmax(0,1fr), правая 18rem, промежуток 1.5rem.

Это позволяет окну 1270 px с sidebar показать читаемый основной контент.
Измеряется пространство внутри страницы, после вычета sidebar и padding.

Основная колонка — отдельный named container home-main.
Не устанавливать её фиксированную высоту, не менять порядок ленты,
не добавлять JS-измерения ширины и resize-перерисовки.

Правая колонка:
- при переносе вниз панели идут вертикально;
- внутри топа допустимы две колонки, если хватает ширины;
- ближайшие серии по умолчанию целыми строками;
- не оставлять зарезервированную пустую полосу рядом с utility-карточками.

## 7. Служебные карточки

До 34rem основного контейнера — одна колонка.
От 34rem — две равные колонки; при нечётном числе последняя во всю строку.
От 52rem — три равные колонки; последняя возвращается в обычную ячейку.

- Единые surface, border, радиус и padding.
- Заголовок 1.125–1.3125rem, line-height 1.3, до естественного переноса.
- Обычные слова не разрывать anywhere; длинный URL можно переносить.
- Основной описательный текст 1rem, line-height 1.55.
- CTA min-height 44px, margin-top:auto, иконка не сжимается.
- Не фиксировать высоту всех карточек в пикселях.
- При двух карточках после закрытия Telegram не резервировать третью.
- Telegram close сохраняется; текст шапки оставляет место под кнопку.
- Загрузка deferred содержимого не меняет количество CSS-колонок по
  количеству аниме или другим данным.

## 8. Компактное расписание

- Grid auto-fit с минимальной ячейкой 19rem, ограниченной 100%.
- Карточка: poster 44x66px, minmax(0,1fr) copy, time.
- Название до двух строк, white-space:normal; не одна буква.
- Мета переносится естественно, min-width:0 у copy.
- Время не сжимается в ноль, font-variant-numeric:tabular-nums.
- На home-main <24rem время идёт под текстом во второй колонке;
  постер занимает две строки.
- Вкладки дней горизонтально прокручиваются внутри блока.
- Заголовок и ссылка секции могут перенестись на отдельные строки.
- Не менять запросы данных, timezone, выбранный день и навигацию.
- Skeleton должен использовать тот же внешний grid-контракт.

## 9. Доступность и взаимодействие

- Проверка клавиатурного фокуса поиска, навигации, карточек и CTA.
- Основные кнопки минимум 44px по высоте.
- Уважать prefers-reduced-motion; не добавлять непрерывную анимацию.
- Hover не меняет размер и не сдвигает соседние элементы.
- Иконки декоративные и не подменяют подпись.
- Безопасные зоны мобильной навигации остаются рабочими.
- 200% browser zoom: контент перестраивается, функции доступны.

## 10. Матрица проверки

Viewport: 320, 360, 390, 768, 979, 1024, 1270, 1440, 1920 px.
Дополнительно 2560/3840 как проверка ограничения ширины и читаемости.
Состояния: dark/light, guest/auth, long titles, Telegram visible/dismissed,
loaded/loading/error/empty schedule, reduced-motion.

Для каждого размера проверить:
1. document.scrollWidth <= innerWidth.
2. В utility все карточки >= минимальной читаемой ширины, если две/три.
3. Название расписания имеет место для двух строк.
4. CTA и close не выходят за границы.
5. Ни один блок не перекрывает шапку/навигацию.
6. Правая колонка переносится при нехватке места.
7. Текст и акцент имеют нужный контраст в обеих темах.
8. Карусели сохраняют внутренний горизонтальный скролл.

## 11. Проверки кода

- Полная production build с существующими prebuild gates.
- TypeScript и релевантный lint.
- CSS route scope / frontend architecture / home geometry / schedule media.
- Контраст палитры вычислить, а не оценивать на глаз.
- Реальные браузерные проверки итогового CSS на граничных ширинах.
- Протоколировать какие проверки выполнены, какие заблокированы.
- Не выдавать статическую проверку строк CSS за визуальную проверку.

## 12. Выпуск и откат

Отдельная ветка от актуального main, проверенный commit и PR.
Без миграций БД, новых переменных окружения и публикации media Worker.
После merge Railway выпускает новый main при включённом автодеплое.
После деплоя проверить страницы и dark/light, а не только HTTP 200.
Откат: предыдущий deploy или revert данного commit, без отката ключей.

## 13. Критерии принятия

Первый этап готов, если общий каркас имеет согласованные поверхности,
главная использует доступную ширину, utility не сжимается в три узкие
колонки, расписание читается, светлая тема не получает тёмных панелей,
производственная сборка и необходимые проверки проходят.

## 14. Фактическая реализация и результаты

Общий контракт добавлен в существующий shared stylesheet; home-only
служебные правила перенесены из общего слоя в route stylesheet.
Главная и основная колонка получили именованные CSS containers.
На узком контейнере правая колонка идёт вниз; utility переключается
1/2/3, а закрытый Telegram блок не резервирует пустую ячейку.
Широкая utility использует auto-fit, чтобы две оставшиеся карточки
занимали доступную строку. Skeleton-постер имеет размер реального постера.

Контраст минимальный по трём поверхностям:
- Dark: text 14.30:1, muted 7.36:1, accent 5.83:1.
- Light: text 13.23:1, muted 5.42:1, accent 6.03:1.
- Белый текст на основной кнопке: 5.57:1.

Браузерная проверка: scripts/adaptive-visual-smoke.mjs использует настоящие
production HTML/CSS/JS из .next и обслуживает их offline через route fulfill.
Внешняя сеть и API отключены. Служебные карточки загружаются настоящими
компонентами, расписание проверяется с явным fixture длинных названий.
Это проверка итогового каскада и размеров, не availability/auth audit.

Для запуска после build:

```bash
CHROMIUM_EXECUTABLE_PATH=/path/to/chromium node scripts/adaptive-visual-smoke.mjs
```

Тест проверяет 22 сочетания темы/ширины, отсутствие page overflow,
ширину service cards, высоту CTA, доступную ширину названий расписания,
цвет canvas, keyboard focus и освобождение сетки после закрытия Telegram.
Снимки служебного ряда и расписания сохраняются в VISUAL_OUTPUT_DIR.
Фиксированная навигация скрывается только на снимках компонентов.

Ограничения: offline guest fixture не подтверждает работу OAuth,
Telegram Mini App, реальные изображения, профильную персонализацию,
сетевые empty/error transitions или браузерный zoom 200% буквально.
720 CSS px проверяет эквивалентную ширину reflow; ручная проверка zoom
и авторизованных сценариев остаётся частью проверки после deploy.

Итоговая проверка: production build с полным prebuild прошла; TypeScript,
targeted ESLint и git diff --check прошли. Браузерный тест без source
overrides прошёл на всех 22 сочетаниях. Проверены пробные клики CTA без
навигации на 390/1270/1920 px, фокус, touch target закрытия Telegram и
удаление его пустой ячейки. Итоговые снимки utility и расписания просмотрены.
OAuth, реальные медиа и авторизованный профиль остаются вне offline теста.
