# Лидерборд: единый поток, пьедестал и персональная строка

## Подтверждённые причины

На скриншотах пользователь #4 и награды недели. Предыдущий desktop-патч
поместил персональную строку в левую половину страницы, но её старые минимальные
ширины колонок суммарно превышали ширину этой половины. Кнопка «Профиль» вышла
за границу панели. `h-screen` и scroll-snap на этой странице не найдены:
эффект отдельных экранов создавали общая высота верхних блоков и карточек.

Последнее правило `align-items:stretch` отменяло нижнее выравнивание пьедестала.
Награды были четырьмя узкими колонками справа от широкого текста сезона;
`white-space:nowrap` и ellipsis принудительно сокращали заголовки.

## Реализация

1. Корневой контейнер — flex-column с gap 16px, естественной высотой и без max-height.
   Верхний баннер компактнее; между ним, наградами и результатами одинаковый отступ.
2. Desktop сохраняет пьедестал и список рядом. Персональная строка проходит
   под обеими колонками, вместо переполнения узкой левой части.
3. Desktop-карточки пьедестала: места 2/3 — 316px, место 1 — 344px.
   Grid выравнивает их по общей нижней линии. Внутри пять стабильных зон:
   подпись места, аватар, идентичность, время, footer. Footer-кнопки имеют общую линию.
4. На телефоне первое место остаётся над двумя призёрами; высоты 348/324px.
   Ники и бейджи не меняют высоту карточки; отметка «Это ты» не добавляет строку.
5. Персональная панель получает адаптивные minmax(0,...) колонки и реальный
   внутренний отступ 20px на desktop / 14px на телефоне. Статистика не сохраняет
   прежнюю жёсткую минимальную ширину. На узких экранах она и действие переходят ниже.
6. Текст наград переносится без ellipsis; номер места сохраняет свою колонку.
   Desktop-текст сезона ограничен 280px, чтобы карточкам досталось достаточно места.
   Countdown и текущая награда находятся в общей нижней строке, а не добавляют
   отдельный ряд под описанием сезона.
7. Общая светлая/тёмная палитра, ссылки профилей, периоды рейтинга и формулы очков
   сохраняются. Изменения ограничены компонентом и его CSS module.

## Приёмка

Проверять настоящую собранную страницу с подменёнными read-only ответами API:

- 2/3/5/25 участников: без списка, короткий список, длинный список.
- Пользователь #4 и #1, гостевой вариант; награды недели и вариант без наград.
- Длинный ник, премиум-отметка, разное количество эпизодов и время просмотра.
- 390/768/1280/1440/1920px, обе темы.
- Нет горизонтального переполнения документа и внутренних прокручиваемых секций.
- Кнопка профиля целиком внутри персональной панели и минимум в 12px от её края.
- На desktop карточки и их footer-кнопки выровнены снизу с допуском 1px.
- Награды переносят текст, без раннего многоточия.
- Верхние соседние блоки разделены gap 16px, без viewport-разрыва.
- Короткий рейтинг на 1920px сохраняет компактную естественную высоту.

Автоматизация: `scripts/leaderboard-layout-smoke.mjs`. Существующая проверка
`scripts/page-consistency-smoke.mjs` покрывает остальные страницы. Browser fixtures
не выполняют настоящую авторизацию, выдачу наград или изменение рейтинга.

Для запуска browser-проверки нужен Playwright и Chromium; можно указать
`PLAYWRIGHT_MODULE_PATH` и `CHROMIUM_EXECUTABLE_PATH`.

## Релиз

Отдельный PR после build/lint/browser-проверок. Изменений БД, секретов и DNS нет.
Откат — revert коммита. Production-публикация после разрешения пользователя.

## Результаты проверки

- Полный `npm run build`: prebuild gates и production build прошли.
- Финальный `npx next build` после перестановки countdown прошёл.
- ESLint изменённого LeaderboardClient: без ошибок и предупреждений.
- Новый browser smoke: 40 сценариев (4 набора × 5 ширин × 2 темы), настоящие
  React-компоненты с подменёнными API. Проверены нижние линии, пропорции,
  отступ профиля, перенос наград, непрерывные интервалы и отсутствие overflow.
- Существующий page-consistency smoke: 30 сочетаний прошли.
- Root CSS: 76 imports / 829701 bytes, лимит соблюдён.
- Скриншоты при 1920px визуально проверены после прокрутки в тёмной теме.

Короткий рейтинг из пяти участников в тесте занимает около 1084px высоты
с учётом внутренних отступов корневого контейнера. Это естественный поток,
без попытки принудительно вместить любое число участников в один viewport.
