# AnimeBox: кинематографичная страница тайтла

## Цель и границы выпуска

Сочетать эмоциональную подачу с быстрым доступом к просмотру. Убрать разрозненный каталог из постера, рамок и текста, сохранив достоверные данные, доступные серии, историю и действия аккаунта. Пользователь видит название и главное действие при открытии; серии доступны без переключения вкладок. Подбор настроений и восстановление рекомендационных рядов выпускаются отдельно.

В выпуск входят hero, компактные действия, читаемое раскрываемое описание, горизонтальный выбор сезона и карточки эпизодов, перестановка похожих тайтлов выше обсуждения, адаптивность и проверка. Автовидео, официальный логотип, новые внешние источники эпизодных описаний, процент совпадения и изменения схемы БД не входят: текущий API не предоставляет надёжные данные для этих функций.

## Структура страницы

1. Hero: изображение, хлебные крошки, название, оригинальное название, факты, основное действие и вспомогательные кнопки, синопсис, жанры.
2. Сезоны и эпизоды: выбор сезона, количество доступных эпизодов, переход по номеру для длинных сериалов, карточки.
3. Похожие тайтлы с существующими ссылками и рейтинговыми данными.
4. Дополнительные действия пользователя и просмотр с друзьями, сворачиваемый порядок частей, обсуждение.

## Hero и изображения

На ПК ориентир 420–480 px в обычном состоянии. Контент не фиксировать по высоте: очень длинное название и раскрытый текст должны увеличивать блок, а не обрезаться. Основная зона до 1240 px; отступы 24–40 px, на телефоне 16–20 px. Баннер покрывает фон, фокус изображения справа, градиенты слева и снизу обеспечивают читаемость. Текст ограничен приблизительно 620–680 px, чтобы арт оставался виден.

Использовать только настоящий горизонтальный bannerImage, через существующий media cascade и responsive srcset. Один приоритетный hero image, без autoplay и дополнительных запросов к данным тайтла. Если баннера нет — оформленный небольшой постер справа и мягкий оттенок обложки, без растяжения вертикальной картинки на весь экран. При сетевой ошибке image cascade переходит на штатный placeholder, высота сохраняется. Мобильный hero использует тот же баннер без дополнительного скачивания фонового видео. Уважать prefers-reduced-motion.

Название остаётся семантическим h1: 36–48 px на ПК, 26–34 px на телефоне, line-height 1.1–1.2, перенос длинных слов. Оригинальное название — второстепенная строка. Рейтинг подписан AniList. Год, формат, количество эпизодов, статус и сезон — одна переносимая строка с разделителями. Не выводить фиктивные 4K, возрастные ограничения, точные даты или Match.

## Действия и продолжение

Смотреть/Продолжить — единственная залитая главная кнопка, >=48 px. Избранное и добавление в трекер — круглые кнопки >=44 px с SVG, title и aria-label; aria-pressed для избранного, disabled при сохранении. На телефоне просмотр занимает отдельную полную строку. Ошибки сохранения остаются текстом role=status.

Сохранить логику существующего источника, маршрута /episode/N, server watch state и local fallback. Доступность не подменять количеством эпизодов из каталога. Серверный результат продолжения может указывать следующую завершённую/начатую серию; отображать подтверждённый процент только при валидном durationMs. Гость может иметь локальный прогресс — он не является доказательством входа. Объяснить в компактной подсказке, что аккаунт синхронизирует библиотеку, оценки и прогресс между устройствами. Не дублировать большую форму авторизации внутри hero.

## Описание и жанры

Синопсис 16 px/1.6, обычное начертание и светлый цвет. Для hero показывать законченный короткий фрагмент примерно 220–240 символов, короткий текст целиком. Кнопка Описание/Свернуть >=44 px с aria-expanded и aria-controls. В раскрытом состоянии весь очищенный текст доступен, без fixed height и clipping. Существующий общий вариант синопсиса не менять на других страницах.

Жанры — плоские ссылки через точку, без отдельных рамок. Дедупликация по существующему taxonomy value; сохранить ссылки в жанровые SEO-страницы/фильтры. До 6 жанров, перенос без горизонтального переполнения. Альтернативные названия — компактный native details.

## Эпизоды

Новый cinematic вариант EpisodeList применяется только к странице тайтла; страница просмотра и другие потребители сохраняют прежний вариант. Общие эффекты availability, progress events, groups и episode jump остаются едиными.

Сезоны — горизонтальная полоса с короткими label и годом, полный title доступен для assistive technology/tooltip. Активный сезон выделен тонкой фиолетовой линией и фоном. Две колонки карточек от 900 px, одна ниже. Карточка 88–120 px по обычному содержимому, min-height вместо фиксированной высоты. Номер в собственной зоне, заголовок и состояние в собственной зоне, play/check справа; текст не позиционировать абсолютно.

Контракт дополнительной информации: episodeDetails по номеру с title, thumbnailUrl, description, durationSeconds. Все поля optional. Отсутствующее название — Серия N. Отсутствующие кадры — типографический номер, а не общий постер под видом кадра. Не придумывать длительность или сюжет. Превью lazy через существующую image pipeline. Данные контракта не должны влиять на список доступных эпизодов: показывать только availability.episodes.

Прогресс 4 px внутри карточки, отражает существующий percent; завершённые карточки имеют check и статус. Начатая серия содержит время продолжения, если есть positionMs. Не переносить статус на соседнюю карточку после смены сезона. Длинные сериалы сохраняют разделение на группы и jump; обычный список раскрывается партиями по 8 карточек без вложенного вертикального скролла. Показать ещё увеличивает список, не перезагружает данные.

Загрузка, unknown и unavailable различаются текстом и aria-busy. Пустое состояние компактно (примерно 100–140 px) и не создаёт большой пустой экран. Выбор будущего сезона сохраняется явным действием пользователя; автоматическая загрузка связей возвращает текущий сезон только при отсутствии ручного выбора.

## Изоляция, доступность и производительность

CSS Modules; специфичные стили старого episode-list не применяются к новым карточкам. Существующие глобальные классы на контейнерах переопределять только внутри route module/variant. Никаких новых production dependencies, SQL и изменения политики авторизации. SSR тайтла, canonical, JSON-LD, restrictions и ссылки сохраняются.

Фокус видим, интерактивы >=44 px, чтение клавиатурой, корректные aria-current/pressed/expanded и имена. Light theme: текст поверх hero остаётся светлым на локальной тёмной подложке, нижние блоки используют светлые поверхности. Уменьшенное движение отключает декоративные transitions. Изображения ниже первого экрана lazy. На первом рендере данных пользовательских storage не читать; избегать hydration mismatch.

## Приёмка

Браузер: 360, 390, 768, 1366, 1440, 1920 px. Проверить баннер и отсутствие баннера, длинное название, короткий и длинный синопсис, пустые/unknown/available серии, переключение сезона до завершения seasons fetch, 1000 эпизодов с группами, partial/completed прогресс, гостя и ошибки запросов. Нет page horizontal overflow, наложения цифр и статусов, чрезмерных пустых контейнеров. Главная кнопка видна до списка; доступные серии открываются по правильному slug/number.

TypeScript, targeted ESLint, все существующие prebuild checks, production build и GitHub Quality Gate обязательны. QA fixture использует настоящие компоненты и CSS, подменяет только сетевые ответы и серверные данные. После merge дождаться SUCCESS обоих Railway deployments и проверить живую страницу. Не утверждать, что реальный playback или authenticated mutations проверены, если проверялся только гостевой UI.

## Результат проверки реализации

Локальная production-сборка и полный prebuild прошли. Browser fixture на реальных компонентах прошёл 360/390/768/1366/1440/1920 px: 16px синопсис, CTA >=48px, 8 начальных карточек, правильное продолжение серии 2 и отсутствие горизонтального переполнения. Проверены раскрытие полного текста, увеличение списка 8→16, переключение сезона с правильным slug и дополнительными медиаданными, недоступный сезон с компактным состоянием, длинное название и отсутствие баннера, светлая тема. Скриншоты просмотрены. У обычного desktop hero измерено около 505px с блоком продолжения; высокая длинная идентичность увеличивает его естественно.

QA использует настоящий арт Frieren через локальную копию публичного image proxy; API availability/progress/seasons подменены. Реальные authenticated mutations, native Telegram и воспроизведение провайдеров этими проверками не подтверждены. Локальные запросы related/franchise к AniList блокируются 403, поэтому наличие этих секций отдельно проверяется после production deployment. Dev output вынесен в игнорируемую .next, чтобы Tailwind не сканировал временные сборочные файлы. Production config и fixture-подмены восстановлены.
