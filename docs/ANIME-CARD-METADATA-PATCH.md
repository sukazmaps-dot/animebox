# Сверхподробное ТЗ: полнота карточек и сохранение метаданных при обновлении

Дата: 6 октября 2026. База: main 6e3b9d9.

## 1. Задача

Карточки поиска должны показывать уже известные название, постер, год, формат, число серий и рейтинг с первого пригодного ответа. Полный ответ и последующие страницы не должны стирать заполненные поля пустыми значениями. Известное описание также передаётся в полном объекте аниме, если оно есть в сохранённом каталоге.

Быстрый поиск остаётся независимым от внешних AniList/Shikimori запросов. Обогащение карточек выполняется пакетно из существующих сохранённых данных. Никаких новых таблиц, расписаний cron, миграций или установок зависимостей этот патч не требует.

## 2. Подтверждённая причина

Production /api/search/instant?q=friren&limit=4 возвращает четыре карточки с русским названием и жанрами, но без idMal, episodes, score, format, startDate и description. Причина в mapper localAnimeSearchHitToAnime: он создаёт минимальный объект из поискового RPC, который этих полей не возвращает.

Полный /api/anime?search=friren&limit=4 для тех же идентификаторов возвращает серии, даты, форматы и оценки, но в проверенном ответе все четыре описания были пустыми. Получается, что источник поиска и полная ветка имеют разные наборы полей.

Вторая причина находится в клиентском слиянии. До патча первая страница целиком заменялась полным ответом. При догрузке одинаковый id целиком заменял прежний объект. Поэтому частичный свежий объект мог удалить пригодные поля предыдущего объекта.

Третья причина: при отказе внешней гидратации локальных совпадений API только логировал ошибку. Такие совпадения не попадали в кандидаты, хотя их базовые данные и сохранённые метаданные уже были доступны.

## 4. Границы патча

Входит:

- Пакетное чтение сохранённых метаданных по AniList ID.
- Обогащение мгновенного поиска параллельно проверке доступности.
- Дополнение пустых полей полного каталога из сохранённой базы.
- Сохранение локальных совпадений при исключении во внешней гидратации.
- Безопасное слияние карточек в первой и последующих страницах клиента.
- Метрика Server-Timing для чтения метаданных.
- Детерминированные тесты настоящих модулей и API-маршрутов.

Остаётся за пределами:

- Синхронизация и исправление устаревших исходных данных Shikimori.
- Изменение полноты расписания, провайдеров видео и правил доступности.
- Перестройка рекомендаций, авторизации, рекламных блоков и изображений.
- Массовый внешний обход каждого аниме для заполнения описаний.
- Обещание заполнить отсутствующие сведения об анонсированном сезоне.

## 5. Чтение метаданных

Добавить getSavedAnimeMetadata(ids) в saved-catalog-server.

Входные идентификаторы:

1. Только положительные безопасные целые числа.
2. Дубликаты удаляются.
3. За один запрос обрабатывается максимум 50 уникальных идентификаторов.
4. Для ключа кэша идентификаторы сортируются.
5. Пустой набор не вызывает обращение к базе.

Источник — существующее anime_saved_playable_catalog, с существующим явным списком колонок и существующим savedDocumentToAnime. Используется .in('anime_id', ids), а не строковая сборка фильтра из пользовательского текста.

Запрос имеет AbortSignal.timeout(1200). Ошибка чтения метаданных не должна падать наружу до API-клиента: журналируется предупреждение и возвращается пустой набор дополнений. Основные результаты остаются пригодными.

### 5.1. Кэш

Используется существующий createPublicResultCache:

- TTL 30 секунд, начиная с завершения загрузки.
- Не более 128 завершённых наборов и 128 совместно ожидаемых загрузок.
- Одинаковый набор ID совместно использует один запрос.
- Ключ не содержит пользовательскую авторизацию, профиль или историю просмотров.
- Пустой ответ не кэшируется.
- Ошибка не кэшируется.
- При переполнении очереди действует существующий ограниченный режим без дополнительного удержания pending-записей.
- Кэш локален процессу; разные Railway-процессы не обязаны его разделять.

## 6. Политика объединения полей

Создать чистый lib/anime-metadata-merge.ts. Он не читает базу и сеть, пригоден на сервере и в браузере.

Объекты объединяются только при одинаковом Anime.id. Если оба имеют положительный MAL ID и он различается, объединение запрещается. Идентификатор MAL не принимается за идентификатор AniList.

| Поле | Правило |
|---|---|
| Русское название | Непустое русское первичное значение сохраняется; латинский текст в russian допускает замену известным кириллическим названием |
| Romaji | Непустое латинское первичное значение сохраняется; кириллица в romaji допускает замену известным латинским значением |
| English/native | Заполняются только при отсутствии непустого значения |
| Slug, описание, формат, статус и другие текстовые поля | Пустое/пробельное дополняется; непустое первичное сохраняется |
| idMal/mal_id, серии, длительность, оценка | Положительное конечное первичное значение сохраняется; неизвестное дополняется известным положительным |
| Вышедшие серии, popularity, favourites | Конечное неотрицательное первичное значение сохраняется, включая настоящий ноль |
| Жанры, теги, студии | Непустой первичный массив сохраняется; пустой дополняется |
| Синонимы | Объединение с удалением дубликатов |
| Даты | Заполняются отсутствующие компоненты; месяц не переносится между разными годами, день не переносится между разными месяцами |
| Изображения | Заполняются отсутствующие размеры и URL; существующие непустые URL сохраняются |

Не требуется выдумывать серии, статус или оценку при отсутствии данных. Не изменяются шкалы оценок: score и averageScore передаются в своих существующих форматах.

Объединение не должно мутировать объект из кэша или предыдущего React state. Производные объекты и объединённые массивы создаются отдельно.

## 7. Мгновенный поиск

После получения лексических совпадений запускать одновременно:

- Существующую проверку доступности идентификаторов.
- Пакетное чтение сохранённых метаданных.

Список и порядок результата по-прежнему определяются поисковыми совпадениями и проверкой доступности. Сохранённый каталог предоставляет только поля для уже выбранных ID. Он не добавляет посторонние карточки и не обходит проверку доступности.

Для совпадения с сохранённой записью первичным является полный сохранённый объект, а минимальный поисковый объект заполняет его пропуски. Это позволяет получить настоящий romaji вместо русского названия, ранее продублированного в romaji.

Для совпадения без сохранённой записи остаётся минимальная карточка. Отказ чтения метаданных также оставляет минимальные карточки, вместо пустого успешного ответа.

### 7.1. Наблюдаемость

Добавить timings.metadataMs в JSON и animebox_metadata;dur=... в Server-Timing.

Метрика availabilityMs и metadataMs измеряет длительность каждой параллельной операции. Их нельзя складывать как последовательные задержки: операции перекрываются. tookMs включает полный этап быстрого поиска после проверки rate limit.

## 8. Полный каталог

После существующей проверки доступности дополнять кандидаты сохранёнными полями одним пакетным чтением. Если основной ответ уже получен из getSavedCatalogPage, повторное обогащение пропускается.

Свежий ответ провайдера является первичным. Например: episodes=28 от провайдера и episodes=24 в сохранённой базе должны оставить 28. Пустое description от провайдера может получить непустое сохранённое описание.

При исключении в hydrateLocalAnimeHits минимальные объекты соответствующих локальных совпадений включаются в кандидаты. Далее они проходят обычную проверку доступности и могут получить сохранённые метаданные. Запись в лог сохраняется.

Существующие лимиты, сортировка, поиск, фильтры, пагинация, фоновые refresh-задачи и правила HTTP-кэширования продолжают действовать. Данный патч не расширяет права базы и не изменяет политику доступа к просмотру.

## 9. Клиентские обновления

Первая страница:

- Набор ID и порядок нового полного ответа сохраняются.
- Предыдущие карточки используются только как доноры недостающих полей для тех же ID.
- Старые карточки, которых нет в новом ответе, не возвращаются.
- Пустая новая первая страница остаётся пустой.

Последующие страницы:

- Идентификаторы объединяются в стабильном порядке.
- Повторный id не создаёт вторую карточку.
- Повторный частичный объект дополняется ранее известными полями.
- Новые непустые значения повторного объекта имеют приоритет.

Правила отмены запросов, остановки после ошибки, повторной загрузки той же страницы и синхронной блокировки из предыдущего патча сохраняются.

## 12. Результаты проверки реального окружения

До патча production быстрый friren: четыре минимальные карточки без серий, года, формата и рейтинга.

После изменений проверена локальная production-сборка с настоящей подключённой базой:

| AniList ID | MAL ID | Серии | Рейтинг сохранённой копии | Год | Длина описания |
|---:|---:|---:|---:|---:|---:|
| 154587 | 52991 | 28 | 9,25 | 2023 | 792 |
| 182255 | 59978 | 10 | 8,84 | 2026 | 672 |
| 170068 | 56885 | 24 | 7,36 | 2023 | 296 |
| 209939 | неизвестен в выбранной сохранённой записи | неизвестно | неизвестно | неизвестно | 0 |

Для 170068 сохранённая копия указывает 24 серии, тогда как проверенный ранее ответ провайдера указывал 12. Патч не исправляет источник этого расхождения: в быстром ответе используются сохранённые сведения, в полном ответе непустое свежее значение имеет приоритет. Аналогично могут отличаться оценки. Это ограничение свежести данных, а не повод выдумать единое значение.

Первый локальный запрос: HTTP 200, 22 588 мс суммарно; rate limit 5945 мс, lexical 15942 мс, metadata 387 мс, availability 327 мс. Повторный: HTTP 200, 688 мс суммарно; lexical 1 мс, metadata 0 мс, availability 0 мс. Эти значения относятся к локальному пути до базы и процессному кэшу, а не к скорости на телефоне или завершённому Railway deployment.

## 13. Проверки выпуска

Обязательны:

1. tests/anime-card-metadata.mjs — настоящий merge-модуль, reader с подменённой базой, bundled API instant и полного каталога.
2. tests/catalog-request-state.mjs — предыдущая логика гонок и повторной страницы.
3. tests/search-source-recovery.mjs — предыдущая серверная логика поиска и источников.
4. TypeScript --noEmit.
5. ESLint затронутых файлов.
6. Полная production-сборка с существующими prebuild guards.
7. Read-only SQL для проверки реального покрытия данных.
8. Фактический API-запрос локальной production-сборки к подключённой базе.

В тестах предупреждения timeout и provider unavailable намеренно вызываются для проверки деградации и не означают падение тестового запуска.

Измерения браузерного LCP/INP/CLS и визуальная проверка телефона не входят в выполненную автоматическую проверку. Полнота данных, свежесть сохранённых значений и сетевой путь остаются отдельными свойствами.

## 14. Публикация и откат

Публиковать только восемь перечисленных файлов поверх актуального main. Не включать сторонние локальные изменения Cloudflare, package.json, lockfile и других патчей.

Коммит с [deploy] предназначен для подключённого процесса выпуска. Факт обновления main не равен подтверждённому окончанию Railway deployment.

Откат выполняется возвратом этих файлов к предыдущему коммиту. Изменений схемы и данных базы нет; обратная миграция не нужна.

## 15. Итог выполнения

Все восемь файлов реализованы. Прошли tests/anime-card-metadata.mjs, tests/catalog-request-state.mjs, tests/search-source-recovery.mjs, TypeScript --noEmit, ESLint затронутых файлов и существующие prebuild guards.

В первой сборке npm run build итоговая компиляция прошла. После дополнительного уточнения правил нулевых значений и дат повторная сборка столкнулась с повреждением локального persistence-кэша Turbopack (range end index out of range). Кэш сборки перенесён в отдельный временный каталог; следующая чистая production-сборка завершилась с кодом 0. Исходный код и конфигурация сборщика для обхода ошибки не менялись.

В ходе чистой сборки существующая SEO-страница записала предупреждение AniList HTTP 403; предусмотренная обработка этого отказа позволила сборке завершиться. Это не подтверждает доступность AniList из Railway и не является новой ошибкой данного патча.

В окружении проверки установлен Next.js 16.3.8. package.json и lockfile не включены в патч, поэтому подключённый Railway deployment должен отдельно пройти свою сборку на зависимостях main.

Изменения опубликованы как код; окончание Railway deployment и браузерные сценарии на телефоне должны проверяться отдельно после выпуска.
