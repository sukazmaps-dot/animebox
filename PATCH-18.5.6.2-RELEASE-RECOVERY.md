# Patch 18.5.6.2 — Release recovery

## Цель и база
База: 85f60860337ac6ee7737cd9d73f3c6dc507bac1c, ветка patch-18-5-6-1-recommendation-media-recovery.
Закрыть оставшиеся гонки в первоначальном заполнении рекомендаций и объединении запросов изображений. Не повторять реализованные bootstrap, source negative cache, jitter и ограничения preview-деплоев.

## 1. Рекомендации: контракт жизненного цикла
- Каждая запланированная bootstrap-задача принадлежит поколению подборки, в котором была создана.
- При смене настроения или размонтировании поколение инвалидируется существующим requestGenerationRef.
- Перед запуском отложенной задачи сравнить сохранённое поколение с текущим; устаревшую задачу завершить без запроса и изменения состояния.
- Операция ensureRailDepth фиксирует поколение при старте. После каждого await проверить поколение до распределения кандидатов, повторной загрузки и записи ownership.
- Ошибка старого запроса не должна выставить ошибку новой подборке; finally старой операции не должен удалить loading-флаг новой операции с тем же rail id.
- Существующие лимиты bootstrap и последовательная очередь сохраняются. Автозагрузка не превращается в полную выгрузку каталога.
- Стрелка и ручной повтор продолжают работать независимо от одноразового bootstrap.
- При отсутствии кандидатов сохраняются существующие empty/exhausted состояния.

## 2. Media Worker: объединение запросов
- Одновременные запросы одного source + variant используют одну операцию получения изображения.
- Разные варианты могут ждать одну начальную проверку источника.
- После ожидания проверки повторно проверить карту запросов: другой ожидающий запрос мог уже начать получение нужного варианта.
- При недоступном источнике использовать результат общей проверки без новых origin-запросов.
- Успешные результаты разных вариантов не смешивать; карты очищать после завершения.
- Сохранить существующие таймауты, negative TTL, R2, форматы и обработку GET/HEAD.

## 3. Проверки
Добавить поведенческий тест реального кода coalescing с управляемыми Promise: одинаковый вариант, несколько ожидающих одного варианта, разные варианты, недоступный источник, очистка после ошибки. Для клиентской гонки проверить выполнение извлечённой реальной функции с управляемой сменой поколения: поздний результат, поздняя ошибка, cleanup и устаревшая очередь.
Подключить проверку к prebuild, без выключения существующих gates. Запустить prebuild, TypeScript и production build, если зависимости доступны. Фиксировать ограничения окружения отдельно от ошибок проекта.

## 4. Приёмка в браузере после выпуска
- Холодное открытие без кликов: видимые разреженные ряды автоматически дополняются.
- Смена настроения A → B во время загрузки: карточки и ошибки A не попадают в B.
- Быстрая смена A → B → C: только C управляет загрузкой.
- Уход со страницы во время bootstrap: нет продолжения старой очереди.
- Медленная сеть/502: ограниченные повторы и корректная замена изображения, без бесконечной загрузки.
- Телефон и широкий экран: заполнение ряда не требует клика и не меняет существующую геометрию карточек.

## 5. Выпуск и откат
Один проверенный коммит поверх базы. Проверить итоговый SHA релиза; Worker выпускается отдельно от Next.js. Не запускать пустые коммиты для обхода лимита деплоя. Успех локальных проверок не считать подтверждением production. Откат: revert завершающего коммита; SQL-миграции не нужны.
